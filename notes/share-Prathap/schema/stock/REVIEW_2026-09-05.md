## MUST FIX (all empirically confirmed on the scratch build)

1. **Deadlock in `fn_sml_apply` under concurrent posting of one item.**
   Lock order per posting is: one stock_balance row → stock_item_cost FOR
   UPDATE → branch-wide balance revalue broadcast (every holding of the
   item, 16:3082-3095). Two sessions posting the same item via different
   lots/godowns cross-lock. Reproduced: **24 deadlocks in 800 single-row
   inserts** from two sessions (two tills on one item = everyday case).
   Fix: take the sic lock BEFORE the first balance write so ordering is
   global (sic → sbl everywhere).

2. **Post-lock holes** (probed, all succeed today):
   a. `fn_svh_post_lock` (19:747) exempts IN_TRANSIT/RECEIVED — a plain
      UPDATE regresses an IN_TRANSIT OUT to DRAFT (lines then unlock, a
      second despatch moves the stock twice), or flips it to POSTED so
      `fn_svh_cancel` reverses it while transit rows stay open. Also
      soft-delete of an IN_TRANSIT OUT hides it from `ix_svh_inbound` yet
      receive never checks `o.svh_is_deleted`.
   b. No DELETE guard on stock_voucher — a POSTED voucher hard-DELETEs,
      lines cascade, ledger rows orphaned.
   c. `fn_svi_post_lock` (19:708) checks only the NEW parent on UPDATE — a
      posted line reparents onto a DRAFT voucher.
   Fix: freeze IN_TRANSIT/RECEIVED like POSTED (whitelist IN_TRANSIT→
   RECEIVED, which receive's own UPDATE performs), add a DELETE trigger,
   check OLD parent when svi_voucher_id/acc_year change.

3. **`ux_stt_out_line` aborts a legitimate OUT** — same item+lot despatched
   from two source godowns on one voucher (or two split lines): destination
   godown is header-level, so the transit key collapses to (item, lot,
   bucket) per voucher. Reproduced: raw 23505 with no worded message.
   Fix: aggregate the transit row (ON CONFLICT DO UPDATE sent += …) or
   refuse with a worded error at validate time.

4. **`fn_sdd_rebuild` double-counts cancelled sales.** Reversal rows keep
   txn_type SALE with direction flipped; the rebuild sums magnitudes with no
   `is_reversal`/direction handling. Reproduced: a cancelled 30-unit sale
   shows `sdd_sold_qty = 60` (should be 0). Poisons the forecasting input.
   Fix: direction-signed sums (`-sml_direction * sml_base_qty` for SALE) so
   original + reversal net out.

5. **Transfer cost bypass**: a line arriving with nonzero `svi_cost_rate`
   skips `fn_sml_cost_default` (bails on nonzero rate) and 20's OUT insert
   omits the value columns. Reproduced: OUT ledger row rate 555, value 0 —
   wrong valuation AND "a transfer never revalues" broken.
   Fix: zero the rate before insert (policy cost authoritative) or supply
   values explicitly.

6. **`stock_item_cost` seed clamp**: first-ever movement being a sale (ALLOW
   default supports it) seeds sic at GREATEST(qty,0)=0; the later receipt
   then overstates. Reproduced: ledger nets 5 on hand, `sic_total_qty` = 10 —
   and nothing ever rebuilds sic.
   Fix: seed with the true signed quantity (negative allowed), matching the
   update path.

## SHOULD FIX (verified by reading, not probed)

- **Receive bucket mismatch unvalidated** beyond the DAMAGED case
  (20:472-476): a SALEABLE line against a DAMAGED transit row launders
  damaged goods into SALEABLE silently. Refuse `svi_bucket <> stt_bucket`
  unless the line is DAMAGED.
- **Replay across a year boundary defeats the uniques**: `ux_sml_source`,
  `ux_sml_reversal`, `ux_srv_source` all include `acc_year` (partition key),
  so a sync replay stamped with a different year posts/reverses twice.
  Enforce "cancellation carries the original's acc_year" in the functions.
- **`fn_sml_immutable` guards too few columns** (16:3232): item, branch,
  doc_date, txn_type and all cost/value columns stay editable after posting;
  and flipping `sml_is_deleted` desyncs sbl/slt/sic with no compensation.
- **`sic_last_purchase_rate/date` stamped by every inward** (16:3042) —
  SALE_RETURN, TRANSFER_IN, PHYSICAL_PLUS, and reversals of outwards all
  overwrite it; 19's LAST_PURCHASE rate source reads it back. Guard on
  txn_type = PURCHASE and NOT is_reversal (same guard as last_sale).
- **Refresher lost update**: `fn_sbl_refresh_reserved` / `fn_stt_refresh`
  sum before locking the balance row — two concurrent reservations can
  persist a stale sum; and no rebuild path repairs reserved/transit columns.
  Re-sum after acquiring the row lock (or inside the UPDATE).
- **`fn_sbl_rebuild` can't zero a balance row with no surviving ledger rows**
  (joins FROM truth; orphans keep wrong quantities), and never repairs
  slt_status.
- **`fn_svh_cancel`**: add `sml_acc_year = p_acc_year` (+company/branch) to
  the reversal scan (partition pruning; currently scans every year); add a
  `fn_svh_recompute` call so a cancelled PHYSICAL header stops showing its
  variance.
- **Plain UPDATE can set DRAFT → POSTED** with zero ledger rows (then
  frozen). Whitelist header status transitions.
- **One-opening-per-holding guard is read-then-write** (19:369) — two
  concurrent opening posts for one holding both pass. Advisory xact lock on
  the holding hash.
- **ISSUE mapping trusts `srm_allowed_txn_types[1]` blindly** (19:130) — a
  reason listing an inward/transfer type makes an ISSUE post that type with
  direction −1. Whitelist outward types.
- **Cancel guard blocks cancelling a DRAFT TRANSFER_IN** (20:598 refuses any
  linked TRANSFER_IN; the link is mandatory on all of them). Add
  `AND OLD.svh_status = 'POSTED'`.
- Defaults that violate their own CHECKs (insert relying on default always
  fails): `srv_reserved_qty`, `stt_sent_qty`, `sml_base_qty`+free (DEFAULT 0
  vs > 0 CHECKs). Drop the defaults.
- `stock_transit` has no FK to `stock_voucher(svh_id, svh_acc_year)` though
  the composite exists and svi uses it.
- Godown↔branch belong-together never validated (OUT can name branch B with
  branch A's godown; gdl_branch_id exists but 19/20 never read it); receive
  never checks company match or base-uom match.
- `ix_smp_lookup` omits `smp_uom_id` — multi-unit items pay heap visits on
  every billing lookup. Add it to the key.
- Reversal of an outward pollutes `sbl_last_in_date`/`first_in_date`
  (LAST_IN_DATE-basis ageing sees a cancellation as a fresh receipt); the
  revalue broadcast doesn't bump `sbl_row_version`/`modified_on` (sync
  keyed on it misses revalues).
- `ck_smp_mrp > 0` vs `ck_slt_prices >= 0`: an MRP-0 lot can never be
  priced as a bucket (falls to MASTER silently) — confirm intended.
- Q26: `LEAST(...) < r.min_price` is NULL-silent when min_price is NULL —
  the API must always send the loaded min (or COALESCE).
- `ck_svh_link` / `ck_slt_inward_src` don't bind the acc_year leg of the
  source triple; a TRANSFER_IN with NULL link year fails only with a
  misleading message at receive.

## Client-side rules the screens must own (no schema change)

  The screen must drop/skip uncounted lines before posting.

- Per-line write-back fires header recompute n+1 times per post (perf note

## Decisions to document

12. **`svi_counted_qty` NULL vs 0** — `svi_diff_qty` is GENERATED
    `COALESCE(counted,0) − COALESCE(book,0)` (16:1603-1605), so a line left
    uncounted posts a **FULL SHORTAGE**, indistinguishable from a counted
    zero. The sharpest unstated trap in the share. State the rule: the
    screen drops uncounted lines before Post, or NULL is refused at save.
13. **TRANSFER_IN header godowns** — `ck_svh_transfer_godowns` (16:1495)
    demands both godowns on a receive too; what fills `svh_from_godown_id`
    on an IN is documented nowhere.
14. **Who picks the receiving godown on a Branch Outward** (sender chooses
    in the destination branch? branch default?) — plus the cross-branch
    godown picker query for it.

## Screen gotchas already specced (client must implement)

- **Opening**: `svi_uom_id` is `iuc_id`, not `unit_id`; `svh_to_godown_id`
  mandatory (post raises even though `ck_svh_godowns` asks for only one);
  cost is per BASE unit; `svi_value` is generated, so the screen never sums
  its own grid; one opening per holding per year.
- **Physical**: default `svh_rate_source = 'AVG_COST'` (MANUAL is wrong
  here); the counted godown goes in `svh_from_godown_id`; freeze is wall
  clock, per godown, auto-lifting at post/cancel; an all-agreed count posts
  zero ledger rows and still closes POSTED.
- **Transfers**: `svi_lot_id` NOT NULL (pick from balance, never resolve);
  leave `svi_cost_rate` 0 and let the policy stamp it; ship SALEABLE and
  DAMAGED of one lot as two vouchers; no Cancel button after despatch
  (mid-flight cancel is refused by design); posted TRANSFER_IN cannot be
  cancelled — un-receiving is a reverse transfer.
- **Inward**: link triple + acc_year mandatory; cost is never entered (the
  IN posts at `stt_cost_rate` regardless of the line); partial receipts are
  simply more TRANSFER_IN vouchers.
- **Adjustments**: 16s seed is a hard prerequisite; `srm_require_remarks`
  is enforced by NO trigger — screen/API must; RELOT_OUT/RELOT_IN is the
  sanctioned wrong-batch fix and needs both halves raised together.
