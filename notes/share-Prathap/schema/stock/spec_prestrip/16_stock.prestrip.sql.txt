-- ═══════════════════════════════════════════════════════════════════════════
--  NexERP backend — 16: STOCK
--
--      stock.stock_track_policy     how an item is tracked        (stp_)
--      stock.stock_reason_master    why stock moved               (srm_)
--      stock.stock_ageing_slab      the ageing buckets            (sag_)
--      stock.stock_lot              batch / MRP / SP / supplier   (slt_)
--      stock.stock_ledger           every movement, immutable     (sml_)
--      stock.stock_balance          what is on hand now           (sbl_)
--      stock.stock_item_cost        moving weighted average       (sic_)
--      stock.stock_voucher          inward / outward document     (svh_)
--      stock.stock_voucher_item     its lines                     (svi_)
--      stock.stock_reservation      qty promised, not yet issued  (srv_)
--      stock.stock_transit          sent from A, not yet at B     (stt_)
--      stock.stock_valuation_snap   closing stock, frozen         (svs_)
--      stock.stock_demand_daily     what actually sold, per day   (sdd_)
--      stock.stock_reorder_policy   min / max / lead time         (srp_)
--      stock.stock_forecast         what we expect to sell        (sfc_)
--      stock.stock_movement_class   ABC / XYZ / FSN, dead stock   (smc_)
--      stock.stock_mrp_price        selling prices per MRP bucket (smp_)  §20
--
--  Requires PostgreSQL 18+ (uuidv7()).  Run order: … → 14 → 15 → stock/16.
--  This file lives in schema/stock/ with the rest of the stock module; see
--  its README.md for the folder's contents and where it slots into the chain.
--
--  ── What this file is ────────────────────────────────────────────────────
--  The stock engine. Until now there was none: files 00–15 build sales,
--  accounts, GST, loyalty and promotions, and not one of them can say how
--  many of an item a branch holds. sale_bill_item has carried sbi_godown_id,
--  sbi_stock_id, sbi_batch_no, sbi_batch_date and sbi_expiry_date since file
--  01, pointing at a stock row that did not exist. This file is that row.
--
--  ── What it does NOT do ──────────────────────────────────────────────────
--  It does not touch anything already live. Not one ALTER, not one DROP, not
--  one rename. In particular the Prisma-owned tables
--
--      inventory.item_stock_ledger (stl_)   inventory.item_stock_balance (isb_)
--      inventory.item_batch_master (btm_)   inventory.item_batch_stock   (ibs_)
--      stock.opening_stock_header/_detail   stock.physical_stock_*
--
--  are left exactly as they are. They become read-only legacy the day the
--  service layer is pointed here; migrating them is a separate one-time
--  script that replays their balances through an OPENING voucher, so the
--  engine below is proved on real data instead of being handed a balance.
--
--  Every table name and every column prefix in this file was checked against
--  the live catalog and against files 00–15. Nothing collides.
--
--  ── Why the stock schema and not inventory ───────────────────────────────
--  inventory is Prisma's. Putting the engine in stock guarantees no name can
--  collide with item_stock_ledger / item_stock_balance, and makes the cutover
--  boundary something you can see in a schema listing rather than something
--  you have to remember.
--
--  ── The shape: a ledger, a cache, and a lot ──────────────────────────────
--  Three tables carry the whole model and everything else decorates them.
--
--      stock_ledger    every in and out, append-only, never updated in place,
--                      never deleted. A cancellation is a reversal ROW. This
--                      is the truth; if it and the cache disagree, the cache
--                      is wrong.
--      stock_balance   on hand per branch / godown / item / lot / bucket,
--                      maintained by trigger from the ledger. A cache, and
--                      fn_sbl_rebuild() exists to prove it: run it and
--                      nothing should change.
--      stock_lot       the IDENTITY of a holding — its batch, its MRP, its
--                      selling price, its expiry, and the supplier it came
--                      from. Quantity never lives here.
--
--  ── Batch-wise, MRP-wise, selling-price-wise, or none ────────────────────
--  These are not four modes with four code paths. They are five independent
--  boolean flags on stock_track_policy, and stock_lot has one nullable column
--  per flag plus a null-normalised generated key column beside it:
--
--      slt_mrp         numeric(18,6)                  -- NULL when not tracked
--      slt_key_mrp     GENERATED AS (COALESCE(slt_mrp, -1)) STORED
--
--  One unique index over the generated keys serves every combination. A
--  grocery item tracked by nothing gets exactly ONE lot, for ever, with every
--  identity column NULL. A pharma item gets a lot per batch per expiry per
--  supplier. A garment gets a lot per MRP. Same table, same index, same
--  insert path, no branching anywhere in the engine.
--
--  Tracking could not go on inventory.item_master: it is Prisma-owned and off
--  limits, and its item_batch_config integer has never had a defined meaning
--  in any layer. stock_track_policy replaces it and resolves through
--  item+branch → item → group+branch → group → company, so head office sets a
--  default and one branch overrides it.
--
--  ── Supplier-wise stock ──────────────────────────────────────────────────
--  The supplier is ON THE LOT, not derived by tracing consumption back to a
--  purchase. The same batch number received from two suppliers is two lots.
--  That costs a few more rows and buys exact supplier-wise stock, exact
--  supplier-wise ageing, and a recall that names the right supplier without
--  a single join back through the ledger.
--
--  ── Ageing ───────────────────────────────────────────────────────────────
--  slt_first_inward_date is when the lot first entered the company;
--  sbl_first_in_date is when it first entered THIS godown. A transfer
--  between branches must not reset the clock on stock that has been in the
--  chain for ninety days, so ageing reports read the lot; a godown's own
--  "how long has this sat HERE" reads the balance. stp_ageing_basis picks
--  which, per item.
--
--  ── Valuation: both methods, from stored data ────────────────────────────
--  slt_cost_rate is the lot's actual cost, so FIFO and lot-actual valuation
--  are a straight read. stock_item_cost carries the moving weighted average
--  per branch, maintained by the same trigger. Neither is derived from the
--  other and neither has to be recomputed to answer a question.
--
--  ── This is built for a CHAIN ────────────────────────────────────────────
--      * stock_transit — a transfer that leaves branch A on the 29th and
--        arrives at B on the 2nd is not "nowhere" for four days, and must
--        never be counted twice. A single shop has no such state.
--      * stock_reservation — an order taken at one till against stock a
--        second till is about to sell. Counting open orders out of
--        sale_order_item cannot work when the order was raised offline.
--      * stock_valuation_snap — closing stock for fifty branches cannot be a
--        full ledger replay every time somebody opens a report.
--      * stock_demand_daily + stock_forecast — head office replenishing
--        fifty branches needs demand history per branch, and needs to know
--        which days were stock-outs so a fast mover is not mistaken for a
--        slow one.
--
--  ── Prediction: the numbers are stored, the maths is not ─────────────────
--  stock_forecast holds forecast qty, confidence band, safety stock, reorder
--  point, suggested order qty and the back-test error columns, plus the model
--  parameters as jsonb. Nothing in this file computes them. A forecasting
--  model that lives in PL/pgSQL cannot be changed without a migration, and it
--  will be changed. The schema's job is to hold the inputs (stock_demand_daily),
--  the settings (stock_reorder_policy) and the outputs (stock_forecast) in a
--  shape a job can read and write.
--
--  ── Foreign keys, all verified to exist ──────────────────────────────────
--      public.companys(comp_id)               public.branch_master(br_id)
--      public.user_master(usr_id)             fixed.device_master(dev_id)
--      inventory.item_master(item_id)         inventory.item_group_master(itg_id)
--      inventory.item_unit_conversion(iuc_id) inventory.godown_locations(gdl_id)
--      purchase.suppliers(sup_id)
--
--  Restated because stock is where it is most often got wrong: a UNIT on any
--  line is inventory.item_unit_conversion(iuc_id), NEVER item_unit_master
--  (unit_id) — the stock a bill consumes must be keyed the same way the bill
--  keys it (sale_bill_item.fk_sbi_item_unit). Every quantity is therefore
--  stored twice: as entered, and converted to base.
--
--  A GODOWN is inventory.godown_locations(gdl_id) — a self-referencing tree
--  whose gdl_type runs WAREHOUSE / ZONE / AISLE / RACK / SHELF / BIN. Stock
--  is held at whatever node the branch chooses to operate at;
--  branch_master.br_default_godown_id names the default.
--
--  ── House rules applied without exception ────────────────────────────────
--      * uuidv7() keys, generated at the counter, offline-safe
--      * transaction tables PARTITION BY LIST (acc_year), PK (id, acc_year);
--        balances and masters are plain tables
--      * statuses are varchar + CHECK, never enum types
--      * soft delete everywhere; every index filtered on it
--      * numeric(18,6) qty and rate, numeric(18,2) value, numeric(9,3) percent
-- ═══════════════════════════════════════════════════════════════════════════

CREATE SCHEMA IF NOT EXISTS stock;

-- Needed by the two EXCLUDE constraints below (policy date overlap, ageing
-- slab overlap). Already present if 15 has been run; harmless if repeated.
CREATE EXTENSION IF NOT EXISTS btree_gist;


-- ───────────────────────────────────────────────────────────────────────────
--  §0  Year-partition helper for the stock schema.
--
--  public.fn_create_year_partitions (00_init.sql) scans public, sales and
--  accounts only. A partitioned table in stock would therefore be created
--  and then silently never given a partition — and a missing partition is
--  not a warning, it is every insert for that year failing.
--
--  Rather than edit 00_init.sql, stock brings its own. Same body, same
--  narrowing to single-column LIST partitioning (so the Prisma tables already
--  sitting in this schema are skipped, being unpartitioned), different
--  namespace. The April 1st ritual gains one line:
--
--      SELECT public.fn_create_year_partitions('2027-2028');
--      SELECT stock.fn_create_stock_partitions('2027-2028');
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_create_stock_partitions(p_acc_year character(9))
RETURNS integer
LANGUAGE plpgsql
AS $$
DECLARE
    r        record;
    v_year   text    := trim(p_acc_year);
    v_suffix text    := replace(trim(p_acc_year), '-', '_');
    v_count  integer := 0;
BEGIN
    IF v_year !~ '^\d{4}-\d{4}$' THEN
        RAISE EXCEPTION 'acc_year must look like 2026-2027, got %', p_acc_year;
    END IF;

    FOR r IN
        SELECT n.nspname AS sch, c.relname AS tbl
          FROM pg_partitioned_table pt
          JOIN pg_class     c ON c.oid = pt.partrelid
          JOIN pg_namespace n ON n.oid = c.relnamespace
         WHERE n.nspname = 'stock'
           AND pt.partstrat = 'l'      -- LIST-partitioned only
           AND pt.partnatts = 1        -- single-column key (acc_year)
         ORDER BY c.relname
    LOOP
        EXECUTE format(
            'CREATE TABLE IF NOT EXISTS %I.%I PARTITION OF %I.%I FOR VALUES IN (%L)',
            r.sch, r.tbl || '_' || v_suffix, r.sch, r.tbl, v_year);
        v_count := v_count + 1;
    END LOOP;

    RETURN v_count;   -- number of parents visited
END $$;

ALTER FUNCTION stock.fn_create_stock_partitions(character(9)) OWNER to postgres;


-- ═══════════════════════════════════════════════════════════════════════════
--  §1  stock_track_policy (stp_) — HOW an item is tracked.
--
--  The answer to "batch-wise, MRP-wise, selling-price-wise, or none".
--
--  Six independent booleans, not one enum. A mode column would have made
--  "batch AND MRP AND expiry" — the ordinary pharma case — inexpressible, and
--  the legacy item_master.batch_config integer that tried it never got a
--  defined meaning in any layer, client or server, in three versions.
--
--  Which combination is live decides ONE thing: which columns of stock_lot
--  are significant. Nothing else in the engine reads these flags, because
--  fn_slt_resolve() normalises the lot key once, at the door.
--
--  ── Scope ────────────────────────────────────────────────────────────────
--  A row applies to a COMPANY, an item GROUP, or an ITEM, optionally narrowed
--  to one branch. Resolution runs most-specific first:
--
--      item + branch  →  item  →  group + branch  →  group  →  company
--
--  The kind/scope_id pair with GENERATED per-kind columns beside it is the
--  same construction as promotion_scheme_item (15) and loyalty_scheme_item
--  (12): one polymorphic pair for the screen to bind to, and a real foreign
--  key on each kind so a deleted item group cannot leave a policy pointing at
--  nothing. Nothing can write the generated columns; they cannot drift.
--
--  ── Why effective dates ──────────────────────────────────────────────────
--  Turning batch tracking ON for an item that already has stock is a real
--  event with a date, not a checkbox. Lots created before the change keep the
--  signature they were created under (slt_track_signature), so history stays
--  readable and a policy change can never silently re-key old stock.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_track_policy
(
    stp_id                   uuid           NOT NULL DEFAULT uuidv7(),
    -- NULL = EVERY company. inventory.item_master.item_company_id is itself
    -- nullable and items are deliberately not company-owned, so a company-less
    -- item would have nothing to write a policy against — and an item used by
    -- two companies would need two identical rows, either of which could be
    -- edited without the other. A company-specific row beats a NULL one.
    stp_company_id           uuid,
    -- NULL = every branch in the company. A branch row beats a company row.
    stp_branch_id            uuid,

    -- ── Scope: the pair, and the typed columns beside it ─────────────────
    stp_scope                character varying(20) NOT NULL DEFAULT 'COMPANY',
    -- NULL only when stp_scope = 'COMPANY'.
    stp_scope_id             uuid,

    stp_item_id  uuid GENERATED ALWAYS AS
        (CASE WHEN stp_scope = 'ITEM'  THEN stp_scope_id END) STORED,
    stp_group_id uuid GENERATED ALWAYS AS
        (CASE WHEN stp_scope = 'GROUP' THEN stp_scope_id END) STORED,

    -- ── What is significant about a holding ──────────────────────────────
    -- All false = plain item-wise stock: one lot, for ever, every identity
    -- column NULL. That is the DEFAULT, and it is the common case.
    stp_track_batch          boolean NOT NULL DEFAULT false,
    stp_track_mrp            boolean NOT NULL DEFAULT false,
    stp_track_sale_price     boolean NOT NULL DEFAULT false,
    stp_track_expiry         boolean NOT NULL DEFAULT false,
    stp_track_serial         boolean NOT NULL DEFAULT false,
    -- Supplier is tracked separately from batch on purpose: the same batch
    -- number from two suppliers is two holdings, and only this flag decides
    -- whether the business cares.
    stp_track_supplier       boolean NOT NULL DEFAULT false,

    -- B/M/S/E/R/P in that order, 'N' when nothing is tracked. Stamped onto
    -- every lot at creation so history survives a policy change.
    stp_track_signature      character varying(8) GENERATED ALWAYS AS (
        COALESCE(NULLIF(
            (CASE WHEN stp_track_batch      THEN 'B' ELSE '' END) ||
            (CASE WHEN stp_track_mrp        THEN 'M' ELSE '' END) ||
            (CASE WHEN stp_track_sale_price THEN 'S' ELSE '' END) ||
            (CASE WHEN stp_track_expiry     THEN 'E' ELSE '' END) ||
            (CASE WHEN stp_track_serial     THEN 'R' ELSE '' END) ||
            (CASE WHEN stp_track_supplier   THEN 'P' ELSE '' END)
        , ''), 'N') ) STORED,

    -- ── How it is valued ─────────────────────────────────────────────────
    -- WAVG reads stock_item_cost; FIFO and LOT_ACTUAL read slt_cost_rate.
    -- Both are always maintained, so this only selects which one a report
    -- believes — changing it needs no recomputation.
    stp_valuation_method     character varying(20) NOT NULL DEFAULT 'WAVG',

    -- ── Which lot goes out when nobody names one ─────────────────────────
    -- The single most consequential column in this file. /master-lookups/
    -- item-price returns ONE stock row to the billing screen; before this
    -- there was nothing in the schema that said which. FEFO (first expiry,
    -- first out) is the default because it is right for anything perishable
    -- and harmless for anything else.
    stp_issue_strategy       character varying(20) NOT NULL DEFAULT 'FEFO',

    -- ── Negative stock ───────────────────────────────────────────────────
    -- ALLOW because a counter must be able to sell before the GRN clerk has
    -- caught up. WARN posts and flags. BLOCK aborts the transaction — for
    -- controlled substances and anything serialised.
    stp_allow_negative       character varying(10) NOT NULL DEFAULT 'ALLOW',

    -- ── Expiry ───────────────────────────────────────────────────────────
    stp_shelf_life_days      integer,
    stp_near_expiry_days     integer        NOT NULL DEFAULT 30,
    stp_block_expired_sale   boolean        NOT NULL DEFAULT false,

    -- INWARD_DATE  — when the lot first entered the company (chain-wide age)
    -- LAST_IN_DATE — when it last entered THIS godown (shelf age)
    -- MFG_DATE     — age of the goods themselves
    stp_ageing_basis         character varying(20) NOT NULL DEFAULT 'INWARD_DATE',

    -- ── When this policy is in force ─────────────────────────────────────
    -- The window is resolved against the DOCUMENT's date, not today's, so a
    -- business can genuinely say "we start tracking batches on 1 July" and
    -- have June's receipts keep the identity scheme they were entered under.
    --
    -- The default start is deliberately far in the past. Defaulting it to
    -- CURRENT_DATE looks tidier and is a trap: a policy authored today would
    -- not apply to a receipt back-dated to yesterday, which would silently
    -- fall through to "track nothing" and create an untracked lot for an item
    -- the business believes is batch-tracked. A policy with no stated start
    -- date has always been in force.
    stp_effective_from       date           NOT NULL DEFAULT DATE '1900-01-01',
    stp_effective_to         date           NOT NULL DEFAULT DATE '9999-12-31',

    stp_remarks              character varying(250),
    stp_is_active            boolean NOT NULL DEFAULT true,
    stp_is_deleted           boolean NOT NULL DEFAULT false,
    stp_sync_date            timestamp with time zone,
    stp_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    stp_created_by           uuid,
    stp_modified_on          timestamp with time zone,
    stp_modified_by          uuid,

    CONSTRAINT pk_stock_track_policy PRIMARY KEY (stp_id),

    -- Two policies for the same thing, same branch, overlapping dates, is not
    -- a rule — it is whichever the resolver reads first, and the same item
    -- keys its stock differently on two tills. The database refuses it.
    -- NULLs COALESCE'd to the nil uuid because EXCLUDE never conflicts on
    -- NULL, which would let every company-wide row clash with nothing at all.
    CONSTRAINT ex_stp_overlap EXCLUDE USING gist (
        -- COALESCEd for the same reason branch and scope_id are, immediately
        -- below: EXCLUDE never conflicts on NULL, so two every-company rows
        -- for the same scope and dates would both be accepted.
        (COALESCE(stp_company_id, '00000000-0000-0000-0000-000000000000'::uuid)) WITH =,
        (COALESCE(stp_branch_id, '00000000-0000-0000-0000-000000000000'::uuid)) WITH =,
        stp_scope WITH =,
        (COALESCE(stp_scope_id, '00000000-0000-0000-0000-000000000000'::uuid)) WITH =,
        daterange(stp_effective_from, stp_effective_to, '[]') WITH &&
    ) WHERE (stp_is_active = true AND stp_is_deleted = false),

    CONSTRAINT fk_stp_company FOREIGN KEY (stp_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_stp_branch FOREIGN KEY (stp_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    -- NO ACTION, not CASCADE: PostgreSQL refuses ON UPDATE CASCADE on a
    -- foreign key over a GENERATED column, because it cannot write one.
    -- Same reason files 12 and 15 spell their scope FKs this way.
    CONSTRAINT fk_stp_item FOREIGN KEY (stp_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE NO ACTION ON DELETE RESTRICT,
    CONSTRAINT fk_stp_group FOREIGN KEY (stp_group_id)
        REFERENCES inventory.item_group_master (itg_id) MATCH SIMPLE
        ON UPDATE NO ACTION ON DELETE RESTRICT,
    CONSTRAINT fk_stp_created_by FOREIGN KEY (stp_created_by)
        REFERENCES public.user_master (usr_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_stp_scope CHECK (
        stp_scope::text = ANY (ARRAY['COMPANY'::text, 'GROUP'::text, 'ITEM'::text])),
    -- COMPANY carries no id; GROUP and ITEM must.
    CONSTRAINT ck_stp_scope_id CHECK (
        (stp_scope::text = 'COMPANY' AND stp_scope_id IS NULL)
     OR (stp_scope::text <> 'COMPANY' AND stp_scope_id IS NOT NULL)),
    CONSTRAINT ck_stp_valuation CHECK (
        stp_valuation_method::text = ANY (ARRAY['WAVG'::text, 'FIFO'::text,
                                                'LOT_ACTUAL'::text])),
    CONSTRAINT ck_stp_issue_strategy CHECK (
        stp_issue_strategy::text = ANY (ARRAY['FIFO'::text, 'FEFO'::text,
                                              'LIFO'::text, 'MANUAL'::text])),
    CONSTRAINT ck_stp_allow_negative CHECK (
        stp_allow_negative::text = ANY (ARRAY['ALLOW'::text, 'WARN'::text,
                                              'BLOCK'::text])),
    CONSTRAINT ck_stp_ageing_basis CHECK (
        stp_ageing_basis::text = ANY (ARRAY['INWARD_DATE'::text, 'MFG_DATE'::text,
                                            'LAST_IN_DATE'::text])),
    CONSTRAINT ck_stp_dates CHECK (stp_effective_to >= stp_effective_from),
    CONSTRAINT ck_stp_near_expiry CHECK (stp_near_expiry_days >= 0),
    CONSTRAINT ck_stp_shelf_life CHECK (
        stp_shelf_life_days IS NULL OR stp_shelf_life_days > 0),
    -- Expiry tracking without batch tracking cannot be keyed: two deliveries
    -- with different expiry dates and no batch number are indistinguishable
    -- on the shelf.
    CONSTRAINT ck_stp_expiry_needs_batch CHECK (
        stp_track_expiry = false OR stp_track_batch = true),
    -- FEFO can only order lots that have an expiry date to order by.
    CONSTRAINT ck_stp_fefo_needs_expiry CHECK (
        stp_issue_strategy::text <> 'FEFO' OR stp_track_expiry = true
        OR stp_track_batch = false)
);

ALTER TABLE IF EXISTS stock.stock_track_policy OWNER to postgres;

-- The resolver's exact lookup shape, most-specific first.
CREATE INDEX IF NOT EXISTS ix_stp_resolve
    ON stock.stock_track_policy USING btree
    (stp_company_id, stp_scope, stp_scope_id, stp_branch_id)
    INCLUDE (stp_effective_from, stp_effective_to)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE stp_is_active = true AND stp_is_deleted = false;

CREATE INDEX IF NOT EXISTS ix_stp_item
    ON stock.stock_track_policy USING btree (stp_item_id)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE stp_item_id IS NOT NULL AND stp_is_deleted = false;


-- ═══════════════════════════════════════════════════════════════════════════
--  §2  stock_reason_master (srm_) — WHY stock moved.
--
--  A lookup table and not a CHECK list, because reasons are exactly the thing
--  a business adds to: "damaged in transit", "shop soiled", "sample to rep",
--  "rat bite", "festival display shrinkage". Each can be pointed at a GL
--  ledger so a write-off posts itself.
--
--  fixed.stock_adj_reasons already exists and is left alone; it belongs to
--  the legacy engine and its rows carry no GL link.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_reason_master
(
    srm_id                   uuid           NOT NULL DEFAULT uuidv7(),
    -- NULL = a SHARED reason, offered to every company. Unlike the tracking
    -- policy (most-specific row wins) and the ageing ladder (all-or-nothing),
    -- reasons MERGE: a picker shows the shared ones and the company's own
    -- together, because the user is choosing one from a list and more choices
    -- are not a contradiction. A company that defines its own row with the
    -- same code overrides the shared one — see the reason picker in 16q.
    srm_company_id           uuid,
    srm_code                 character varying(30)  NOT NULL,
    srm_name                 character varying(150) NOT NULL,

    -- Which movements may cite it. Empty array = any. Kept as text[] rather
    -- than a child table because it is a filter for a dropdown, not a rule
    -- anybody reports on.
    srm_allowed_txn_types    text[]         NOT NULL DEFAULT '{}'::text[],
    -- IN, OUT or BOTH — stops "damaged" appearing on a receipt screen.
    srm_direction            character varying(10)  NOT NULL DEFAULT 'BOTH',

    srm_require_remarks      boolean        NOT NULL DEFAULT false,
    -- Where the value goes when stock is written off. NULL = no auto posting.
    srm_gl_ledger_id         uuid,
    srm_sort_order           integer        NOT NULL DEFAULT 0,

    srm_remarks              character varying(250),
    srm_is_active            boolean NOT NULL DEFAULT true,
    srm_is_deleted           boolean NOT NULL DEFAULT false,
    srm_sync_date            timestamp with time zone,
    srm_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    srm_created_by           uuid,
    srm_modified_on          timestamp with time zone,
    srm_modified_by          uuid,

    CONSTRAINT pk_stock_reason_master PRIMARY KEY (srm_id),

    CONSTRAINT fk_srm_company FOREIGN KEY (srm_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srm_gl_ledger FOREIGN KEY (srm_gl_ledger_id)

    CONSTRAINT ck_srm_code_shape CHECK (srm_code ~ '^[A-Za-z0-9_-]+$')
);

-- ═══════════════════════════════════════════════════════════════════════════
--  §3  stock_ageing_slab (sag_) — the ageing buckets, as data.
--
--  0-30 / 31-60 / 61-90 / 91-180 / 181+ is one company's answer, not every
--  company's: a dairy wants 0-3 / 4-7 / 8+, a jeweller wants years. The
--  buckets are rows so the report does not have to be rewritten.
--
--  sag_to_days NULL is the open-ended last slab. The EXCLUDE stops two slabs
--  claiming the same day, which would double-count stock in a report that
--  must sum to the balance.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_ageing_slab
(
    sag_id                   uuid           NOT NULL DEFAULT uuidv7(),
    -- NULL = the DEFAULT ladder, used by any company that has not defined one
    -- of its own. Note this is an ALL-OR-NOTHING fallback, not a merge: see
    -- fn_sag_effective. A company either uses its own slabs or the default
    -- ones, never a mixture — mixing two ladders would put one holding in two
    -- buckets and the report would stop summing to the balance.
    sag_company_id           uuid,
    sag_slab_no              integer        NOT NULL,
    sag_label                character varying(50)  NOT NULL,
    sag_from_days            integer        NOT NULL,
    -- NULL = open ended; there must be exactly one such slab per ladder.
    sag_to_days              integer,

    sag_is_active            boolean NOT NULL DEFAULT true,
    sag_is_deleted           boolean NOT NULL DEFAULT false,
    sag_sync_date            timestamp with time zone,
    sag_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    sag_created_by           uuid,
    sag_modified_on          timestamp with time zone,
    sag_modified_by          uuid,

    CONSTRAINT pk_stock_ageing_slab PRIMARY KEY (sag_id),

    -- The range is half-open: inclusive from, exclusive to+1. Written this
    -- way rather than as '[]' because an inclusive bound of int4's maximum
    -- overflows when PostgreSQL normalises it to upper+1.
    CONSTRAINT ex_sag_overlap EXCLUDE USING gist (
        -- COALESCEd because EXCLUDE never conflicts on NULL: without it two
        -- default slabs could claim the same day. A default slab and a company
        -- slab covering the same days DO coexist, and must — they belong to
        -- different ladders.
        (COALESCE(sag_company_id, '00000000-0000-0000-0000-000000000000'::uuid)) WITH =,
        int4range(sag_from_days, COALESCE(sag_to_days + 1, 2147483647), '[)') WITH &&
    ) WHERE (sag_is_active = true AND sag_is_deleted = false)
      -- DEFERRABLE so a screen can save a whole ladder in one transaction.
      -- Shrinking 0-30 to 0-14 collides with 31-60 until that row moves too,
      -- so a row-at-a-time save cannot reorder a ladder at all. A client that
      -- needs to issues SET CONSTRAINTS stock.ex_sag_overlap DEFERRED first.
      -- INITIALLY IMMEDIATE, so nothing that does not ask for it changes.
      DEFERRABLE INITIALLY IMMEDIATE,

    CONSTRAINT fk_sag_company FOREIGN KEY (sag_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_sag_days CHECK (
        sag_from_days >= 0 AND (sag_to_days IS NULL OR sag_to_days >= sag_from_days)),
    CONSTRAINT ck_sag_slab_no CHECK (sag_slab_no >= 1)
);

ALTER TABLE IF EXISTS stock.stock_ageing_slab OWNER to postgres;

-- COALESCEd for the same reason as the EXCLUDE above: a plain unique index
-- treats every NULL as distinct, so two default slabs could both be slab 1.
CREATE UNIQUE INDEX IF NOT EXISTS ux_sag_slab_no
    ON stock.stock_ageing_slab USING btree
    ((COALESCE(sag_company_id, '00000000-0000-0000-0000-000000000000'::uuid)), sag_slab_no)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sag_is_deleted = false;


-- ═══════════════════════════════════════════════════════════════════════════
--  §4  stock_lot (slt_) — the IDENTITY of a holding. Never its quantity.
--
--  A lot is "this item, this batch, this MRP, this selling price, this
--  expiry, from this supplier". Quantity lives in stock_balance, movement in
--  stock_ledger. Splitting identity from quantity is what lets the same lot
--  be held in four godowns across three branches without four truths about
--  its expiry date.
--
--  ── Company-scoped, deliberately ─────────────────────────────────────────
--  A lot is NOT per branch. Transfer stock from Anna Nagar to Adyar and it is
--  the same batch, the same expiry, the same supplier, and — critically — the
--  same age. A per-branch lot would reset the ageing clock at every transfer
--  and let a chain hide ninety-day-old stock by moving it. Branch and godown
--  live on stock_balance, which carries its own sbl_first_in_date for "how
--  long has it been on THIS shelf".
--
--  ── The null-normalised key ──────────────────────────────────────────────
--  Every tracked dimension is a nullable column with a generated companion
--  that substitutes a sentinel when it is NULL. The unique index is built
--  over the companions, never the originals, because a UNIQUE index treats
--  every NULL as distinct — which would let the same untracked item accrete
--  a new lot on every single receipt, for ever.
--
--      tracked:      slt_mrp = 120.00  →  slt_key_mrp = 120.00
--      not tracked:  slt_mrp = NULL    →  slt_key_mrp = -1
--
--  So an item tracked by nothing has exactly ONE lot with all six identity
--  columns NULL, and every consumer of the engine — reports, the billing
--  lookup, the ledger — treats it identically to a pharma lot. There is no
--  "non-batch path" anywhere in this file.
--
--  Sentinels are chosen to be impossible values, not merely unlikely: '~'
--  sorts after every alphanumeric batch number, -1 cannot be a price,
--  0001-01-01 cannot be an expiry date, and the nil uuid is not a supplier.
--
--  ── Why the supplier is here and not derived ─────────────────────────────
--  Supplier-wise stock traced back through consumption is a guess the moment
--  two receipts of the same batch are commingled: which supplier's units did
--  the customer take? Locking the supplier onto the lot makes the question
--  disappear. The cost is more rows; the return is that supplier-wise stock,
--  supplier-wise ageing and a supplier recall are all one WHERE clause.
--
--  ── Cost on the lot ──────────────────────────────────────────────────────
--  slt_cost_rate is this lot's own cost, which is what makes FIFO and
--  LOT_ACTUAL valuation a read rather than a replay. The moving weighted
--  average is maintained in parallel in stock_item_cost. Both, always, so
--  stp_valuation_method selects an answer instead of triggering a rebuild.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_lot
(
    slt_id                   uuid           NOT NULL DEFAULT uuidv7(),
    slt_company_id           uuid           NOT NULL,
    slt_tenant_id            uuid,

    slt_item_id              uuid           NOT NULL,
    -- The item's BASE unit (an iuc_id). Every quantity anywhere in this
    -- engine is stored in this unit as well as in the unit it was keyed in.
    slt_base_uom_id          uuid           NOT NULL,

    -- ── Identity. NULL means "not significant for this item". ────────────
    slt_batch_no             character varying(100),
    slt_mfg_batch_no         character varying(100),
    slt_mrp                  numeric(18,6),
    slt_sale_price           numeric(18,6),
    slt_mfg_date             date,
    slt_expiry_date          date,
    slt_serial_no            character varying(100),
    slt_supplier_id          uuid,

    -- ── The key the unique index is actually built on ────────────────────
    slt_key_batch    character varying(100) GENERATED ALWAYS AS
        (COALESCE(NULLIF(upper(btrim(slt_batch_no)), ''), '~')) STORED,
    slt_key_mrp      numeric(18,6) GENERATED ALWAYS AS
        (COALESCE(slt_mrp, -1)) STORED,
    slt_key_sp       numeric(18,6) GENERATED ALWAYS AS
        (COALESCE(slt_sale_price, -1)) STORED,
    slt_key_expiry   date GENERATED ALWAYS AS
        (COALESCE(slt_expiry_date, DATE '0001-01-01')) STORED,
    slt_key_serial   character varying(100) GENERATED ALWAYS AS
        (COALESCE(NULLIF(upper(btrim(slt_serial_no)), ''), '~')) STORED,
    slt_key_supplier uuid GENERATED ALWAYS AS
        (COALESCE(slt_supplier_id, '00000000-0000-0000-0000-000000000000'::uuid)) STORED,

    -- Which flags were live when this lot was created (see §1). A policy
    -- change tomorrow must not make yesterday's lots unreadable.
    slt_track_signature      character varying(8) NOT NULL DEFAULT 'N',

    -- ── Where it came from, and when ─────────────────────────────────────
    -- The ageing anchor for the chain as a whole, and the recall trail.
    slt_first_inward_date    date           NOT NULL DEFAULT CURRENT_DATE,
    slt_first_inward_branch  uuid,
    slt_inward_src_module    character varying(20),
    slt_inward_src_doc_type  character varying(30),
    slt_inward_src_doc_id    uuid,
    slt_inward_src_acc_year  character(9),
    slt_inward_refno         character varying(100),

    -- ── Cost, as received ────────────────────────────────────────────────
    slt_purchase_rate        numeric(18,6)  NOT NULL DEFAULT 0,  -- supplier's rate, with tax
    slt_cost_rate            numeric(18,6)  NOT NULL DEFAULT 0,  -- landed, with tax
    slt_cost_rate_wot        numeric(18,6)  NOT NULL DEFAULT 0,  -- landed, without tax
    slt_landed_rate          numeric(18,6)  NOT NULL DEFAULT 0,  -- incl freight/loading
    slt_tax_rate             numeric(9,3)   NOT NULL DEFAULT 0,

    -- ── Lifecycle ────────────────────────────────────────────────────────
    -- CLOSED is set by the engine when the last unit leaves; BLOCKED and
    -- EXPIRED are business decisions that stop the lot being issued.
    slt_status               character varying(20) NOT NULL DEFAULT 'ACTIVE',
    slt_closed_on            timestamp with time zone,
    slt_blocked_reason       character varying(250),

    -- Chain-wide total across every branch and godown. TRIGGER-MAINTAINED
    -- from stock_ledger by fn_sml_apply(). Never written from application
    -- code; stock_balance owns the per-godown truth this sums.
    slt_total_on_hand        numeric(18,6)  NOT NULL DEFAULT 0,

    slt_row_version          bigint         NOT NULL DEFAULT 1,
    slt_remarks              character varying(250),
    slt_is_active            boolean NOT NULL DEFAULT true,
    slt_is_deleted           boolean NOT NULL DEFAULT false,
    slt_sync_date            timestamp with time zone,
    slt_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    slt_created_by           uuid,
    slt_modified_on          timestamp with time zone,
    slt_modified_by          uuid,

    CONSTRAINT pk_stock_lot PRIMARY KEY (slt_id),

    CONSTRAINT fk_slt_company FOREIGN KEY (slt_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_slt_item FOREIGN KEY (slt_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_slt_base_uom FOREIGN KEY (slt_base_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_slt_supplier FOREIGN KEY (slt_supplier_id)
        REFERENCES purchase.suppliers (sup_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_slt_branch FOREIGN KEY (slt_first_inward_branch)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_slt_status CHECK (
        slt_status::text = ANY (ARRAY['ACTIVE'::text, 'CLOSED'::text,
                                      'BLOCKED'::text, 'EXPIRED'::text])),
    CONSTRAINT ck_slt_expiry_order CHECK (
        slt_mfg_date IS NULL OR slt_expiry_date IS NULL
        OR slt_expiry_date >= slt_mfg_date),
    CONSTRAINT ck_slt_prices CHECK (
        (slt_mrp IS NULL OR slt_mrp >= 0) AND
        (slt_sale_price IS NULL OR slt_sale_price >= 0)),
    CONSTRAINT ck_slt_batch_shape CHECK (
        slt_batch_no IS NULL OR length(btrim(slt_batch_no)) > 0),
    CONSTRAINT ck_slt_serial_shape CHECK (
        slt_serial_no IS NULL OR length(btrim(slt_serial_no)) > 0),
    -- The source triple is all-or-nothing, as everywhere else in the chain.
    CONSTRAINT ck_slt_inward_src CHECK (
        (slt_inward_src_doc_id IS NULL AND slt_inward_src_doc_type IS NULL
         AND slt_inward_src_module IS NULL)
     OR (slt_inward_src_doc_id IS NOT NULL AND slt_inward_src_doc_type IS NOT NULL
         AND slt_inward_src_module IS NOT NULL))
);

ALTER TABLE IF EXISTS stock.stock_lot OWNER to postgres;

-- ── THE index of this file ─────────────────────────────────────────────────
-- Built entirely over the generated key columns. This is what collapses
-- batch-wise, MRP-wise, selling-price-wise and none into one mechanism: an
-- untracked item normalises to ('~', -1, -1, 0001-01-01, '~', nil) on every
-- receipt and therefore finds its existing lot instead of making another.
CREATE UNIQUE INDEX IF NOT EXISTS ux_slt_identity
    ON stock.stock_lot USING btree
    (slt_company_id, slt_item_id, slt_key_batch, slt_key_mrp, slt_key_sp,
     slt_key_expiry, slt_key_serial, slt_key_supplier)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE slt_is_deleted = false;

-- FEFO and near-expiry, the two reads that must never scan.
CREATE INDEX IF NOT EXISTS ix_slt_expiry
    ON stock.stock_lot USING btree
    (slt_company_id, slt_item_id, slt_expiry_date)
    INCLUDE (slt_batch_no, slt_mrp, slt_total_on_hand)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE slt_expiry_date IS NOT NULL AND slt_status::text = 'ACTIVE'
      AND slt_is_deleted = false;

-- FIFO / LIFO, and the chain-wide ageing report.
CREATE INDEX IF NOT EXISTS ix_slt_inward
    ON stock.stock_lot USING btree
    (slt_company_id, slt_item_id, slt_first_inward_date)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE slt_is_deleted = false;

-- Supplier-wise stock and supplier recall.
CREATE INDEX IF NOT EXISTS ix_slt_supplier
    ON stock.stock_lot USING btree
    (slt_company_id, slt_supplier_id, slt_item_id)
    INCLUDE (slt_batch_no, slt_total_on_hand)

-- Batch traceability by number alone: "who has any of batch AX-4471?"
CREATE INDEX IF NOT EXISTS ix_slt_batch_no

    WITH (fillfactor=100, deduplicate_items=True)
    WHERE slt_batch_no IS NOT NULL AND slt_is_deleted = false;

-- MRP-wise stock summary: the retail question "how much at 120, how much
-- at the old 110".
CREATE INDEX IF NOT EXISTS ix_slt_mrp
    ON stock.stock_lot USING btree
    (slt_company_id, slt_item_id, slt_mrp)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE slt_mrp IS NOT NULL AND slt_is_deleted = false;


-- ═══════════════════════════════════════════════════════════════════════════
--  §5  stock_ledger (sml_) — every movement. The truth.
--
--  Append-only. Never updated in place, never deleted. A cancelled bill does
--  not remove its ledger rows, it writes reversing ones — because a stock
--  figure that can change retrospectively is a stock figure nobody can
--  reconcile, and because in an offline chain the cancellation may arrive
--  after the day was closed.
--
--  A BEFORE DELETE trigger (§17) raises rather than trusting convention.
--
--  ── Grain ────────────────────────────────────────────────────────────────
--  One row per (source document, line, split, godown, lot, direction). That
--  is exactly the grain sale_bill_item already emits — sbi_line_no ×
--  sbi_split_no × sbi_godown_id × sbi_stock_id — so posting a bill is a
--  straight INSERT ... SELECT with no reshaping and no aggregation.
--
--  A transfer writes TWO rows, not one: TRANSFER_OUT at the source and
--  TRANSFER_IN at the destination, each with its own godown. They are not
--  simultaneous — see stock_transit (§11).
--
--  ── Why there is no running balance column ───────────────────────────────
--  A "balance after this movement" column is the classic stock-ledger trap:
--  two tills posting concurrently must serialise on it, a back-dated entry
--  invalidates every row after it, and the offline chain has no global order
--  to compute it in. The balance is stock_balance's job and nothing else's.
--
--  ── Free quantity is stock ───────────────────────────────────────────────
--  Free goods sit on the shelf and get sold. They are counted in on-hand.
--  They are also kept in their own columns, because margin reporting must
--  separate what was paid for from what was not. sml_signed_base_qty adds
--  both and applies the direction — it is the one column every quantity
--  report sums, and the only one stock_balance reads.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_ledger
(
    sml_id                   uuid           NOT NULL DEFAULT uuidv7(),
    sml_company_id           uuid           NOT NULL,
    sml_branch_id            uuid           NOT NULL,
    sml_tenant_id            uuid,
    sml_acc_year             character(9)   NOT NULL,

    -- Where the stock physically is. Never nullable: an unlocated movement
    -- cannot be reversed, counted or transferred. branch_master.
    -- br_default_godown_id resolves it for screens with no godown selector.
    sml_godown_id            uuid           NOT NULL,

    -- ── What moved ───────────────────────────────────────────────────────
    sml_item_id              uuid           NOT NULL,
    sml_lot_id               uuid           NOT NULL,
    -- The unit the document was keyed in (an iuc_id), and the item's base
    -- unit. Both stored so a report can show "3 cases" and still sum pieces.
    sml_uom_id               uuid           NOT NULL,
    sml_base_uom_id          uuid           NOT NULL,
    sml_to_base_factor       numeric(18,6)  NOT NULL DEFAULT 1,

    -- ── Which document caused it ─────────────────────────────────────────
    -- The (module, doc_type, doc_id) triple used by acc_tender_detail,
    -- txn_status_log, txn_hold and acc_voucher_doc_register. A new document
    -- type that moves stock costs one CHECK value here and nothing else.
    sml_src_module           character varying(20)  NOT NULL,
    sml_src_doc_type         character varying(30)  NOT NULL,
    sml_src_doc_id           uuid           NOT NULL,
    -- The document's own year, which is not always this row's year: a
    -- sale return in April against a March bill posts here in the new year.
    sml_src_acc_year         character(9),
    sml_src_refno            character varying(100),
    sml_line_no              integer        NOT NULL DEFAULT 1,
    sml_split_no             integer        NOT NULL DEFAULT 1,

    -- ── The movement itself ──────────────────────────────────────────────
    sml_txn_type             character varying(30)  NOT NULL,
    -- +1 in, -1 out. Redundant against txn_type on purpose: a report that
    -- sums must not have to know that EXPIRY_WRITEOFF is an out.
    sml_direction            smallint       NOT NULL,
    -- Saleable stock and damaged stock are both stock, and must never be
    -- added together by accident. Separate buckets, one balance row each.
    sml_bucket               character varying(20)  NOT NULL DEFAULT 'SALEABLE',

    sml_doc_date             date           NOT NULL,
    sml_doc_datetime         timestamp with time zone NOT NULL DEFAULT now(),
    sml_posted_on            timestamp with time zone NOT NULL DEFAULT now(),

    -- ── Quantity, as keyed and in base ───────────────────────────────────
    sml_qty                  numeric(18,6)  NOT NULL DEFAULT 0,
    sml_base_qty             numeric(18,6)  NOT NULL DEFAULT 0,
    sml_free_qty             numeric(18,6)  NOT NULL DEFAULT 0,
    sml_free_base_qty        numeric(18,6)  NOT NULL DEFAULT 0,
    sml_weight_qty           numeric(18,6)  NOT NULL DEFAULT 0,

    -- The one column stock_balance reads and every quantity report sums.
    sml_signed_base_qty      numeric(18,6) GENERATED ALWAYS AS
        (sml_direction::numeric * (sml_base_qty + sml_free_base_qty)) STORED,

    -- ── Value ────────────────────────────────────────────────────────────
    -- On an inward these are what it cost. On an outward they are what it
    -- cost US (the COGS), taken from the lot or the moving average per
    -- stp_valuation_method — never the selling price.
    sml_cost_rate            numeric(18,6)  NOT NULL DEFAULT 0,
    sml_cost_value           numeric(18,2)  NOT NULL DEFAULT 0,
    sml_cost_rate_wot        numeric(18,6)  NOT NULL DEFAULT 0,
    sml_cost_value_wot       numeric(18,2)  NOT NULL DEFAULT 0,
    sml_landed_rate          numeric(18,6)  NOT NULL DEFAULT 0,
    sml_landed_value         numeric(18,2)  NOT NULL DEFAULT 0,
    -- What the document said, which is the selling price on a sale. Kept
    -- beside cost so margin needs no join back to sale_bill_item.
    sml_doc_rate             numeric(18,6)  NOT NULL DEFAULT 0,
    sml_doc_rate_wot         numeric(18,6)  NOT NULL DEFAULT 0,
    sml_doc_amount_wot       numeric(18,2)  NOT NULL DEFAULT 0,
    -- Snapshots from the lot, so batch/MRP-wise reports read one table.
    sml_mrp                  numeric(18,6),
    sml_batch_no             character varying(100),
    sml_expiry_date          date,

    -- ── Reversal ─────────────────────────────────────────────────────────
    sml_is_reversal          boolean        NOT NULL DEFAULT false,
    sml_reverses_id          uuid,

    sml_reason_id            uuid,
    sml_party_id             uuid,          -- customer or supplier, per module
    sml_narration            text,

    sml_is_deleted           boolean NOT NULL DEFAULT false,
    sml_sync_date            timestamp with time zone,
    sml_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    sml_created_by           uuid,

    CONSTRAINT pk_stock_ledger PRIMARY KEY (sml_id, sml_acc_year),

    CONSTRAINT fk_sml_company FOREIGN KEY (sml_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sml_branch FOREIGN KEY (sml_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sml_godown FOREIGN KEY (sml_godown_id)
        REFERENCES inventory.godown_locations (gdl_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sml_item FOREIGN KEY (sml_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sml_lot FOREIGN KEY (sml_lot_id)
        REFERENCES stock.stock_lot (slt_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sml_uom FOREIGN KEY (sml_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sml_base_uom FOREIGN KEY (sml_base_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sml_reason FOREIGN KEY (sml_reason_id)
        REFERENCES stock.stock_reason_master (srm_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_sml_acc_year CHECK (
        sml_acc_year ~ '^[0-9]{4}-[0-9]{4}$'
        AND RIGHT(sml_acc_year, 4)::int = LEFT(sml_acc_year, 4)::int + 1),
    CONSTRAINT ck_sml_txn_type CHECK (
        sml_txn_type::text = ANY (ARRAY[
            'OPENING'::text,          'PURCHASE'::text,      'PURCHASE_RETURN'::text,
            'SALE'::text,             'SALE_RETURN'::text,
            'TRANSFER_OUT'::text,     'TRANSFER_IN'::text,
            'ADJUST_PLUS'::text,      'ADJUST_MINUS'::text,
            'PHYSICAL_PLUS'::text,    'PHYSICAL_MINUS'::text,
            'DAMAGE'::text,           'EXPIRY_WRITEOFF'::text,
            'REPACK_IN'::text,        'REPACK_OUT'::text,
            'BUCKET_IN'::text,        'BUCKET_OUT'::text,
            'GIFT_ISSUE'::text,       'SAMPLE_ISSUE'::text])),
    CONSTRAINT ck_sml_direction CHECK (sml_direction = ANY (ARRAY[1, -1])),
    CONSTRAINT ck_sml_bucket CHECK (
        sml_bucket::text = ANY (ARRAY['SALEABLE'::text, 'DAMAGED'::text,
                                      'QUARANTINE'::text, 'EXPIRED'::text,
                                      'SAMPLE'::text])),
    CONSTRAINT ck_sml_src_module CHECK (
        sml_src_module::text = ANY (ARRAY['SALES'::text, 'PURCHASE'::text,
                                          'STOCK'::text, 'LOYALTY'::text,
                                          'PRODUCTION'::text, 'MIGRATION'::text])),
    CONSTRAINT ck_sml_split_no CHECK (sml_split_no >= 1),
    CONSTRAINT ck_sml_line_no CHECK (sml_line_no >= 1),
    -- Quantities are magnitudes; the sign lives in sml_direction alone. A
    -- negative qty with a negative direction is a silent double negation.
    CONSTRAINT ck_sml_qty_sign CHECK (
        sml_qty >= 0 AND sml_base_qty >= 0
        AND sml_free_qty >= 0 AND sml_free_base_qty >= 0),
    CONSTRAINT ck_sml_qty_nonzero CHECK (
        sml_base_qty + sml_free_base_qty > 0),
    CONSTRAINT ck_sml_to_base_factor CHECK (sml_to_base_factor > 0),
    CONSTRAINT ck_sml_reversal CHECK (
        (sml_is_reversal = false AND sml_reverses_id IS NULL)
     OR (sml_is_reversal = true  AND sml_reverses_id IS NOT NULL))
) PARTITION BY LIST (sml_acc_year);

-- ── Posting idempotency ────────────────────────────────────────────────────
-- The same bill posted twice — a retry after a timeout, a sync replaying a
-- day — must not move stock twice. Same shape as ux_gdr_source (05) and
-- ux_avh_src (03). Direction is in the key because a transfer legitimately
-- writes an OUT and an IN for one source line.
CREATE UNIQUE INDEX IF NOT EXISTS ux_sml_source
    ON stock.stock_ledger USING btree
    (sml_company_id, sml_branch_id, sml_acc_year, sml_src_module,
     sml_src_doc_type, sml_src_doc_id, sml_line_no, sml_split_no,
     sml_godown_id, sml_lot_id, sml_direction)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sml_is_deleted = false AND sml_is_reversal = false;

-- ── Reversal idempotency ───────────────────────────────────────────────────
-- ux_sml_source deliberately excludes reversal rows, which would otherwise
-- leave them with no unique constraint at all. fn_svh_cancel (19) guards with
-- a NOT EXISTS, but that is read-then-write: two concurrent cancels, or an
-- offline sync replaying a cancellation that already applied, could both pass
-- it and reverse the same movement twice — moving stock the wrong way with no
-- error. One reversal per ledger row, and the second insert fails instead.
-- (Nothing legitimately reverses a row twice: a cancelled voucher cannot be
-- re-posted, and a reversal is never itself reversed.)
CREATE UNIQUE INDEX IF NOT EXISTS ux_sml_reversal
    ON stock.stock_ledger USING btree (sml_reverses_id, sml_acc_year)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sml_is_reversal = true AND sml_is_deleted = false;

-- The item ledger screen: one item, one branch, in date order.
CREATE INDEX IF NOT EXISTS ix_sml_item_date
    ON stock.stock_ledger USING btree
    (sml_company_id, sml_branch_id, sml_item_id, sml_doc_date DESC)
    INCLUDE (sml_godown_id, sml_lot_id, sml_signed_base_qty, sml_txn_type)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sml_is_deleted = false;

-- fn_sbl_rebuild and every as-on-date recomputation.
CREATE INDEX IF NOT EXISTS ix_sml_balance_scope
    ON stock.stock_ledger USING btree
    (sml_company_id, sml_branch_id, sml_godown_id, sml_item_id, sml_lot_id,
     sml_bucket, sml_doc_date)
    INCLUDE (sml_signed_base_qty, sml_cost_value)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sml_is_deleted = false;

-- Lot movement history: the recall trail, and where a batch went.
CREATE INDEX IF NOT EXISTS ix_sml_lot
    ON stock.stock_ledger USING btree (sml_lot_id, sml_doc_date DESC)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sml_is_deleted = false;

-- Drilling from a document into what it moved.
CREATE INDEX IF NOT EXISTS ix_sml_source_doc
    ON stock.stock_ledger USING btree
    (sml_src_module, sml_src_doc_type, sml_src_doc_id)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sml_is_deleted = false;

-- fn_sdd_rebuild: the sales-only slice, by day.
CREATE INDEX IF NOT EXISTS ix_sml_demand
    ON stock.stock_ledger USING btree
    (sml_company_id, sml_branch_id, sml_doc_date, sml_item_id)
    INCLUDE (sml_signed_base_qty, sml_doc_amount_wot, sml_cost_value_wot)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE sml_is_deleted = false
      AND sml_txn_type::text = ANY (ARRAY['SALE'::text, 'SALE_RETURN'::text]);


-- ═══════════════════════════════════════════════════════════════════════════
--  §6  stock_balance (sbl_) — what is on hand. A CACHE.
--
--  Every column here is derivable from stock_ledger. It exists so that the
--  billing screen's stock lookup is one index read instead of an aggregate
--  over a year of movements, and fn_sbl_rebuild() (§17) exists to prove that
--  claim on demand: run it and nothing should change.
--
--  ── Not partitioned, and no acc_year ─────────────────────────────────────
--  Stock does not reset on 1 April. A branch that holds forty units on 31
--  March holds forty units on 1 April, and a balance keyed by year would
--  need a carry-forward job that is exactly the sort of thing that runs at
--  2 a.m. and silently fails. This is the reasoning 09_acc_bill_balance.sql
--  gives for acc_bill_balance, applied to stock. Year-end figures come from
--  stock_valuation_snap (§12), which is what a frozen number is for.
--
--  ── One row per bucket ───────────────────────────────────────────────────
--  Saleable and damaged stock are both stock and must never be added up by
--  accident. Each bucket is its own row, so a report that wants only what
--  can be sold filters, and a report that wants everything does not.
--
--  ── The denormalised identity columns ────────────────────────────────────
--  sbl_batch_no, sbl_mrp, sbl_sale_price, sbl_expiry_date and sbl_supplier_id
--  are copies of stock_lot, written by the same trigger. They are what turn
--  "stock by MRP", "stock by supplier" and "what expires this month" into
--  single-table index scans instead of a join to stock_lot for every row of
--  a fifty-branch report. stock_lot owns them; nothing else may write them.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_balance
(
    sbl_id                   uuid           NOT NULL DEFAULT uuidv7(),
    sbl_company_id           uuid           NOT NULL,
    sbl_branch_id            uuid           NOT NULL,
    sbl_tenant_id            uuid,
    sbl_godown_id            uuid           NOT NULL,
    sbl_item_id              uuid           NOT NULL,
    sbl_lot_id               uuid           NOT NULL,
    sbl_base_uom_id          uuid           NOT NULL,
    sbl_bucket               character varying(20) NOT NULL DEFAULT 'SALEABLE',

    -- ── Accumulators. TRIGGER-MAINTAINED from stock_ledger. ──────────────
    -- Never written from application code. fn_sml_apply() owns them.
    sbl_in_qty               numeric(18,6)  NOT NULL DEFAULT 0,
    sbl_out_qty              numeric(18,6)  NOT NULL DEFAULT 0,
    sbl_free_in_qty          numeric(18,6)  NOT NULL DEFAULT 0,
    sbl_free_out_qty         numeric(18,6)  NOT NULL DEFAULT 0,

    -- Free goods are physical stock: they sit on the shelf and they get sold,
    -- so they count. They are kept in their own accumulators only so margin
    -- reporting can separate what was paid for from what was not.
    sbl_on_hand_qty          numeric(18,6) GENERATED ALWAYS AS
        (sbl_in_qty + sbl_free_in_qty - sbl_out_qty - sbl_free_out_qty) STORED,

    -- Promised to an order, still on the shelf. Owned by stock_reservation.
    sbl_reserved_qty         numeric(18,6)  NOT NULL DEFAULT 0,
    -- Sent from another branch, not yet received here. Owned by stock_transit.
    -- NOT part of on hand: it is not here yet.
    sbl_transit_in_qty       numeric(18,6)  NOT NULL DEFAULT 0,

    -- The arithmetic is repeated rather than referencing sbl_on_hand_qty,
    -- because PostgreSQL forbids a generated column reading another one.
    sbl_available_qty        numeric(18,6) GENERATED ALWAYS AS
        (sbl_in_qty + sbl_free_in_qty - sbl_out_qty - sbl_free_out_qty
         - sbl_reserved_qty) STORED,

    -- ── Value ────────────────────────────────────────────────────────────
    sbl_avg_cost_rate        numeric(18,6)  NOT NULL DEFAULT 0,
    sbl_avg_cost_rate_wot    numeric(18,6)  NOT NULL DEFAULT 0,
    sbl_stock_value          numeric(18,2)  NOT NULL DEFAULT 0,
    sbl_stock_value_wot      numeric(18,2)  NOT NULL DEFAULT 0,

    -- ── Ageing anchors, for THIS godown ──────────────────────────────────
    -- The lot's own slt_first_inward_date answers "how old is this stock in
    -- the chain". These answer "how long has it sat on this shelf".
    sbl_first_in_date        date,
    sbl_last_in_date         date,
    sbl_last_out_date        date,

    -- ── Identity cache. Owned by stock_lot; written by the same trigger. ──
    sbl_batch_no             character varying(100),
    sbl_mrp                  numeric(18,6),
    sbl_sale_price           numeric(18,6),
    sbl_expiry_date          date,
    sbl_supplier_id          uuid,

    sbl_row_version          bigint         NOT NULL DEFAULT 1,
    sbl_is_active            boolean NOT NULL DEFAULT true,
    sbl_is_deleted           boolean NOT NULL DEFAULT false,
    sbl_sync_date            timestamp with time zone,
    sbl_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    sbl_created_by           uuid,
    sbl_modified_on          timestamp with time zone,
    sbl_modified_by          uuid,

    CONSTRAINT pk_stock_balance PRIMARY KEY (sbl_id),

    CONSTRAINT fk_sbl_company FOREIGN KEY (sbl_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sbl_branch FOREIGN KEY (sbl_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sbl_godown FOREIGN KEY (sbl_godown_id)
        REFERENCES inventory.godown_locations (gdl_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sbl_item FOREIGN KEY (sbl_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sbl_lot FOREIGN KEY (sbl_lot_id)
        REFERENCES stock.stock_lot (slt_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sbl_base_uom FOREIGN KEY (sbl_base_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sbl_supplier FOREIGN KEY (sbl_supplier_id)
        REFERENCES purchase.suppliers (sup_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_sbl_bucket CHECK (
        sbl_bucket::text = ANY (ARRAY['SALEABLE'::text, 'DAMAGED'::text,
                                      'QUARANTINE'::text, 'EXPIRED'::text,
                                      'SAMPLE'::text])),
    CONSTRAINT ck_sbl_accum CHECK (
        sbl_in_qty >= 0 AND sbl_out_qty >= 0
        AND sbl_free_in_qty >= 0 AND sbl_free_out_qty >= 0),
    -- Reservations and transit are their own tables' business, but neither
    -- may go negative here.
    CONSTRAINT ck_sbl_reserved CHECK (sbl_reserved_qty >= 0),
    CONSTRAINT ck_sbl_transit CHECK (sbl_transit_in_qty >= 0)
);

-- ═══════════════════════════════════════════════════════════════════════════

--  Both are maintained on every movement, always, so stp_valuation_method

    sic_total_value_wot      numeric(18,2)  NOT NULL DEFAULT 0,

        ON UPDATE CASCADE ON DELETE RESTRICT,

-- ═══════════════════════════════════════════════════════════════════════════
--  §8  stock_voucher (svh_) — one document for every stock movement that is
--      not a sale.
--
--  Before this table there was no way to bring stock INTO the system at all:
--  no purchase, no GRN, no transfer, no adjustment exists anywhere in the
--  chain or in the live database. One generic document covers all of it:
--
--      OPENING          the balance a branch starts with
--      RECEIPT          goods in — from a supplier, pending a purchase module
--      ISSUE            goods out — consumption, samples, internal use
--      ADJUSTMENT       a correction, with a reason
--      TRANSFER_OUT     goods leaving for another branch or godown
--      TRANSFER_IN      goods arriving from one
--      DAMAGE           moved to the DAMAGED bucket, or written off
--      EXPIRY_WRITEOFF  expired stock leaving the saleable bucket
--      PHYSICAL         a count, posting only the difference
--      REPACK_OUT/IN    a bulk unit broken into retail units
--
--  ── Why not a table per document type ────────────────────────────────────
--  Because they differ in three columns and share forty. The legacy system
--  had opening_stock_header, physical_stock_header and tmp_brtrfs, each with
--  its own line table and its own subtly different batch columns, and every
--  report had to UNION them. A voucher_type column and one CHECK is the whole
--  difference.
--
--  ── When purchase arrives ────────────────────────────────────────────────
--  A real purchase/GRN module posts into stock_ledger through the same
--  (src_module, src_doc_type, src_doc_id) triple that this voucher uses. It
--  needs no change here and no migration: RECEIPT vouchers raised in the
--  meantime stay valid history.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_voucher
(
    svh_id                   uuid           NOT NULL DEFAULT uuidv7(),
    svh_company_id           uuid           NOT NULL,
    svh_branch_id            uuid           NOT NULL,
    svh_tenant_id            uuid,
    svh_acc_year             character(9)   NOT NULL,

    -- The device IS the counter; there is no separate counter id. Same rule
    -- as sale_order (06). A stock voucher raised offline on a warehouse
    -- tablet must number itself without asking the server.
    svh_device_id            uuid           NOT NULL,
    svh_session_id           uuid,

    svh_voucher_type         character varying(30)  NOT NULL,
    -- Per company/branch/year/DEVICE. The printed refno embeds the device
    -- series and is unique per branch/year without it.
    svh_slno                 bigint         NOT NULL,
    svh_refno                character varying(100) NOT NULL,
    svh_usr_refno            character varying(100),
    svh_doc_date             date           NOT NULL,
    svh_doc_datetime         timestamp with time zone NOT NULL DEFAULT now(),

    -- ── Where stock came from and went ───────────────────────────────────
    -- A RECEIPT fills to_godown only; an ISSUE fills from_godown only; a
    -- TRANSFER fills both, and to_branch when it leaves the store.
    svh_from_godown_id       uuid,
    svh_to_godown_id         uuid,
    svh_to_branch_id         uuid,

    svh_supplier_id          uuid,          -- RECEIPT / purchase-side
    svh_party_ref            character varying(100),
    svh_reason_id            uuid,

    -- TRANSFER_IN points back at its TRANSFER_OUT; PHYSICAL points at the
    -- ADJUSTMENT it generated. Composite, because it can cross a year end.
    svh_link_src_module      character varying(20),
    svh_link_src_doc_type    character varying(30),
    svh_link_src_doc_id      uuid,
    svh_link_src_acc_year    character(9),

    -- ── Totals. Caches of stock_voucher_item; the line table owns them. ───
    svh_line_count           integer        NOT NULL DEFAULT 0,
    svh_total_qty            numeric(18,6)  NOT NULL DEFAULT 0,
    svh_total_value          numeric(18,2)  NOT NULL DEFAULT 0,
    svh_total_value_wot      numeric(18,2)  NOT NULL DEFAULT 0,

    -- ── Lifecycle ────────────────────────────────────────────────────────
    -- Nothing reaches stock_ledger until POSTED. IN_TRANSIT is a
    -- TRANSFER_OUT that has left and not yet been received.
    svh_status               character varying(20) NOT NULL DEFAULT 'DRAFT',
    svh_posted_on            timestamp with time zone,
    svh_posted_by            uuid,
    svh_approved_on          timestamp with time zone,
    svh_approved_by          uuid,
    svh_cancelled_on         timestamp with time zone,
    svh_cancelled_by         uuid,
    svh_cancel_reason        character varying(250),
    svh_version_no           integer        NOT NULL DEFAULT 1,

    -- ── PHYSICAL only ────────────────────────────────────────────────────

-- ═══════════════════════════════════════════════════════════════════════════
--  §10  stock_reservation (srv_) — quantity promised but still on the shelf.
--
--  A sale order taken at one till against stock a second till is about to
--  sell. Counting open orders out of sale_order_item cannot work in a chain:
--  the order that committed the last unit may have been raised offline in
--  another branch and not yet synced, and soi_pending_qty is a cache of the
--  ORDER's state, not of the stock's.
--
--  Reserved stock is on hand — it is physically there — but it is not
--  available. That distinction is why stock_balance has both columns.
--
--  A reservation expires. Without srv_expires_on a quoted order abandoned in
--  March holds stock hostage for ever.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_reservation
(
    srv_id                   uuid           NOT NULL DEFAULT uuidv7(),
    srv_company_id           uuid           NOT NULL,
    srv_branch_id            uuid           NOT NULL,
    srv_tenant_id            uuid,
    srv_acc_year             character(9)   NOT NULL,

    srv_godown_id            uuid           NOT NULL,
    srv_item_id              uuid           NOT NULL,
    srv_lot_id               uuid           NOT NULL,
    srv_base_uom_id          uuid           NOT NULL,
    srv_bucket               character varying(20) NOT NULL DEFAULT 'SALEABLE',

    -- What is holding the stock.
    srv_src_module           character varying(20)  NOT NULL,
    srv_src_doc_type         character varying(30)  NOT NULL,
    srv_src_doc_id           uuid           NOT NULL,
    srv_src_acc_year         character(9),
    srv_src_refno            character varying(100),
    srv_line_no              integer        NOT NULL DEFAULT 1,

    srv_reserved_qty         numeric(18,6)  NOT NULL DEFAULT 0,
    srv_consumed_qty         numeric(18,6)  NOT NULL DEFAULT 0,
    srv_released_qty         numeric(18,6)  NOT NULL DEFAULT 0,
    -- What is still holding stock. The trigger sums this into
    -- stock_balance.sbl_reserved_qty.
    srv_open_qty             numeric(18,6) GENERATED ALWAYS AS
        (srv_reserved_qty - srv_consumed_qty - srv_released_qty) STORED,

    srv_reserved_on          timestamp with time zone NOT NULL DEFAULT now(),
    srv_expires_on           timestamp with time zone,
    srv_status               character varying(20) NOT NULL DEFAULT 'OPEN',
    srv_closed_on            timestamp with time zone,
    srv_close_reason         character varying(250),

    srv_is_deleted           boolean NOT NULL DEFAULT false,
    srv_sync_date            timestamp with time zone,
    srv_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    srv_created_by           uuid,
    srv_modified_on          timestamp with time zone,
    srv_modified_by          uuid,

    CONSTRAINT pk_stock_reservation PRIMARY KEY (srv_id, srv_acc_year),

    CONSTRAINT fk_srv_company FOREIGN KEY (srv_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srv_branch FOREIGN KEY (srv_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srv_godown FOREIGN KEY (srv_godown_id)
        REFERENCES inventory.godown_locations (gdl_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srv_item FOREIGN KEY (srv_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srv_lot FOREIGN KEY (srv_lot_id)
        REFERENCES stock.stock_lot (slt_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srv_base_uom FOREIGN KEY (srv_base_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_srv_acc_year CHECK (
        srv_acc_year ~ '^[0-9]{4}-[0-9]{4}$'
        AND RIGHT(srv_acc_year, 4)::int = LEFT(srv_acc_year, 4)::int + 1),
    CONSTRAINT ck_srv_status CHECK (
        srv_status::text = ANY (ARRAY['OPEN'::text, 'PARTIAL'::text,
                                      'CONSUMED'::text, 'RELEASED'::text,
                                      'EXPIRED'::text])),
    CONSTRAINT ck_srv_bucket CHECK (
        srv_bucket::text = ANY (ARRAY['SALEABLE'::text, 'DAMAGED'::text,
                                      'QUARANTINE'::text, 'EXPIRED'::text,
                                      'SAMPLE'::text])),
    CONSTRAINT ck_srv_qty CHECK (
        srv_reserved_qty > 0 AND srv_consumed_qty >= 0 AND srv_released_qty >= 0),
    -- More cannot be consumed and released than was ever reserved.
    CONSTRAINT ck_srv_settled CHECK (
        srv_consumed_qty + srv_released_qty <= srv_reserved_qty)
) PARTITION BY LIST (srv_acc_year);

-- ═══════════════════════════════════════════════════════════════════════════
--  §11  stock_transit (stt_) — sent from A, not yet arrived at B.
--
--  A chain moves stock between stores constantly, and a transfer is not
--  instantaneous. Between the lorry leaving and the goods being checked in,
--  the stock is out of A's balance and not yet in B's — and if nothing
--  records it, it is simply missing, which is how a chain loses stock on
--  paper and then finds it on the floor.
--
--  ── Not partitioned ──────────────────────────────────────────────────────
--  A transfer despatched on 29 March and received on 2 April spans two
--  accounting years. Partitioning it by year would put the two halves of one
--  fact in two partitions and make "what is in transit right now" a query
--  across years. Same reasoning as stock_balance and acc_bill_balance.
--
--  ── Short receipts are the point ─────────────────────────────────────────
--  stt_short_qty is what left and never arrived. It is generated, not
--  entered, so it cannot be quietly rounded away, and it is the number a
--  transfer-loss report is built on.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_transit
(
    stt_id                   uuid           NOT NULL DEFAULT uuidv7(),
    stt_company_id           uuid           NOT NULL,
    stt_tenant_id            uuid,

    stt_from_branch_id       uuid           NOT NULL,
    stt_from_godown_id       uuid           NOT NULL,
    stt_to_branch_id         uuid           NOT NULL,
    stt_to_godown_id         uuid           NOT NULL,

    stt_item_id              uuid           NOT NULL,
    stt_lot_id               uuid           NOT NULL,
    stt_base_uom_id          uuid           NOT NULL,
    stt_bucket               character varying(20) NOT NULL DEFAULT 'SALEABLE',

    -- Both halves of the movement, each with its own year.
    stt_out_voucher_id       uuid           NOT NULL,
    stt_out_acc_year         character(9)   NOT NULL,
    stt_out_refno            character varying(100),
    stt_in_voucher_id        uuid,
    stt_in_acc_year          character(9),
    stt_in_refno             character varying(100),

    stt_sent_qty             numeric(18,6)  NOT NULL DEFAULT 0,
    stt_received_qty         numeric(18,6)  NOT NULL DEFAULT 0,
    stt_damage_qty           numeric(18,6)  NOT NULL DEFAULT 0,
    -- What left and never arrived. Generated so it cannot be edited.
    stt_short_qty            numeric(18,6) GENERATED ALWAYS AS
        (stt_sent_qty - stt_received_qty - stt_damage_qty) STORED,

    stt_cost_rate            numeric(18,6)  NOT NULL DEFAULT 0,
    stt_transit_value        numeric(18,2)  NOT NULL DEFAULT 0,

    stt_sent_on              timestamp with time zone NOT NULL DEFAULT now(),
    stt_expected_on          date,
    stt_received_on          timestamp with time zone,
    stt_status               character varying(20) NOT NULL DEFAULT 'IN_TRANSIT',
    stt_lr_no                character varying(50),
    stt_vehicle_no           character varying(30),

    stt_remarks              character varying(250),
    stt_is_deleted           boolean NOT NULL DEFAULT false,
    stt_sync_date            timestamp with time zone,
    stt_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    stt_created_by           uuid,
    stt_modified_on          timestamp with time zone,
    stt_modified_by          uuid,

    CONSTRAINT pk_stock_transit PRIMARY KEY (stt_id),

    CONSTRAINT fk_stt_company FOREIGN KEY (stt_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_stt_from_branch FOREIGN KEY (stt_from_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_stt_to_branch FOREIGN KEY (stt_to_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE

        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_stt_status CHECK (
        stt_status::text = ANY (ARRAY['IN_TRANSIT'::text, 'PARTIAL'::text,
                                      'RECEIVED'::text, 'CANCELLED'::text])),
    CONSTRAINT ck_stt_bucket CHECK (

-- ═══════════════════════════════════════════════════════════════════════════
--  §12  stock_valuation_snap (svs_) — closing stock, frozen.
--
--  "Stock value as on 31 March" must give the same answer in April and in
--  October, and it must give it in seconds for fifty branches. Replaying the
--  ledger does neither: it is slow, and a back-dated correction posted in
--  June silently changes March's audited figure.
--
--  A snapshot is taken at period close and never touched again. As-on-date
--  for any other day is the nearest snapshot plus the ledger delta since —
--  bounded work, not a full replay (see fn_stock_asof(), §17).
--
--  Three valuations are stored, not one. At cost is what the books want, at
--  MRP is what the shop floor counts, at selling price is what a retailer
--  means by "stock worth". Deriving the second and third later is impossible
--  once a price list changes.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_valuation_snap
(
    svs_id                   uuid           NOT NULL DEFAULT uuidv7(),
    svs_company_id           uuid           NOT NULL,
    svs_branch_id            uuid           NOT NULL,
    svs_tenant_id            uuid,
    -- A scope column, not a partition key: a snapshot is a frozen fact that
    -- gets read for years.
    svs_acc_year             character(9)   NOT NULL,

    svs_godown_id            uuid           NOT NULL,
    svs_item_id              uuid           NOT NULL,
    svs_lot_id               uuid           NOT NULL,
    svs_base_uom_id          uuid           NOT NULL,
    svs_bucket               character varying(20) NOT NULL DEFAULT 'SALEABLE',

    svs_snap_type            character varying(20) NOT NULL DEFAULT 'MONTH',
    svs_snap_date            date           NOT NULL,

    svs_qty                  numeric(18,6)  NOT NULL DEFAULT 0,
    svs_avg_cost_rate        numeric(18,6)  NOT NULL DEFAULT 0,
    svs_avg_cost_rate_wot    numeric(18,6)  NOT NULL DEFAULT 0,
    svs_value_at_cost        numeric(18,2)  NOT NULL DEFAULT 0,
    svs_value_at_cost_wot    numeric(18,2)  NOT NULL DEFAULT 0,
    svs_value_at_mrp         numeric(18,2)  NOT NULL DEFAULT 0,
    svs_value_at_sp          numeric(18,2)  NOT NULL DEFAULT 0,

    -- Copied from the lot at freeze time; the lot may be closed by the time
    -- anybody reads this.
    svs_batch_no             character varying(100),
    svs_mrp                  numeric(18,6),
    svs_expiry_date          date,
    svs_supplier_id          uuid,
    -- How old the stock was on the snapshot date. Stored because it cannot
    -- be recomputed for a lot that has since been consumed.
    svs_age_days             integer,

    svs_frozen_on            timestamp with time zone NOT NULL DEFAULT now(),
    svs_frozen_by            uuid,
    svs_is_deleted           boolean NOT NULL DEFAULT false,
    svs_sync_date            timestamp with time zone,
    svs_created_on           timestamp with time zone NOT NULL DEFAULT now(),

    CONSTRAINT pk_stock_valuation_snap PRIMARY KEY (svs_id),

    CONSTRAINT fk_svs_company FOREIGN KEY (svs_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_svs_branch FOREIGN KEY (svs_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_svs_godown FOREIGN KEY (svs_godown_id)
        REFERENCES inventory.godown_locations (gdl_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_svs_item FOREIGN KEY (svs_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_svs_lot FOREIGN KEY (svs_lot_id)
        REFERENCES stock.stock_lot (slt_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_svs_snap_type CHECK (
        svs_snap_type::text = ANY (ARRAY['DAY'::text, 'MONTH'::text,
                                         'YEAR_OPEN'::text, 'YEAR_CLOSE'::text])),
    CONSTRAINT ck_svs_bucket CHECK (
        svs_bucket::text = ANY (ARRAY['SALEABLE'::text, 'DAMAGED'::text,
                                      'QUARANTINE'::text, 'EXPIRED'::text,
                                      'SAMPLE'::text]))
);

ALTER TABLE IF EXISTS stock.stock_valuation_snap OWNER to postgres;

    ON stock.stock_valuation_snap USING btree
    (svs_company_id, svs_branch_id, svs_godown_id, svs_item_id, svs_lot_id,
     svs_bucket, svs_snap_type, svs_snap_date)

CREATE INDEX IF NOT EXISTS ix_svs_asof

CREATE INDEX IF NOT EXISTS ix_svs_report

-- ═══════════════════════════════════════════════════════════════════════════
--  §13  stock_demand_daily (sdd_) — what actually sold, per branch, per day.
--
--  The input every forecast needs and no transactional table can serve.
--  Aggregating a year of sale_bill_item across fifty branches on every run of
--  a replenishment job is not a plan; this is the pre-aggregate, rebuilt by
--  fn_sdd_rebuild() from the ledger, which means it can always be recomputed
--  and never has to be trusted blindly.
--
--  ── sdd_stockout_flag is the column that makes forecasts honest ──────────
--  If an item was out of stock on Tuesday it sold zero on Tuesday, and a
--  model that reads that as "demand was zero" will under-forecast the fastest
--  movers for ever and keep them out of stock. Censored demand has to be
--  MARKED at the point where it is still knowable — afterwards, a zero is
--  indistinguishable from a zero.
--
--  sdd_promo_qty exists for the same reason in the other direction: a week of
--  buy-one-get-one is not the baseline, and a model that treats it as one
--  will over-order for the month after.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_demand_daily
(
    sdd_id                   uuid           NOT NULL DEFAULT uuidv7(),
    sdd_company_id           uuid           NOT NULL,
    sdd_branch_id            uuid           NOT NULL,
    sdd_tenant_id            uuid,
    sdd_item_id              uuid           NOT NULL,
    sdd_base_uom_id          uuid           NOT NULL,
    sdd_demand_date          date           NOT NULL,
    -- Denormalised so a weekday/seasonality model does not compute it a
    -- million times. 0 = Sunday, matching EXTRACT(dow).
    sdd_day_of_week          smallint       NOT NULL DEFAULT 0,

    sdd_sold_qty             numeric(18,6)  NOT NULL DEFAULT 0,
    sdd_free_qty             numeric(18,6)  NOT NULL DEFAULT 0,
    sdd_return_qty           numeric(18,6)  NOT NULL DEFAULT 0,
    sdd_net_qty              numeric(18,6) GENERATED ALWAYS AS
        (sdd_sold_qty + sdd_free_qty - sdd_return_qty) STORED,
    -- Sold while a promotion was running: real sales, but not the baseline.
    sdd_promo_qty            numeric(18,6)  NOT NULL DEFAULT 0,

    sdd_bill_count           integer        NOT NULL DEFAULT 0,
    sdd_line_count           integer        NOT NULL DEFAULT 0,
    sdd_customer_count       integer        NOT NULL DEFAULT 0,

    sdd_revenue_wot          numeric(18,2)  NOT NULL DEFAULT 0,
    sdd_cogs_wot             numeric(18,2)  NOT NULL DEFAULT 0,
    sdd_margin_wot           numeric(18,2) GENERATED ALWAYS AS
        (sdd_revenue_wot - sdd_cogs_wot) STORED,

    -- ── Truthfulness flags ───────────────────────────────────────────────
    -- On hand hit zero at some point that day: demand was censored, the
    -- figure above is a floor and not a measurement.
    sdd_stockout_flag        boolean        NOT NULL DEFAULT false,
    sdd_stockout_hours       numeric(9,3)   NOT NULL DEFAULT 0,
    -- The branch was shut. Excluded from a moving average, not read as zero.
    sdd_closed_flag          boolean        NOT NULL DEFAULT false,
    sdd_open_qty_start       numeric(18,6)  NOT NULL DEFAULT 0,
    sdd_close_qty_end        numeric(18,6)  NOT NULL DEFAULT 0,

    sdd_rebuilt_on           timestamp with time zone NOT NULL DEFAULT now(),
    sdd_is_deleted           boolean NOT NULL DEFAULT false,
    sdd_sync_date            timestamp with time zone,
    sdd_created_on           timestamp with time zone NOT NULL DEFAULT now(),

    CONSTRAINT pk_stock_demand_daily PRIMARY KEY (sdd_id),

    CONSTRAINT fk_sdd_company FOREIGN KEY (sdd_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sdd_branch FOREIGN KEY (sdd_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sdd_item FOREIGN KEY (sdd_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sdd_base_uom FOREIGN KEY (sdd_base_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_sdd_dow CHECK (sdd_day_of_week BETWEEN 0 AND 6),
    CONSTRAINT ck_sdd_stockout_hours CHECK (
        sdd_stockout_hours >= 0 AND sdd_stockout_hours <= 24),
    CONSTRAINT ck_sdd_counts CHECK (
        sdd_bill_count >= 0 AND sdd_line_count >= 0 AND sdd_customer_count >= 0)
);

ALTER TABLE IF EXISTS stock.stock_demand_daily OWNER to postgres;

CREATE UNIQUE INDEX IF NOT EXISTS ux_sdd_scope
    ON stock.stock_demand_daily USING btree
    (sdd_company_id, sdd_branch_id, sdd_item_id, sdd_demand_date)
    WITH (fillfactor=90, deduplicate_items=True)
    WHERE sdd_is_deleted = false;

-- The forecasting read: one item, one branch, a window of days, in order.
CREATE INDEX IF NOT EXISTS ix_sdd_series
    ON stock.stock_demand_daily USING btree
    (sdd_company_id, sdd_branch_id, sdd_item_id, sdd_demand_date DESC)
    INCLUDE (sdd_net_qty, sdd_stockout_flag, sdd_promo_qty)
    WITH (fillfactor=90, deduplicate_items=True)
    WHERE sdd_is_deleted = false;

-- Chain-wide demand for one item across every branch on a date range: the
-- head-office allocation question.
CREATE INDEX IF NOT EXISTS ix_sdd_chain
    ON stock.stock_demand_daily USING btree
    (sdd_company_id, sdd_item_id, sdd_demand_date)
    INCLUDE (sdd_branch_id, sdd_net_qty)
    WITH (fillfactor=90, deduplicate_items=True)
    WHERE sdd_is_deleted = false;


-- ═══════════════════════════════════════════════════════════════════════════
--  §14  stock_reorder_policy (srp_) — min, max, lead time, safety.
--
--  The item master already has a reorder grid keyed on (branch, godown, unit),
--  and it is left alone: it is Prisma's, it holds only four numbers, and it
--  has no concept of lead time, which is the single most important input to
--  a reorder point. This table is the replenishment settings the forecasting
--  side needs, and it can be populated from the old grid without altering it.
--
--  ── Why the standard deviation of lead time ──────────────────────────────
--  Safety stock is not a percentage of demand, it is a buffer against
--  variability — in demand AND in how long the supplier takes. A supplier who
--  averages 7 days but ranges 3 to 21 needs far more cover than one who is
--  reliably 10. Without srp_lead_time_sd_days the safety stock is a guess
--  dressed as arithmetic.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_reorder_policy
(
    srp_id                   uuid           NOT NULL DEFAULT uuidv7(),
    srp_company_id           uuid           NOT NULL,
    srp_branch_id            uuid           NOT NULL,
    -- NULL = the whole branch, however many godowns it operates.
    srp_godown_id            uuid,
    srp_item_id              uuid           NOT NULL,
    srp_uom_id               uuid           NOT NULL,

    srp_min_qty              numeric(18,6)  NOT NULL DEFAULT 0,
    srp_max_qty              numeric(18,6)  NOT NULL DEFAULT 0,
    srp_reorder_level        numeric(18,6)  NOT NULL DEFAULT 0,
    srp_reorder_qty          numeric(18,6)  NOT NULL DEFAULT 0,
    srp_safety_stock         numeric(18,6)  NOT NULL DEFAULT 0,

    srp_lead_time_days       numeric(9,3)   NOT NULL DEFAULT 0,
    srp_lead_time_sd_days    numeric(9,3)   NOT NULL DEFAULT 0,
    srp_review_period_days   integer        NOT NULL DEFAULT 7,
    -- The probability of not stocking out during lead time that the safety
    -- stock is sized for. 95.000 is the usual retail answer.
    srp_service_level_perc   numeric(9,3)   NOT NULL DEFAULT 95,

    srp_moq                  numeric(18,6)  NOT NULL DEFAULT 0,
    srp_pack_multiple        numeric(18,6)  NOT NULL DEFAULT 1,
    srp_shelf_capacity_qty   numeric(18,6)  NOT NULL DEFAULT 0,
    srp_preferred_supplier_id uuid,

    -- MANUAL means a human set these and a job must not overwrite them.
    srp_source               character varying(20) NOT NULL DEFAULT 'MANUAL',
    srp_computed_on          timestamp with time zone,
    srp_auto_replenish       boolean        NOT NULL DEFAULT false,

    srp_remarks              character varying(250),
    srp_is_active            boolean NOT NULL DEFAULT true,
    srp_is_deleted           boolean NOT NULL DEFAULT false,
    srp_sync_date            timestamp with time zone,
    srp_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    srp_created_by           uuid,
    srp_modified_on          timestamp with time zone,
    srp_modified_by          uuid,

    CONSTRAINT pk_stock_reorder_policy PRIMARY KEY (srp_id),

    CONSTRAINT fk_srp_company FOREIGN KEY (srp_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srp_branch FOREIGN KEY (srp_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srp_godown FOREIGN KEY (srp_godown_id)
        REFERENCES inventory.godown_locations (gdl_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srp_item FOREIGN KEY (srp_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srp_uom FOREIGN KEY (srp_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_srp_supplier FOREIGN KEY (srp_preferred_supplier_id)
        REFERENCES purchase.suppliers (sup_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_srp_source CHECK (
        srp_source::text = ANY (ARRAY['MANUAL'::text, 'COMPUTED'::text])),
    CONSTRAINT ck_srp_levels CHECK (
        srp_min_qty >= 0 AND srp_safety_stock >= 0
        AND (srp_max_qty = 0 OR srp_max_qty >= srp_min_qty)),
    CONSTRAINT ck_srp_lead_time CHECK (
        srp_lead_time_days >= 0 AND srp_lead_time_sd_days >= 0),
    CONSTRAINT ck_srp_service_level CHECK (
        srp_service_level_perc > 0 AND srp_service_level_perc < 100),
    CONSTRAINT ck_srp_pack CHECK (srp_pack_multiple > 0),
    CONSTRAINT ck_srp_review CHECK (srp_review_period_days > 0)
);

ALTER TABLE IF EXISTS stock.stock_reorder_policy OWNER to postgres;

-- One policy per item per location. The nil-uuid COALESCE gives the

    ON stock.stock_reorder_policy USING btree

     (COALESCE(srp_godown_id, '00000000-0000-0000-0000-000000000000'::uuid)),

CREATE INDEX IF NOT EXISTS ix_srp_auto
    ON stock.stock_reorder_policy USING btree (srp_company_id, srp_branch_id)

      AND srp_is_deleted = false;


-- ═══════════════════════════════════════════════════════════════════════════
--  §15  stock_forecast (sfc_) — what we expect to sell, and what to order.
--
--  ── The maths is NOT in this file, and that is the design ────────────────
--  A forecasting model written in PL/pgSQL cannot be changed without a
--  migration, cannot be back-tested against last year without running last
--  year, and cannot be swapped when the retailer discovers that Croston fits
--  their slow movers better than exponential smoothing. It WILL be changed.
--
--  So the schema holds the three things a model needs to be useful and does
--  not hold the model: the inputs (stock_demand_daily), the settings
--  (stock_reorder_policy) and the outputs (this table). A job, the API layer,
--  or a notebook writes rows here; every screen reads them the same way
--  regardless of what produced them.
--
--  ── Why the error columns are not optional ───────────────────────────────
--  A forecast without a measured error is a number somebody made up. MAPE,
--  RMSE and bias are written by the same run that writes the forecast,
--  computed against the period just past, so a buyer can see that this item's
--  model has been wrong by 40% for three months and stop trusting it. Bias
--  separately from error, because consistently over-ordering and randomly
--  missing are different diseases with different cures.
--
--  ── One row per (item, branch, run date, horizon, method) ────────────────
--  Keeping the method in the key means two models can run side by side and be
--  compared on the same history — which is the only honest way to choose one.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_forecast
(
    sfc_id                   uuid           NOT NULL DEFAULT uuidv7(),
    sfc_company_id           uuid           NOT NULL,
    sfc_branch_id            uuid           NOT NULL,
    sfc_tenant_id            uuid,
    sfc_item_id              uuid           NOT NULL,
    sfc_base_uom_id          uuid           NOT NULL,

    -- The day the forecast was made for (not the day it was computed).
    sfc_forecast_date        date           NOT NULL,
    sfc_horizon_days         integer        NOT NULL DEFAULT 30,
    sfc_method               character varying(30) NOT NULL DEFAULT 'MOVING_AVG',

    -- ── The forecast ─────────────────────────────────────────────────────
    sfc_forecast_qty         numeric(18,6)  NOT NULL DEFAULT 0,
    sfc_forecast_lower       numeric(18,6),
    sfc_forecast_upper       numeric(18,6),
    sfc_confidence_perc      numeric(9,3),
    sfc_daily_rate           numeric(18,6)  NOT NULL DEFAULT 0,

    -- ── What the model saw ───────────────────────────────────────────────
    sfc_history_days         integer        NOT NULL DEFAULT 0,
    sfc_stockout_days        integer        NOT NULL DEFAULT 0,
    sfc_trend_slope          numeric(18,6),
    sfc_seasonality_index    numeric(9,4),
    -- Alpha/beta/gamma, window lengths, whatever the method needs. Kept as
    -- jsonb so a new method costs no column.
    sfc_model_params         jsonb,

    -- ── How wrong it has been ────────────────────────────────────────────
    sfc_mape                 numeric(9,3),
    sfc_rmse                 numeric(18,6),
    sfc_bias                 numeric(18,6),
    sfc_backtest_days        integer,

    -- ── What to do about it ──────────────────────────────────────────────
    sfc_on_hand_qty          numeric(18,6)  NOT NULL DEFAULT 0,
    -- Ordered or in transit: stock already coming, which must be netted off
    -- before suggesting more. Forgetting this is how a chain double-orders.
    sfc_pipeline_qty         numeric(18,6)  NOT NULL DEFAULT 0,
    sfc_safety_stock         numeric(18,6)  NOT NULL DEFAULT 0,
    sfc_reorder_point        numeric(18,6)  NOT NULL DEFAULT 0,
    sfc_suggested_order_qty  numeric(18,6)  NOT NULL DEFAULT 0,
    sfc_days_of_cover        numeric(9,2),
    sfc_expected_stockout_on date,
    sfc_preferred_supplier_id uuid,

    -- Set when a buyer overrides the suggestion, so the next back-test knows
    -- the order it sees was not the one the model asked for.
    sfc_accepted_qty         numeric(18,6),
    sfc_accepted_by          uuid,
    sfc_accepted_on          timestamp with time zone,

    sfc_computed_on          timestamp with time zone NOT NULL DEFAULT now(),
    sfc_computed_by          character varying(50),
    sfc_is_deleted           boolean NOT NULL DEFAULT false,
    sfc_sync_date            timestamp with time zone,
    sfc_created_on           timestamp with time zone NOT NULL DEFAULT now(),

    CONSTRAINT pk_stock_forecast PRIMARY KEY (sfc_id),

    CONSTRAINT fk_sfc_company FOREIGN KEY (sfc_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sfc_branch FOREIGN KEY (sfc_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sfc_item FOREIGN KEY (sfc_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sfc_base_uom FOREIGN KEY (sfc_base_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_sfc_supplier FOREIGN KEY (sfc_preferred_supplier_id)
        REFERENCES purchase.suppliers (sup_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_sfc_method CHECK (
        sfc_method::text = ANY (ARRAY[
            'MOVING_AVG'::text, 'WMA'::text, 'SES'::text, 'HOLT'::text,
            'HOLT_WINTERS'::text, 'CROSTON'::text, 'REGRESSION'::text,
            'MANUAL'::text, 'EXTERNAL'::text])),
    CONSTRAINT ck_sfc_horizon CHECK (sfc_horizon_days > 0),
    CONSTRAINT ck_sfc_band CHECK (
        sfc_forecast_lower IS NULL OR sfc_forecast_upper IS NULL
        OR sfc_forecast_upper >= sfc_forecast_lower),
    CONSTRAINT ck_sfc_confidence CHECK (
        sfc_confidence_perc IS NULL
        OR (sfc_confidence_perc > 0 AND sfc_confidence_perc <= 100)),
    CONSTRAINT ck_sfc_qty CHECK (
        sfc_forecast_qty >= 0 AND sfc_safety_stock >= 0
        AND sfc_suggested_order_qty >= 0),
    CONSTRAINT ck_sfc_stockout_days CHECK (
        sfc_stockout_days >= 0 AND sfc_stockout_days <= sfc_history_days),
    CONSTRAINT ck_sfc_accepted CHECK (
        (sfc_accepted_qty IS NULL AND sfc_accepted_on IS NULL)
     OR (sfc_accepted_qty IS NOT NULL AND sfc_accepted_on IS NOT NULL))
);

-- ═══════════════════════════════════════════════════════════════════════════
--  §16  stock_movement_class (smc_) — fast, slow, dead.
--
--  Three orthogonal classifications, because they answer different questions
--  and a single "category A" hides two of them:
--
--      ABC  by VALUE      — where the money is. 20% of items, 80% of value.
--      XYZ  by VARIABILITY— how predictable. An X item can be forecast; a Z
--                           item can only be buffered.
--      FSN  by FREQUENCY  — how often it moves at all. Fast, Slow, Non-moving.
--
--  An A-Z item — high value, wildly unpredictable — is the one that ties up
--  capital and still stocks out, and it is invisible to any single ranking.
--
--  Computed per period by the same job that writes forecasts, and stored
--  rather than derived because the classification of March must not change
--  when April's sales arrive.
-- ═══════════════════════════════════════════════════════════════════════════
CREATE TABLE IF NOT EXISTS stock.stock_movement_class
(
    smc_id                   uuid           NOT NULL DEFAULT uuidv7(),
    smc_company_id           uuid           NOT NULL,
    smc_branch_id            uuid           NOT NULL,
    smc_tenant_id            uuid,
    smc_item_id              uuid           NOT NULL,

    smc_period_from          date           NOT NULL,
    smc_period_to            date           NOT NULL,

    smc_abc_class            character(1),
    smc_xyz_class            character(1),
    smc_fsn_class            character(1),

    smc_velocity_qty_per_day numeric(18,6)  NOT NULL DEFAULT 0,
    smc_movement_count       integer        NOT NULL DEFAULT 0,
    smc_days_since_last_sale integer,
    smc_days_of_cover        numeric(9,2),
    -- Cost of goods sold in the period over average stock held: how many
    -- times the shelf turned over. The number a retailer actually manages by.
    smc_turn_ratio           numeric(9,3),
    smc_demand_cv            numeric(9,4),   -- coefficient of variation → XYZ

    smc_period_qty           numeric(18,6)  NOT NULL DEFAULT 0,
    smc_period_value_wot     numeric(18,2)  NOT NULL DEFAULT 0,
    smc_avg_stock_qty        numeric(18,6)  NOT NULL DEFAULT 0,
    smc_avg_stock_value      numeric(18,2)  NOT NULL DEFAULT 0,
    smc_closing_qty          numeric(18,6)  NOT NULL DEFAULT 0,
    smc_closing_value        numeric(18,2)  NOT NULL DEFAULT 0,

    smc_rank_in_branch       integer,
    smc_cum_value_perc       numeric(9,3),

    -- Held, not sold, for long enough to be a decision. The date matters:
    -- "dead since November" is actionable, "dead" is not.
    smc_dead_stock_flag      boolean        NOT NULL DEFAULT false,
    smc_dead_since_date      date,
    smc_dead_value           numeric(18,2)  NOT NULL DEFAULT 0,

    smc_computed_on          timestamp with time zone NOT NULL DEFAULT now(),
    smc_is_deleted           boolean NOT NULL DEFAULT false,
    smc_sync_date            timestamp with time zone,
    smc_created_on           timestamp with time zone NOT NULL DEFAULT now(),

    CONSTRAINT pk_stock_movement_class PRIMARY KEY (smc_id),

    CONSTRAINT fk_smc_company FOREIGN KEY (smc_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_smc_branch FOREIGN KEY (smc_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_smc_item FOREIGN KEY (smc_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_smc_abc CHECK (
        smc_abc_class IS NULL OR smc_abc_class = ANY (ARRAY['A', 'B', 'C'])),
    CONSTRAINT ck_smc_xyz CHECK (
        smc_xyz_class IS NULL OR smc_xyz_class = ANY (ARRAY['X', 'Y', 'Z'])),
    CONSTRAINT ck_smc_fsn CHECK (
        smc_fsn_class IS NULL OR smc_fsn_class = ANY (ARRAY['F', 'S', 'N'])),
    CONSTRAINT ck_smc_period CHECK (smc_period_to >= smc_period_from),
    CONSTRAINT ck_smc_dead CHECK (
        smc_dead_stock_flag = false OR smc_dead_since_date IS NOT NULL)
);

ALTER TABLE IF EXISTS stock.stock_movement_class OWNER to postgres;

CREATE UNIQUE INDEX IF NOT EXISTS ux_smc_scope
    ON stock.stock_movement_class USING btree
    (smc_company_id, smc_branch_id, smc_item_id, smc_period_from, smc_period_to)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE smc_is_deleted = false;

-- The classification report, and the A-Z drilldown.
CREATE INDEX IF NOT EXISTS ix_smc_class
    ON stock.stock_movement_class USING btree
    (smc_company_id, smc_branch_id, smc_period_to DESC,
     smc_abc_class, smc_xyz_class, smc_fsn_class)
    INCLUDE (smc_item_id, smc_closing_value, smc_turn_ratio)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE smc_is_deleted = false;

-- Dead stock, worst first — the liquidation worklist.
CREATE INDEX IF NOT EXISTS ix_smc_dead
    ON stock.stock_movement_class USING btree
    (smc_company_id, smc_branch_id, smc_dead_value DESC)
    INCLUDE (smc_item_id, smc_dead_since_date, smc_closing_qty)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE smc_dead_stock_flag = true AND smc_is_deleted = false;


-- ═══════════════════════════════════════════════════════════════════════════
--  §17  THE ENGINE — functions and triggers.
--
--  The house pattern (09_acc_bill_balance, 13_loyalty_ledger, 14_loyalty_
--  coupon) is a recompute function plus a thin trigger that calls it, with
--  the invariant enforced by a CHECK the trigger writes through — so a bad
--  child row aborts its own INSERT instead of quietly corrupting a parent.
--  Stock follows it exactly.
-- ═══════════════════════════════════════════════════════════════════════════


-- ───────────────────────────────────────────────────────────────────────────
--  17.1  fn_stp_effective — resolve the tracking policy for one item.
--
--  Most specific wins:  item+branch → item → group+branch → group →
--  company+branch → company.  When nothing matches at all, the answer is
--  "track nothing", which is the correct default for a grocery line and
--  means an item needs no policy row to work.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_stp_effective(
    p_company_id uuid,
    p_branch_id  uuid,
    p_item_id    uuid,
    p_on_date    date DEFAULT CURRENT_DATE)
RETURNS TABLE (
    track_batch      boolean,
    track_mrp        boolean,
    track_sale_price boolean,
    track_expiry     boolean,
    track_serial     boolean,
    track_supplier   boolean,
    track_signature  character varying(8),
    valuation_method character varying(20),
    issue_strategy   character varying(20),
    allow_negative   character varying(10),
    near_expiry_days integer,
    block_expired    boolean,
    ageing_basis     character varying(20))
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
    v_group_id uuid;
BEGIN
    SELECT im.item_group_id INTO v_group_id
      FROM inventory.item_master im
     WHERE im.item_id = p_item_id;

    RETURN QUERY
    SELECT p.stp_track_batch, p.stp_track_mrp, p.stp_track_sale_price,
           p.stp_track_expiry, p.stp_track_serial, p.stp_track_supplier,
           p.stp_track_signature, p.stp_valuation_method, p.stp_issue_strategy,
           p.stp_allow_negative, p.stp_near_expiry_days,
           p.stp_block_expired_sale, p.stp_ageing_basis
      FROM stock.stock_track_policy p
     WHERE (p.stp_company_id = p_company_id OR p.stp_company_id IS NULL)
       AND p.stp_is_active = true
       AND p.stp_is_deleted = false
       AND p_on_date BETWEEN p.stp_effective_from AND p.stp_effective_to
       AND (p.stp_branch_id IS NULL OR p.stp_branch_id = p_branch_id)
       AND (   (p.stp_scope = 'ITEM'    AND p.stp_scope_id = p_item_id)
            OR (p.stp_scope = 'GROUP'   AND p.stp_scope_id = v_group_id)
            OR (p.stp_scope = 'COMPANY'))
     ORDER BY CASE
                  WHEN p.stp_scope = 'ITEM'    AND p.stp_branch_id IS NOT NULL THEN 1
                  WHEN p.stp_scope = 'ITEM'                                    THEN 2
                  WHEN p.stp_scope = 'GROUP'   AND p.stp_branch_id IS NOT NULL THEN 3
                  WHEN p.stp_scope = 'GROUP'                                   THEN 4
                  WHEN p.stp_branch_id IS NOT NULL                             THEN 5
                  ELSE 6
              END,
              -- Scope specificity is the PRIMARY sort: an ITEM row beats a
              -- GROUP row whatever their companies. Company specificity only
              -- breaks a tie within one level, so a company-specific ITEM row
              -- beats an every-company ITEM row, and both beat any GROUP row.
              (p.stp_company_id IS NULL)
     LIMIT 1;

    -- No policy anywhere: track nothing. One lot, plain item-wise stock.
    -- FEFO, matching the column default, so saving a default policy row for
    -- an item does not silently flip its issue strategy. Identical for an
    -- untracked item anyway — one lot with no expiry orders the same either
    -- way — but the lookup screen shows the strategy, and it must not change
    -- because a row was saved.
    IF NOT FOUND THEN
        RETURN QUERY SELECT false, false, false, false, false, false,
                            'N'::character varying(8),
                            'WAVG'::character varying(20),
                            'FEFO'::character varying(20),
                            'ALLOW'::character varying(10),
                            30, false,
                            'INWARD_DATE'::character varying(20);
    END IF;
END $$;

ALTER FUNCTION stock.fn_stp_effective(uuid, uuid, uuid, date) OWNER to postgres;


-- ───────────────────────────────────────────────────────────────────────────
--  17.2  fn_slt_resolve — find or create the lot, normalising as it goes.
--
--  THE function of this file. Every inward movement calls it; nothing else
--  may INSERT into stock_lot.
--
--  It blanks every identity value the effective policy does not track BEFORE
--  looking anything up. That is what makes an MRP typed out of habit on a
--  non-MRP item harmless instead of stock-fragmenting, and it is why the
--  four "modes" need no branching anywhere else.
--
--  The find/insert/find-again shape (rather than ON CONFLICT) is deliberate:
--  ux_slt_identity is a PARTIAL index over GENERATED columns, and catching
--  the violation is more robust than asking the planner to infer it.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_slt_resolve(
    p_company_id      uuid,
    p_item_id         uuid,
    p_base_uom_id     uuid,
    p_branch_id       uuid    DEFAULT NULL,
    p_batch_no        character varying DEFAULT NULL,
    p_mfg_date        date    DEFAULT NULL,
    p_expiry_date     date    DEFAULT NULL,
    p_mrp             numeric DEFAULT NULL,
    p_sale_price      numeric DEFAULT NULL,
    p_serial_no       character varying DEFAULT NULL,
    p_supplier_id     uuid    DEFAULT NULL,
    p_cost_rate       numeric DEFAULT 0,
    p_cost_rate_wot   numeric DEFAULT 0,
    p_doc_date        date    DEFAULT NULL,
    p_src_module      character varying DEFAULT NULL,
    p_src_doc_type    character varying DEFAULT NULL,
    p_src_doc_id      uuid    DEFAULT NULL,
    p_src_acc_year    character(9) DEFAULT NULL,
    p_src_refno       character varying DEFAULT NULL,
    p_created_by      uuid    DEFAULT NULL)
RETURNS uuid
LANGUAGE plpgsql
AS $$
DECLARE
    pol      record;
    v_batch  character varying(100);
    v_mrp    numeric(18,6);
    v_sp     numeric(18,6);
    v_mfg    date;
    v_exp    date;
    v_serial character varying(100);
    v_sup    uuid;
    v_id     uuid;
    v_date   date := COALESCE(p_doc_date, CURRENT_DATE);
BEGIN
    SELECT * INTO pol
      FROM stock.fn_stp_effective(p_company_id, p_branch_id, p_item_id, v_date);

    -- Normalise: anything not tracked is not part of this item's identity,
    -- whatever the caller passed.
    v_batch  := CASE WHEN pol.track_batch      THEN NULLIF(btrim(p_batch_no), '')  END;
    v_mrp    := CASE WHEN pol.track_mrp        THEN p_mrp        END;
    v_sp     := CASE WHEN pol.track_sale_price THEN p_sale_price END;
    v_exp    := CASE WHEN pol.track_expiry     THEN p_expiry_date END;
    v_mfg    := CASE WHEN pol.track_expiry     THEN p_mfg_date    END;
    v_serial := CASE WHEN pol.track_serial     THEN NULLIF(btrim(p_serial_no), '') END;
    v_sup    := CASE WHEN pol.track_supplier   THEN p_supplier_id END;

    -- Fast path: it almost always already exists.
    SELECT slt_id INTO v_id
      FROM stock.stock_lot
     WHERE slt_company_id = p_company_id
       AND slt_item_id    = p_item_id
       AND slt_is_deleted = false
       AND slt_key_batch    = COALESCE(NULLIF(upper(btrim(v_batch)), ''), '~')
       AND slt_key_mrp      = COALESCE(v_mrp, -1)
       AND slt_key_sp       = COALESCE(v_sp, -1)
       AND slt_key_expiry   = COALESCE(v_exp, DATE '0001-01-01')
       AND slt_key_serial   = COALESCE(NULLIF(upper(btrim(v_serial)), ''), '~')
       AND slt_key_supplier = COALESCE(v_sup, '00000000-0000-0000-0000-000000000000'::uuid);

    IF v_id IS NOT NULL THEN
        RETURN v_id;
    END IF;

    BEGIN
        INSERT INTO stock.stock_lot (
            slt_company_id, slt_item_id, slt_base_uom_id,
            slt_batch_no, slt_mrp, slt_sale_price, slt_mfg_date, slt_expiry_date,
            slt_serial_no, slt_supplier_id, slt_track_signature,
            slt_first_inward_date, slt_first_inward_branch,
            slt_inward_src_module, slt_inward_src_doc_type, slt_inward_src_doc_id,
            slt_inward_src_acc_year, slt_inward_refno,
            slt_cost_rate, slt_cost_rate_wot, slt_purchase_rate, slt_created_by)
        VALUES (
            p_company_id, p_item_id, p_base_uom_id,
            v_batch, v_mrp, v_sp, v_mfg, v_exp,
            v_serial, v_sup, pol.track_signature,
            v_date, p_branch_id,
            p_src_module, p_src_doc_type, p_src_doc_id,
            p_src_acc_year, p_src_refno,
            COALESCE(p_cost_rate, 0), COALESCE(p_cost_rate_wot, 0),
            COALESCE(p_cost_rate, 0), p_created_by)
        RETURNING slt_id INTO v_id;
    EXCEPTION WHEN unique_violation THEN
        -- Another counter created the same lot between the SELECT and here.
        SELECT slt_id INTO v_id
          FROM stock.stock_lot
         WHERE slt_company_id = p_company_id
           AND slt_item_id    = p_item_id
           AND slt_is_deleted = false
           AND slt_key_batch    = COALESCE(NULLIF(upper(btrim(v_batch)), ''), '~')
           AND slt_key_mrp      = COALESCE(v_mrp, -1)
           AND slt_key_sp       = COALESCE(v_sp, -1)
           AND slt_key_expiry   = COALESCE(v_exp, DATE '0001-01-01')
           AND slt_key_serial   = COALESCE(NULLIF(upper(btrim(v_serial)), ''), '~')
           AND slt_key_supplier = COALESCE(v_sup, '00000000-0000-0000-0000-000000000000'::uuid);
    END;

    RETURN v_id;
END $$;

ALTER FUNCTION stock.fn_slt_resolve(uuid, uuid, uuid, uuid, character varying, date,
    date, numeric, numeric, character varying, uuid, numeric, numeric, date,
    character varying, character varying, uuid, character(9), character varying, uuid)
    OWNER to postgres;


-- ───────────────────────────────────────────────────────────────────────────
--  17.3  fn_sml_apply — the posting trigger. One INSERT into stock_ledger
--        maintains four things.
--
--      1  stock_balance   the on-hand cache for this godown/lot/bucket
--      2  stock_lot       chain-wide total and ACTIVE/CLOSED status
--      3  stock_item_cost the moving weighted average for the branch
--      4  the negative-stock policy, enforced or warned or ignored
--
--  Everything it writes is derivable from stock_ledger alone, which is what
--  makes fn_sbl_rebuild() possible and what makes the cache safe to trust.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sml_apply()
RETURNS trigger
LANGUAGE plpgsql
AS $$
DECLARE
    lot        record;
    pol        record;
    v_in       numeric(18,6) := 0;
    v_out      numeric(18,6) := 0;
    v_free_in  numeric(18,6) := 0;
    v_free_out numeric(18,6) := 0;
    v_signed   numeric(18,6);
    v_on_hand  numeric(18,6);
    v_qty      numeric(18,6);
    v_old_qty  numeric(18,6);
    v_old_val  numeric(18,6);
    v_new_qty  numeric(18,6);
    v_new_val  numeric(18,6);
    v_new_val_wot numeric(18,6);
    v_rows     integer;
    v_sic_seeded boolean := false;
BEGIN
    IF NEW.sml_is_deleted THEN
        RETURN NULL;
    END IF;

    v_signed := NEW.sml_signed_base_qty;
    v_qty    := NEW.sml_base_qty + NEW.sml_free_base_qty;

    IF NEW.sml_direction = 1 THEN
        v_in      := NEW.sml_base_qty;
        v_free_in := NEW.sml_free_base_qty;
    ELSE
        v_out      := NEW.sml_base_qty;
        v_free_out := NEW.sml_free_base_qty;
    END IF;

    SELECT slt_batch_no, slt_mrp, slt_sale_price, slt_expiry_date, slt_supplier_id
      INTO lot
      FROM stock.stock_lot
     WHERE slt_id = NEW.sml_lot_id;

    -- ── 1. the balance row ────────────────────────────────────────────────
    UPDATE stock.stock_balance
       SET sbl_in_qty        = sbl_in_qty       + v_in,
           sbl_out_qty       = sbl_out_qty      + v_out,
           sbl_free_in_qty   = sbl_free_in_qty  + v_free_in,
           sbl_free_out_qty  = sbl_free_out_qty + v_free_out,
           sbl_first_in_date = CASE WHEN NEW.sml_direction = 1
                                    THEN LEAST(COALESCE(sbl_first_in_date, NEW.sml_doc_date),
                                               NEW.sml_doc_date)
                                    ELSE sbl_first_in_date END,
           sbl_last_in_date  = CASE WHEN NEW.sml_direction = 1
                                    THEN GREATEST(COALESCE(sbl_last_in_date, NEW.sml_doc_date),
                                                  NEW.sml_doc_date)
                                    ELSE sbl_last_in_date END,
           sbl_last_out_date = CASE WHEN NEW.sml_direction = -1
                                    THEN GREATEST(COALESCE(sbl_last_out_date, NEW.sml_doc_date),
                                                  NEW.sml_doc_date)
                                    ELSE sbl_last_out_date END,
           -- Identity cache, owned by stock_lot.
           sbl_batch_no      = lot.slt_batch_no,
           sbl_mrp           = lot.slt_mrp,
           sbl_sale_price    = lot.slt_sale_price,
           sbl_expiry_date   = lot.slt_expiry_date,
           sbl_supplier_id   = lot.slt_supplier_id,
           sbl_row_version   = sbl_row_version + 1,
           sbl_modified_on   = now()
     WHERE sbl_company_id = NEW.sml_company_id
       AND sbl_branch_id  = NEW.sml_branch_id
       AND sbl_godown_id  = NEW.sml_godown_id
       AND sbl_item_id    = NEW.sml_item_id
       AND sbl_lot_id     = NEW.sml_lot_id
       AND sbl_bucket     = NEW.sml_bucket
       AND sbl_is_deleted = false;

    GET DIAGNOSTICS v_rows = ROW_COUNT;

    IF v_rows = 0 THEN
        BEGIN
            INSERT INTO stock.stock_balance (
                sbl_company_id, sbl_branch_id, sbl_tenant_id, sbl_godown_id,
                sbl_item_id, sbl_lot_id, sbl_base_uom_id, sbl_bucket,
                sbl_in_qty, sbl_out_qty, sbl_free_in_qty, sbl_free_out_qty,
                sbl_first_in_date, sbl_last_in_date, sbl_last_out_date,
                sbl_batch_no, sbl_mrp, sbl_sale_price, sbl_expiry_date,
                sbl_supplier_id, sbl_created_by)
            VALUES (
                NEW.sml_company_id, NEW.sml_branch_id, NEW.sml_tenant_id,
                NEW.sml_godown_id, NEW.sml_item_id, NEW.sml_lot_id,
                NEW.sml_base_uom_id, NEW.sml_bucket,
                v_in, v_out, v_free_in, v_free_out,
                CASE WHEN NEW.sml_direction = 1  THEN NEW.sml_doc_date END,
                CASE WHEN NEW.sml_direction = 1  THEN NEW.sml_doc_date END,
                CASE WHEN NEW.sml_direction = -1 THEN NEW.sml_doc_date END,
                lot.slt_batch_no, lot.slt_mrp, lot.slt_sale_price,
                lot.slt_expiry_date, lot.slt_supplier_id, NEW.sml_created_by);
        EXCEPTION WHEN unique_violation THEN
            -- Two postings created the same holding at once; the other won.
            -- Same full update as the primary path — dropping the date
            -- anchors and identity cache here would leave the loser's
            -- movement half-applied until the next rebuild.
            UPDATE stock.stock_balance
               SET sbl_in_qty       = sbl_in_qty       + v_in,
                   sbl_out_qty      = sbl_out_qty      + v_out,
                   sbl_free_in_qty  = sbl_free_in_qty  + v_free_in,
                   sbl_free_out_qty = sbl_free_out_qty + v_free_out,
                   sbl_first_in_date = CASE WHEN NEW.sml_direction = 1
                                            THEN LEAST(COALESCE(sbl_first_in_date, NEW.sml_doc_date),
                                                       NEW.sml_doc_date)
                                            ELSE sbl_first_in_date END,
                   sbl_last_in_date  = CASE WHEN NEW.sml_direction = 1
                                            THEN GREATEST(COALESCE(sbl_last_in_date, NEW.sml_doc_date),
                                                          NEW.sml_doc_date)
                                            ELSE sbl_last_in_date END,
                   sbl_last_out_date = CASE WHEN NEW.sml_direction = -1
                                            THEN GREATEST(COALESCE(sbl_last_out_date, NEW.sml_doc_date),
                                                          NEW.sml_doc_date)
                                            ELSE sbl_last_out_date END,
                   sbl_batch_no     = lot.slt_batch_no,
                   sbl_mrp          = lot.slt_mrp,
                   sbl_sale_price   = lot.slt_sale_price,
                   sbl_expiry_date  = lot.slt_expiry_date,
                   sbl_supplier_id  = lot.slt_supplier_id,
                   sbl_row_version  = sbl_row_version + 1,
                   sbl_modified_on  = now()
             WHERE sbl_company_id = NEW.sml_company_id
               AND sbl_branch_id  = NEW.sml_branch_id
               AND sbl_godown_id  = NEW.sml_godown_id
               AND sbl_item_id    = NEW.sml_item_id
               AND sbl_lot_id     = NEW.sml_lot_id
               AND sbl_bucket     = NEW.sml_bucket
               AND sbl_is_deleted = false;
        END;
    END IF;

    -- ── 2. the lot's chain-wide total and status ──────────────────────────
    UPDATE stock.stock_lot
       SET slt_total_on_hand = slt_total_on_hand + v_signed,
           slt_status = CASE
                            WHEN slt_total_on_hand + v_signed <= 0
                                 AND slt_status = 'ACTIVE' AND NEW.sml_direction = -1
                            THEN 'CLOSED'
                            WHEN slt_status = 'CLOSED' AND NEW.sml_direction = 1
                            THEN 'ACTIVE'
                            ELSE slt_status
                        END,
           slt_closed_on = CASE
                               WHEN slt_total_on_hand + v_signed <= 0
                                    AND slt_status = 'ACTIVE' AND NEW.sml_direction = -1
                               THEN now()
                               WHEN slt_status = 'CLOSED' AND NEW.sml_direction = 1
                               THEN NULL
                               ELSE slt_closed_on
                           END,
           slt_row_version = slt_row_version + 1,
           slt_modified_on = now()
     WHERE slt_id = NEW.sml_lot_id;

    -- ── 3. the moving weighted average for the branch ─────────────────────
    -- Lock-or-seed loop. On the first-ever movement of an item two counters
    -- can race to create this row, and an ON CONFLICT DO NOTHING that simply
    -- fell through would swallow the loser's quantities — sic_total_qty
    -- would disagree with the ledger for ever, and nothing rebuilds this
    -- table. So the loser loops back and takes the winner's row lock, and
    -- its movement goes through the ordinary update path instead.
    LOOP
        SELECT sic_total_qty, sic_total_value INTO v_old_qty, v_old_val
          FROM stock.stock_item_cost
         WHERE sic_company_id = NEW.sml_company_id
           AND sic_branch_id  = NEW.sml_branch_id
           AND sic_item_id    = NEW.sml_item_id
           AND sic_is_deleted = false
         FOR UPDATE;
        EXIT WHEN FOUND;

        INSERT INTO stock.stock_item_cost (
            sic_company_id, sic_branch_id, sic_item_id, sic_base_uom_id,
            sic_total_qty, sic_total_value, sic_total_value_wot,
            sic_avg_cost_rate, sic_avg_cost_rate_wot, sic_max_cost_rate,
            sic_last_purchase_rate, sic_last_purchase_date, sic_created_by)
        VALUES (
            NEW.sml_company_id, NEW.sml_branch_id, NEW.sml_item_id,
            NEW.sml_base_uom_id,
            GREATEST(v_signed, 0),
            ROUND(GREATEST(v_signed, 0) * NEW.sml_cost_rate, 2),
            ROUND(GREATEST(v_signed, 0) * NEW.sml_cost_rate_wot, 2),
            NEW.sml_cost_rate, NEW.sml_cost_rate_wot, NEW.sml_cost_rate,
            CASE WHEN NEW.sml_direction = 1 THEN NEW.sml_cost_rate ELSE 0 END,
            CASE WHEN NEW.sml_direction = 1 THEN NEW.sml_doc_date END,
            NEW.sml_created_by)
        ON CONFLICT DO NOTHING;
        GET DIAGNOSTICS v_rows = ROW_COUNT;

        -- Inserted: the row already carries this movement. Lost the race:
        -- inserted nothing, loop back and lock what the winner made.
        IF v_rows = 1 THEN
            v_sic_seeded := true;
            EXIT;
        END IF;
    END LOOP;

    IF NOT v_sic_seeded THEN
        IF NEW.sml_direction = 1 THEN
            -- Inward re-averages.
            v_new_qty     := v_old_qty + v_qty;
            v_new_val     := v_old_val + ROUND(v_qty * NEW.sml_cost_rate, 2);
            v_new_val_wot := ROUND(v_qty * NEW.sml_cost_rate_wot, 2);
            UPDATE stock.stock_item_cost
               SET sic_total_qty          = v_new_qty,
                   sic_total_value        = v_new_val,
                   sic_total_value_wot    = sic_total_value_wot + v_new_val_wot,
                   sic_avg_cost_rate      = CASE WHEN v_new_qty > 0
                                                 THEN v_new_val / v_new_qty
                                                 ELSE NEW.sml_cost_rate END,
                   sic_avg_cost_rate_wot  = CASE WHEN v_new_qty > 0
                                                 THEN (sic_total_value_wot + v_new_val_wot) / v_new_qty
                                                 ELSE NEW.sml_cost_rate_wot END,
                   sic_max_cost_rate      = GREATEST(sic_max_cost_rate, NEW.sml_cost_rate),
                   sic_last_purchase_rate = NEW.sml_cost_rate,
                   sic_last_purchase_date = NEW.sml_doc_date,
                   sic_row_version        = sic_row_version + 1,
                   sic_modified_on        = now()
             WHERE sic_company_id = NEW.sml_company_id
               AND sic_branch_id  = NEW.sml_branch_id
               AND sic_item_id    = NEW.sml_item_id
               AND sic_is_deleted = false;
        ELSE
            -- Outward leaves the average alone and relieves value at it.
            UPDATE stock.stock_item_cost
               SET sic_total_qty       = sic_total_qty - v_qty,
                   sic_total_value     = GREATEST(sic_total_value
                                          - ROUND(v_qty * sic_avg_cost_rate, 2), 0),
                   sic_total_value_wot = GREATEST(sic_total_value_wot
                                          - ROUND(v_qty * sic_avg_cost_rate_wot, 2), 0),
                   sic_last_sale_rate  = CASE WHEN NEW.sml_txn_type = 'SALE'
                                              THEN NEW.sml_doc_rate
                                              ELSE sic_last_sale_rate END,
                   sic_last_sale_date  = CASE WHEN NEW.sml_txn_type = 'SALE'
                                              THEN NEW.sml_doc_date
                                              ELSE sic_last_sale_date END,
                   sic_row_version     = sic_row_version + 1,
                   sic_modified_on     = now()
             WHERE sic_company_id = NEW.sml_company_id
               AND sic_branch_id  = NEW.sml_branch_id
               AND sic_item_id    = NEW.sml_item_id
               AND sic_is_deleted = false;
        END IF;
    END IF;

    -- Carry the branch average onto the holdings, so a valuation report never
    -- has to join stock_item_cost per row.
    --
    -- EVERY holding of this item in this branch, not merely the one that just
    -- moved: a weighted average is a property of the item, so when a receipt
    -- moves it, every lot of that item is worth a different amount. Revaluing
    -- only the lot that moved leaves the others carrying the old rate, and the
    -- sum of sbl_stock_value silently stops agreeing with sic_total_value.
    -- The row count is the number of lots of one item in one branch — small.
    UPDATE stock.stock_balance b
       SET sbl_avg_cost_rate     = c.sic_avg_cost_rate,
           sbl_avg_cost_rate_wot = c.sic_avg_cost_rate_wot,
           sbl_stock_value       = ROUND(b.sbl_on_hand_qty * c.sic_avg_cost_rate, 2),
           sbl_stock_value_wot   = ROUND(b.sbl_on_hand_qty * c.sic_avg_cost_rate_wot, 2)
      FROM stock.stock_item_cost c
     WHERE c.sic_company_id = NEW.sml_company_id
       AND c.sic_branch_id  = NEW.sml_branch_id
       AND c.sic_item_id    = NEW.sml_item_id
       AND c.sic_is_deleted = false
       AND b.sbl_company_id = NEW.sml_company_id
       AND b.sbl_branch_id  = NEW.sml_branch_id
       AND b.sbl_item_id    = NEW.sml_item_id
       AND b.sbl_is_deleted = false;

    -- ── 4. the negative-stock policy ──────────────────────────────────────
    SELECT sbl_on_hand_qty INTO v_on_hand
      FROM stock.stock_balance
     WHERE sbl_company_id = NEW.sml_company_id
       AND sbl_branch_id  = NEW.sml_branch_id
       AND sbl_godown_id  = NEW.sml_godown_id
       AND sbl_item_id    = NEW.sml_item_id
       AND sbl_lot_id     = NEW.sml_lot_id
       AND sbl_bucket     = NEW.sml_bucket
       AND sbl_is_deleted = false;

    IF v_on_hand < 0 THEN
        SELECT * INTO pol
          FROM stock.fn_stp_effective(NEW.sml_company_id, NEW.sml_branch_id,
                                      NEW.sml_item_id, NEW.sml_doc_date);

        IF pol.allow_negative = 'BLOCK' THEN
            RAISE EXCEPTION
                'stock would go negative (% on hand) for item % lot % in godown % — policy is BLOCK',
                v_on_hand, NEW.sml_item_id, NEW.sml_lot_id, NEW.sml_godown_id
                USING ERRCODE = 'check_violation';
        ELSIF pol.allow_negative = 'WARN' THEN
            RAISE WARNING
                'negative stock: % on hand for item % lot % in godown %',
                v_on_hand, NEW.sml_item_id, NEW.sml_lot_id, NEW.sml_godown_id;
        END IF;
    END IF;

    RETURN NULL;
END $$;

ALTER FUNCTION stock.fn_sml_apply() OWNER to postgres;

-- Declared on the PARTITIONED PARENT: row triggers propagate to every
-- partition, so a new accounting year needs nothing but its partition.
DROP TRIGGER IF EXISTS tr_sml_apply ON stock.stock_ledger;
CREATE TRIGGER tr_sml_apply
    AFTER INSERT ON stock.stock_ledger
    FOR EACH ROW EXECUTE FUNCTION stock.fn_sml_apply();


-- ───────────────────────────────────────────────────────────────────────────
--  17.4  fn_sml_cost_default — stamp COGS onto an outward movement.
--
--  An outward row's cost is not the caller's opinion, it is what the stock
--  cost US, and it is knowable from data the engine already holds. Leaving it
--  to the application means every posting path has to remember to look it up,
--  and the first one that forgets produces a bill with 100% margin and a
--  valuation that never reconciles again.
--
--  So: if an outward movement arrives with no cost, the database fills it in,
--  per the item's stp_valuation_method —
--
--      WAVG                  the branch's moving average (stock_item_cost)
--      FIFO / LOT_ACTUAL     the actual cost of the lot being consumed
--
--  A caller that DOES supply a cost is left alone; this only closes the gap,
--  it does not overrule anybody. BEFORE INSERT, because the ledger is
--  immutable once written and an AFTER trigger could not correct it.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sml_cost_default()
RETURNS trigger
LANGUAGE plpgsql
AS $$
DECLARE
    pol      record;
    v_rate     numeric(18,6) := 0;
    v_rate_wot numeric(18,6) := 0;
    v_qty      numeric(18,6);
BEGIN
    IF NEW.sml_direction <> -1 OR NEW.sml_cost_rate <> 0 THEN
        RETURN NEW;
    END IF;

    SELECT * INTO pol
      FROM stock.fn_stp_effective(NEW.sml_company_id, NEW.sml_branch_id,
                                  NEW.sml_item_id, NEW.sml_doc_date);

    IF pol.valuation_method IN ('FIFO', 'LOT_ACTUAL') THEN
        SELECT slt_cost_rate, slt_cost_rate_wot INTO v_rate, v_rate_wot
          FROM stock.stock_lot WHERE slt_id = NEW.sml_lot_id;
    ELSE
        SELECT sic_avg_cost_rate, sic_avg_cost_rate_wot INTO v_rate, v_rate_wot
          FROM stock.stock_item_cost
         WHERE sic_company_id = NEW.sml_company_id
           AND sic_branch_id  = NEW.sml_branch_id
           AND sic_item_id    = NEW.sml_item_id
           AND sic_is_deleted = false;

        -- Nothing has ever been received here: fall back to the lot, which is
        -- the only cost that exists. A back-dated sale before its own receipt
        -- lands here, and zero would be worse than approximately right.
        IF NOT FOUND OR COALESCE(v_rate, 0) = 0 THEN
            SELECT slt_cost_rate, slt_cost_rate_wot INTO v_rate, v_rate_wot
              FROM stock.stock_lot WHERE slt_id = NEW.sml_lot_id;
        END IF;
    END IF;

    v_qty := NEW.sml_base_qty + NEW.sml_free_base_qty;

    NEW.sml_cost_rate      := COALESCE(v_rate, 0);
    NEW.sml_cost_rate_wot  := COALESCE(v_rate_wot, 0);
    NEW.sml_cost_value     := ROUND(v_qty * COALESCE(v_rate, 0), 2);
    NEW.sml_cost_value_wot := ROUND(v_qty * COALESCE(v_rate_wot, 0), 2);

    RETURN NEW;
END $$;

ALTER FUNCTION stock.fn_sml_cost_default() OWNER to postgres;

DROP TRIGGER IF EXISTS tr_sml_cost_default ON stock.stock_ledger;
CREATE TRIGGER tr_sml_cost_default
    BEFORE INSERT ON stock.stock_ledger
    FOR EACH ROW EXECUTE FUNCTION stock.fn_sml_cost_default();


-- ───────────────────────────────────────────────────────────────────────────
--  17.5  The ledger is append-only, and the database says so.
--
--  Convention is not enforcement. A stock figure that can be edited
--  retrospectively is a stock figure nobody can reconcile, so DELETE and any
--  UPDATE of a quantity are refused outright. A cancellation writes a
--  reversal row; only the soft-delete flag and sync bookkeeping may change.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sml_immutable()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION
            'stock.stock_ledger is append-only: post a reversal row instead of deleting %',
            OLD.sml_id USING ERRCODE = 'restrict_violation';
    END IF;

    IF NEW.sml_base_qty      IS DISTINCT FROM OLD.sml_base_qty
    OR NEW.sml_free_base_qty IS DISTINCT FROM OLD.sml_free_base_qty
    OR NEW.sml_direction     IS DISTINCT FROM OLD.sml_direction
    OR NEW.sml_lot_id        IS DISTINCT FROM OLD.sml_lot_id
    OR NEW.sml_godown_id     IS DISTINCT FROM OLD.sml_godown_id
    OR NEW.sml_bucket        IS DISTINCT FROM OLD.sml_bucket THEN
        RAISE EXCEPTION
            'stock.stock_ledger movement columns are immutable (row %)', OLD.sml_id
            USING ERRCODE = 'restrict_violation';
    END IF;

    RETURN NEW;
END $$;

ALTER FUNCTION stock.fn_sml_immutable() OWNER to postgres;

DROP TRIGGER IF EXISTS tr_sml_immutable ON stock.stock_ledger;
CREATE TRIGGER tr_sml_immutable
    BEFORE UPDATE OR DELETE ON stock.stock_ledger
    FOR EACH ROW EXECUTE FUNCTION stock.fn_sml_immutable();


-- ───────────────────────────────────────────────────────────────────────────
--  17.5a  The freeze window, enforced.
--
--  A count that does not freeze the stock it is counting is counting a
--  moving target — and until now the freeze was documentation: ck_svh_freeze
--  checked the window's shape and nothing refused a movement inside it.
--
--  The rule: while a DRAFT PHYSICAL voucher with svh_freeze_stock is inside
--  its window, NO ledger row may touch the godown being counted — except the
--  count's own posting. Details that matter:
--
--    * WALL CLOCK, not document date. The freeze protects the shelf as it
--      is NOW; a back-dated document posted during the window still changes
--      today's on-hand, so now() is what is tested.
--    * DRAFT only. Posting the count flips it to POSTED and the freeze
--      lifts by itself, even mid-window; so does cancelling the sheet.
--      Nothing to unlock, nothing to forget at 2 a.m.
--    * The counted godown is COALESCE(from, to) on the PHYSICAL header —
--      counts fill svh_from_godown_id.
--    * Other godowns of the same branch keep trading. A freeze is per
--      godown, not per branch.
--
--  Cost: one probe of ix_svh_freeze_open per posting — a partial index over
--  open freezing counts, which is almost always empty.
-- ───────────────────────────────────────────────────────────────────────────
CREATE INDEX IF NOT EXISTS ix_svh_freeze_open
    ON stock.stock_voucher USING btree
    (svh_company_id, svh_branch_id)
    WITH (fillfactor=100, deduplicate_items=True)
    WHERE svh_voucher_type::text = 'PHYSICAL'
      AND svh_freeze_stock = true
      AND svh_status::text = 'DRAFT'
      AND svh_is_deleted = false;

CREATE OR REPLACE FUNCTION stock.fn_sml_freeze_guard()
RETURNS trigger
LANGUAGE plpgsql
AS $$
DECLARE
    v_ref character varying(100);
    v_to  timestamp with time zone;
BEGIN
    SELECT svh_refno, svh_freeze_to
      INTO v_ref, v_to
      FROM stock.stock_voucher
     WHERE svh_voucher_type::text = 'PHYSICAL'
       AND svh_freeze_stock = true
       AND svh_status::text = 'DRAFT'
       AND svh_is_deleted   = false
       AND svh_company_id   = NEW.sml_company_id
       AND svh_branch_id    = NEW.sml_branch_id
       AND COALESCE(svh_from_godown_id, svh_to_godown_id) = NEW.sml_godown_id
       AND now() BETWEEN svh_freeze_from AND svh_freeze_to
       -- The count's own rows pass: the whole point of the freeze is that
       -- THIS document gets a still shelf to post against.
       AND NOT (NEW.sml_src_module   = 'STOCK'
                AND NEW.sml_src_doc_type = 'STOCK_VOUCHER'
                AND NEW.sml_src_doc_id   = svh_id)
     LIMIT 1;

    IF FOUND THEN
        RAISE EXCEPTION
            'this godown is frozen for physical count % (until %); post the movement after the count closes',
            v_ref, v_to
            USING ERRCODE = 'restrict_violation';
    END IF;

    RETURN NEW;
END $$;

ALTER FUNCTION stock.fn_sml_freeze_guard() OWNER to postgres;

DROP TRIGGER IF EXISTS tr_sml_freeze_guard ON stock.stock_ledger;
CREATE TRIGGER tr_sml_freeze_guard
    BEFORE INSERT ON stock.stock_ledger
    FOR EACH ROW EXECUTE FUNCTION stock.fn_sml_freeze_guard();


-- ───────────────────────────────────────────────────────────────────────────
--  17.6  Reservations and transit roll into the balance.
--
--  Both are recompute-from-children, not increment-in-place: an increment
--  that runs twice is wrong for ever, whereas a re-sum is right every time
--  and costs one indexed aggregate.
--
--  Both can also precede the holding's FIRST movement: an order taken
--  against stock the GRN clerk has not keyed yet, a transfer despatched to
--  a godown that has never held the item. An UPDATE alone would then match
--  no row, the hold would be invisible in sbl_reserved_qty / transit_in,
--  and when fn_sml_apply later created the row it would default both to 0
--  and never re-sum them. So the refreshers create the zero-quantity row
--  first when there is anything to carry.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sbl_ensure_row(
    p_company_id uuid, p_branch_id uuid, p_godown_id uuid,
    p_item_id uuid, p_lot_id uuid, p_bucket character varying)
RETURNS void
LANGUAGE plpgsql
AS $$
BEGIN
    IF EXISTS (SELECT 1
                 FROM stock.stock_balance
                WHERE sbl_company_id = p_company_id
                  AND sbl_branch_id  = p_branch_id
                  AND sbl_godown_id  = p_godown_id
                  AND sbl_item_id    = p_item_id
                  AND sbl_lot_id     = p_lot_id
                  AND sbl_bucket     = p_bucket
                  AND sbl_is_deleted = false) THEN
        RETURN;
    END IF;

    BEGIN
        -- All accumulators default to 0; identity cache from the lot, the
        -- same columns fn_sml_apply copies, so the row is indistinguishable
        -- from one the ledger created.
        INSERT INTO stock.stock_balance (
            sbl_company_id, sbl_branch_id, sbl_godown_id, sbl_item_id,
            sbl_lot_id, sbl_base_uom_id, sbl_bucket,
            sbl_batch_no, sbl_mrp, sbl_sale_price, sbl_expiry_date,
            sbl_supplier_id)
        SELECT p_company_id, p_branch_id, p_godown_id, p_item_id,
               l.slt_id, l.slt_base_uom_id, p_bucket,
               l.slt_batch_no, l.slt_mrp, l.slt_sale_price, l.slt_expiry_date,
               l.slt_supplier_id
          FROM stock.stock_lot l
         WHERE l.slt_id = p_lot_id;
    EXCEPTION WHEN unique_violation THEN
        NULL;   -- another session created it; that is all that was wanted
    END;
END $$;

ALTER FUNCTION stock.fn_sbl_ensure_row(uuid, uuid, uuid, uuid, uuid,
    character varying) OWNER to postgres;


CREATE OR REPLACE FUNCTION stock.fn_sbl_refresh_reserved(
    p_company_id uuid, p_branch_id uuid, p_godown_id uuid,
    p_item_id uuid, p_lot_id uuid, p_bucket character varying)
RETURNS void
LANGUAGE plpgsql
AS $$
DECLARE
    v_open numeric(18,6);
BEGIN
    SELECT COALESCE(SUM(r.srv_open_qty), 0) INTO v_open
      FROM stock.stock_reservation r
     WHERE r.srv_company_id = p_company_id
       AND r.srv_branch_id  = p_branch_id
       AND r.srv_godown_id  = p_godown_id
       AND r.srv_item_id    = p_item_id
       AND r.srv_lot_id     = p_lot_id
       AND r.srv_bucket     = p_bucket
       AND r.srv_is_deleted = false
       AND r.srv_status IN ('OPEN', 'PARTIAL');

    IF v_open > 0 THEN
        PERFORM stock.fn_sbl_ensure_row(p_company_id, p_branch_id,
            p_godown_id, p_item_id, p_lot_id, p_bucket);
    END IF;

    UPDATE stock.stock_balance
       SET sbl_reserved_qty = v_open,
           sbl_row_version = sbl_row_version + 1,
           sbl_modified_on = now()
     WHERE sbl_company_id = p_company_id
       AND sbl_branch_id  = p_branch_id
       AND sbl_godown_id  = p_godown_id
       AND sbl_item_id    = p_item_id
       AND sbl_lot_id     = p_lot_id
       AND sbl_bucket     = p_bucket
       AND sbl_is_deleted = false;
END $$;

ALTER FUNCTION stock.fn_sbl_refresh_reserved(uuid, uuid, uuid, uuid, uuid,
    character varying) OWNER to postgres;


CREATE OR REPLACE FUNCTION stock.fn_srv_refresh()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        PERFORM stock.fn_sbl_refresh_reserved(OLD.srv_company_id, OLD.srv_branch_id,
            OLD.srv_godown_id, OLD.srv_item_id, OLD.srv_lot_id, OLD.srv_bucket);
        RETURN NULL;
    END IF;

    PERFORM stock.fn_sbl_refresh_reserved(NEW.srv_company_id, NEW.srv_branch_id,
        NEW.srv_godown_id, NEW.srv_item_id, NEW.srv_lot_id, NEW.srv_bucket);

    -- A reservation moved to a different holding leaves the old one to re-sum.
    IF TG_OP = 'UPDATE' AND (NEW.srv_lot_id    IS DISTINCT FROM OLD.srv_lot_id
                          OR NEW.srv_godown_id IS DISTINCT FROM OLD.srv_godown_id
                          OR NEW.srv_bucket    IS DISTINCT FROM OLD.srv_bucket) THEN
        PERFORM stock.fn_sbl_refresh_reserved(OLD.srv_company_id, OLD.srv_branch_id,
            OLD.srv_godown_id, OLD.srv_item_id, OLD.srv_lot_id, OLD.srv_bucket);
    END IF;

    RETURN NULL;
END $$;

    AFTER INSERT OR UPDATE OR DELETE ON stock.stock_reservation

CREATE OR REPLACE FUNCTION stock.fn_stt_refresh()
RETURNS trigger
LANGUAGE plpgsql
AS $$
DECLARE
    v_company uuid; v_branch uuid; v_godown uuid;
    v_item uuid; v_lot uuid; v_bucket character varying(20);
    v_transit numeric(18,6);
BEGIN
    IF TG_OP = 'DELETE' THEN
        v_company := OLD.stt_company_id; v_branch := OLD.stt_to_branch_id;
        v_godown  := OLD.stt_to_godown_id; v_item := OLD.stt_item_id;
        v_lot     := OLD.stt_lot_id;       v_bucket := OLD.stt_bucket;
    ELSE
        v_company := NEW.stt_company_id; v_branch := NEW.stt_to_branch_id;
        v_godown  := NEW.stt_to_godown_id; v_item := NEW.stt_item_id;
        v_lot     := NEW.stt_lot_id;       v_bucket := NEW.stt_bucket;
    END IF;

    SELECT COALESCE(SUM(t.stt_sent_qty - t.stt_received_qty - t.stt_damage_qty), 0)
      INTO v_transit
      FROM stock.stock_transit t
     WHERE t.stt_company_id   = v_company
       AND t.stt_to_branch_id = v_branch
       AND t.stt_to_godown_id = v_godown
       AND t.stt_item_id      = v_item
       AND t.stt_lot_id       = v_lot
       AND t.stt_bucket       = v_bucket
       AND t.stt_is_deleted   = false
       AND t.stt_status IN ('IN_TRANSIT', 'PARTIAL');

    -- The commonest first-transit case: the receiving godown has never held
    -- this item. See the 17.6 header — the row must exist or the inbound
    -- quantity is invisible until the goods arrive.
    IF v_transit > 0 THEN
        PERFORM stock.fn_sbl_ensure_row(v_company, v_branch, v_godown,
            v_item, v_lot, v_bucket);
    END IF;

    -- Only the DESTINATION carries transit: at the source the stock has
    -- already left and is out of the balance entirely.
    UPDATE stock.stock_balance
       SET sbl_transit_in_qty = v_transit,
           sbl_row_version = sbl_row_version + 1,
           sbl_modified_on = now()
     WHERE sbl_company_id = v_company
       AND sbl_branch_id  = v_branch
       AND sbl_godown_id  = v_godown
       AND sbl_item_id    = v_item
       AND sbl_lot_id     = v_lot
       AND sbl_bucket     = v_bucket
       AND sbl_is_deleted = false;

    RETURN NULL;
END $$;

ALTER FUNCTION stock.fn_stt_refresh() OWNER to postgres;

DROP TRIGGER IF EXISTS tr_stt_refresh ON stock.stock_transit;
CREATE TRIGGER tr_stt_refresh
    AFTER INSERT OR UPDATE OR DELETE ON stock.stock_transit
    FOR EACH ROW EXECUTE FUNCTION stock.fn_stt_refresh();


-- ───────────────────────────────────────────────────────────────────────────
--  17.7  Voucher totals — the header's caches, re-summed from its lines.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_svh_recompute(
    p_voucher_id uuid, p_acc_year character(9))
RETURNS void
LANGUAGE plpgsql
AS $$
DECLARE
    v_type character varying(30);
BEGIN
    IF p_voucher_id IS NULL THEN
        RETURN;
    END IF;

    SELECT svh_voucher_type INTO v_type
      FROM stock.stock_voucher
     WHERE svh_id = p_voucher_id AND svh_acc_year = p_acc_year;

    -- ── PHYSICAL: the header carries the NET VARIANCE ────────────────────
    -- A count's lines carry qty 0 by design — only the difference posts —
    -- so the generic sum below would report 0 whatever the variance was
    -- (the flow doc's known gap). The honest source is the LEDGER rows the
    -- count posted: quantity as the signed sum, value at the cost each row
    -- actually carried — a shortage's COGS is stamped onto the ROW by
    -- fn_sml_cost_default and never appears on the line. A DRAFT count has
    -- posted nothing and truthfully totals 0; its provisional variance
    -- (SUM(svi_diff_qty)) is the screen's business, not the header's.
    IF v_type = 'PHYSICAL' THEN
        UPDATE stock.stock_voucher v
           SET svh_line_count      = s.cnt,
               svh_total_qty       = l.qty,
               svh_total_value     = l.val,
               svh_total_value_wot = l.val_wot,
               svh_modified_on     = now()
          FROM (SELECT COUNT(*) AS cnt
                  FROM stock.stock_voucher_item
                 WHERE svi_voucher_id = p_voucher_id
                   AND svi_acc_year   = p_acc_year
                   AND svi_is_deleted = false) s,
               -- Reversals included on purpose: a cancelled-then-recomputed
               -- count truthfully totals back to 0.
               (SELECT COALESCE(SUM(sml_signed_base_qty), 0)                AS qty,
                       COALESCE(SUM(sml_direction * sml_cost_value), 0)     AS val,
                       COALESCE(SUM(sml_direction * sml_cost_value_wot), 0) AS val_wot
                  FROM stock.stock_ledger
                 WHERE sml_acc_year     = p_acc_year
                   AND sml_src_module   = 'STOCK'
                   AND sml_src_doc_type = 'STOCK_VOUCHER'
                   AND sml_src_doc_id   = p_voucher_id
                   AND sml_is_deleted   = false) l
         WHERE v.svh_id = p_voucher_id AND v.svh_acc_year = p_acc_year;
        RETURN;
    END IF;

    UPDATE stock.stock_voucher v
       SET svh_line_count      = s.cnt,
           svh_total_qty       = s.qty,
           svh_total_value     = s.val,
           svh_total_value_wot = s.val_wot,
           svh_modified_on     = now()
      FROM (
            SELECT COUNT(*)                                       AS cnt,
                   COALESCE(SUM(svi_base_qty + svi_free_base_qty), 0) AS qty,
                   COALESCE(SUM(svi_value), 0)                    AS val,
                   COALESCE(SUM(svi_value_wot), 0)                AS val_wot
              FROM stock.stock_voucher_item
             WHERE svi_voucher_id = p_voucher_id
               AND svi_acc_year   = p_acc_year
               AND svi_is_deleted = false
           ) s
     WHERE v.svh_id       = p_voucher_id
       AND v.svh_acc_year = p_acc_year;
END $$;

ALTER FUNCTION stock.fn_svh_recompute(uuid, character(9)) OWNER to postgres;


CREATE OR REPLACE FUNCTION stock.fn_svi_refresh_header()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        PERFORM stock.fn_svh_recompute(OLD.svi_voucher_id, OLD.svi_acc_year);
        RETURN NULL;
    END IF;

    PERFORM stock.fn_svh_recompute(NEW.svi_voucher_id, NEW.svi_acc_year);

    IF TG_OP = 'UPDATE' AND NEW.svi_voucher_id IS DISTINCT FROM OLD.svi_voucher_id THEN
        PERFORM stock.fn_svh_recompute(OLD.svi_voucher_id, OLD.svi_acc_year);
    END IF;

    RETURN NULL;
END $$;

ALTER FUNCTION stock.fn_svi_refresh_header() OWNER to postgres;

DROP TRIGGER IF EXISTS tr_svi_refresh_header ON stock.stock_voucher_item;
CREATE TRIGGER tr_svi_refresh_header
    AFTER INSERT OR UPDATE OR DELETE ON stock.stock_voucher_item
    FOR EACH ROW EXECUTE FUNCTION stock.fn_svi_refresh_header();


-- ───────────────────────────────────────────────────────────────────────────
--  17.8  fn_sbl_rebuild — the proof that the cache is only a cache.
--
--  Re-derives every balance for a branch from stock_ledger alone. Run it
--  after a migration, after a suspected concurrency bug, or as a nightly
--  assertion: if it changes anything, the trigger has a hole and the ledger
--  is still right.
--
--  Returns the number of holdings that DIFFERED, so it can be alerted on.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sbl_rebuild(
    p_company_id uuid,
    p_branch_id  uuid DEFAULT NULL)
RETURNS integer
LANGUAGE plpgsql
AS $$
DECLARE
    v_diff integer := 0;
    v_ins  integer := 0;
BEGIN
    WITH truth AS (
        SELECT sml_company_id, sml_branch_id, sml_godown_id, sml_item_id,
               sml_lot_id, sml_bucket, (array_agg(sml_base_uom_id))[1] AS base_uom,
               SUM(CASE WHEN sml_direction =  1 THEN sml_base_qty      ELSE 0 END) AS in_qty,
               SUM(CASE WHEN sml_direction = -1 THEN sml_base_qty      ELSE 0 END) AS out_qty,
               SUM(CASE WHEN sml_direction =  1 THEN sml_free_base_qty ELSE 0 END) AS f_in,
               SUM(CASE WHEN sml_direction = -1 THEN sml_free_base_qty ELSE 0 END) AS f_out,
               MIN(sml_doc_date) FILTER (WHERE sml_direction =  1) AS first_in,
               MAX(sml_doc_date) FILTER (WHERE sml_direction =  1) AS last_in,
               MAX(sml_doc_date) FILTER (WHERE sml_direction = -1) AS last_out
          FROM stock.stock_ledger
         WHERE sml_company_id = p_company_id
           AND (p_branch_id IS NULL OR sml_branch_id = p_branch_id)
           AND sml_is_deleted = false
         GROUP BY 1, 2, 3, 4, 5, 6
    ), applied AS (
        UPDATE stock.stock_balance b
           SET sbl_in_qty        = t.in_qty,
               sbl_out_qty       = t.out_qty,
               sbl_free_in_qty   = t.f_in,
               sbl_free_out_qty  = t.f_out,
               sbl_first_in_date = t.first_in,
               sbl_last_in_date  = t.last_in,
               sbl_last_out_date = t.last_out,
               sbl_row_version   = b.sbl_row_version + 1,
               sbl_modified_on   = now()
          FROM truth t
         WHERE b.sbl_company_id = t.sml_company_id
           AND b.sbl_branch_id  = t.sml_branch_id
           AND b.sbl_godown_id  = t.sml_godown_id
           AND b.sbl_item_id    = t.sml_item_id
           AND b.sbl_lot_id     = t.sml_lot_id
           AND b.sbl_bucket     = t.sml_bucket
           AND b.sbl_is_deleted = false
           AND (b.sbl_in_qty       IS DISTINCT FROM t.in_qty
             OR b.sbl_out_qty      IS DISTINCT FROM t.out_qty
             OR b.sbl_free_in_qty  IS DISTINCT FROM t.f_in
             OR b.sbl_free_out_qty IS DISTINCT FROM t.f_out)
        RETURNING 1)
    SELECT COUNT(*) INTO v_diff FROM applied;

    -- Holdings the ledger knows about and the cache has never heard of.
    INSERT INTO stock.stock_balance (
        sbl_company_id, sbl_branch_id, sbl_godown_id, sbl_item_id, sbl_lot_id,
        sbl_base_uom_id, sbl_bucket,
        sbl_in_qty, sbl_out_qty, sbl_free_in_qty, sbl_free_out_qty,
        sbl_first_in_date, sbl_last_in_date, sbl_last_out_date,
        sbl_batch_no, sbl_mrp, sbl_sale_price, sbl_expiry_date, sbl_supplier_id)
    SELECT t.sml_company_id, t.sml_branch_id, t.sml_godown_id, t.sml_item_id,
           t.sml_lot_id, t.base_uom, t.sml_bucket,
           t.in_qty, t.out_qty, t.f_in, t.f_out,
           t.first_in, t.last_in, t.last_out,
           l.slt_batch_no, l.slt_mrp, l.slt_sale_price, l.slt_expiry_date,
           l.slt_supplier_id
      FROM (
            SELECT sml_company_id, sml_branch_id, sml_godown_id, sml_item_id,
                   sml_lot_id, sml_bucket, (array_agg(sml_base_uom_id))[1] AS base_uom,
                   SUM(CASE WHEN sml_direction =  1 THEN sml_base_qty      ELSE 0 END) AS in_qty,
                   SUM(CASE WHEN sml_direction = -1 THEN sml_base_qty      ELSE 0 END) AS out_qty,
                   SUM(CASE WHEN sml_direction =  1 THEN sml_free_base_qty ELSE 0 END) AS f_in,
                   SUM(CASE WHEN sml_direction = -1 THEN sml_free_base_qty ELSE 0 END) AS f_out,
                   MIN(sml_doc_date) FILTER (WHERE sml_direction =  1) AS first_in,
                   MAX(sml_doc_date) FILTER (WHERE sml_direction =  1) AS last_in,
                   MAX(sml_doc_date) FILTER (WHERE sml_direction = -1) AS last_out
              FROM stock.stock_ledger
             WHERE sml_company_id = p_company_id
               AND (p_branch_id IS NULL OR sml_branch_id = p_branch_id)
               AND sml_is_deleted = false
             GROUP BY 1, 2, 3, 4, 5, 6
           ) t
      JOIN stock.stock_lot l ON l.slt_id = t.sml_lot_id
     WHERE NOT EXISTS (
            SELECT 1 FROM stock.stock_balance b
             WHERE b.sbl_company_id = t.sml_company_id
               AND b.sbl_branch_id  = t.sml_branch_id
               AND b.sbl_godown_id  = t.sml_godown_id
               AND b.sbl_item_id    = t.sml_item_id
               AND b.sbl_lot_id     = t.sml_lot_id
               AND b.sbl_bucket     = t.sml_bucket
               AND b.sbl_is_deleted = false);

    -- ACCUMULATED, not assigned: the update count above is the drift signal
    -- a nightly assertion alerts on, and overwriting it here with only the
    -- missing-holding count would report 0 while fifty balances had drifted.
    GET DIAGNOSTICS v_ins = ROW_COUNT;
    v_diff := v_diff + v_ins;

    -- The lot's chain-wide total, likewise re-derived.
    UPDATE stock.stock_lot l
       SET slt_total_on_hand = COALESCE(s.total, 0),
           slt_modified_on   = now()
      FROM (SELECT sbl_lot_id, SUM(sbl_on_hand_qty) AS total
              FROM stock.stock_balance
             WHERE sbl_company_id = p_company_id
               AND sbl_is_deleted = false
             GROUP BY sbl_lot_id) s
     WHERE l.slt_id = s.sbl_lot_id
       AND l.slt_total_on_hand IS DISTINCT FROM s.total;

    RETURN v_diff;
END $$;

ALTER FUNCTION stock.fn_sbl_rebuild(uuid, uuid) OWNER to postgres;


-- ───────────────────────────────────────────────────────────────────────────
--  17.9  fn_sdd_rebuild — the demand aggregate, re-derived from the ledger.
--
--  Idempotent for a date range: delete and re-insert, so a re-run after a
--  back-dated bill produces the right answer rather than a doubled one.
--
--  stockout_flag is set where the day's closing balance was zero or less —
--  a floor, not a measurement, which every model downstream must know.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sdd_rebuild(
    p_company_id uuid,
    p_branch_id  uuid,
    p_from       date,
    p_to         date)
RETURNS integer
LANGUAGE plpgsql
AS $$
DECLARE
    v_rows integer := 0;
BEGIN
    DELETE FROM stock.stock_demand_daily
     WHERE sdd_company_id = p_company_id
       AND sdd_branch_id  = p_branch_id
       AND sdd_demand_date BETWEEN p_from AND p_to;

    INSERT INTO stock.stock_demand_daily (
        sdd_company_id, sdd_branch_id, sdd_item_id, sdd_base_uom_id,
        sdd_demand_date, sdd_day_of_week,
        sdd_sold_qty, sdd_free_qty, sdd_return_qty,
        sdd_bill_count, sdd_line_count,
        sdd_revenue_wot, sdd_cogs_wot)
    SELECT sml_company_id, sml_branch_id, sml_item_id,
           (array_agg(sml_base_uom_id))[1],
           sml_doc_date,
           EXTRACT(dow FROM sml_doc_date)::smallint,
           COALESCE(SUM(sml_base_qty)      FILTER (WHERE sml_txn_type = 'SALE'), 0),
           COALESCE(SUM(sml_free_base_qty) FILTER (WHERE sml_txn_type = 'SALE'), 0),
           COALESCE(SUM(sml_base_qty + sml_free_base_qty)
                                           FILTER (WHERE sml_txn_type = 'SALE_RETURN'), 0),
           COUNT(DISTINCT sml_src_doc_id)  FILTER (WHERE sml_txn_type = 'SALE'),
           COUNT(*)                        FILTER (WHERE sml_txn_type = 'SALE'),
           COALESCE(SUM(sml_doc_amount_wot) FILTER (WHERE sml_txn_type = 'SALE'), 0),
           COALESCE(SUM(sml_cost_value_wot) FILTER (WHERE sml_txn_type = 'SALE'), 0)
      FROM stock.stock_ledger
     WHERE sml_company_id = p_company_id
       AND sml_branch_id  = p_branch_id
       AND sml_doc_date BETWEEN p_from AND p_to
       AND sml_is_deleted = false
       AND sml_txn_type IN ('SALE', 'SALE_RETURN')
     GROUP BY sml_company_id, sml_branch_id, sml_item_id, sml_doc_date;

    GET DIAGNOSTICS v_rows = ROW_COUNT;

    -- Mark the days where there was nothing left to sell. Approximated from
    -- the CURRENT balance walked backwards; a branch that wants it exact runs
    -- this nightly, when "current" and "end of day" are the same thing.
    UPDATE stock.stock_demand_daily d
       SET sdd_stockout_flag = true
      FROM (SELECT sbl_item_id
              FROM stock.stock_balance
             WHERE sbl_company_id = p_company_id
               AND sbl_branch_id  = p_branch_id
               AND sbl_is_deleted = false
             GROUP BY sbl_item_id
            HAVING SUM(sbl_on_hand_qty) <= 0) z
     WHERE d.sdd_company_id = p_company_id
       AND d.sdd_branch_id  = p_branch_id
       AND d.sdd_item_id    = z.sbl_item_id
       AND d.sdd_demand_date BETWEEN p_from AND p_to;

    RETURN v_rows;
END $$;

ALTER FUNCTION stock.fn_sdd_rebuild(uuid, uuid, date, date) OWNER to postgres;


-- ───────────────────────────────────────────────────────────────────────────
--  17.10  fn_stock_asof — quantity and value as on any date.
--
--  Nearest snapshot at or before the date, plus the ledger movements since.
--  Bounded work: with a month-end snapshot the delta is never more than a
--  month of rows, however many years of history exist. With no snapshot at
--  all it degrades to a full replay and still gives the right answer.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_stock_asof(
    p_company_id uuid,
    p_branch_id  uuid,
    p_as_on      date,
    p_item_id    uuid DEFAULT NULL,
    p_godown_id  uuid DEFAULT NULL)
RETURNS TABLE (
    godown_id   uuid,
    item_id     uuid,
    lot_id      uuid,
    bucket      character varying(20),
    qty         numeric(18,6),
    value_at_cost numeric(18,2))
LANGUAGE sql
STABLE
AS $$
    WITH base AS (
        -- The most recent frozen point at or before the date.
        SELECT DISTINCT ON (svs_godown_id, svs_item_id, svs_lot_id, svs_bucket)
               svs_godown_id, svs_item_id, svs_lot_id, svs_bucket,
               svs_snap_date, svs_qty, svs_value_at_cost
          FROM stock.stock_valuation_snap
         WHERE svs_company_id = p_company_id
           AND svs_branch_id  = p_branch_id
           AND svs_snap_date <= p_as_on
           AND svs_is_deleted = false
           AND (p_item_id   IS NULL OR svs_item_id   = p_item_id)
           AND (p_godown_id IS NULL OR svs_godown_id = p_godown_id)
         ORDER BY svs_godown_id, svs_item_id, svs_lot_id, svs_bucket,
                  svs_snap_date DESC
    ), delta AS (
        SELECT l.sml_godown_id, l.sml_item_id, l.sml_lot_id, l.sml_bucket,
               SUM(l.sml_signed_base_qty) AS d_qty,
               SUM(l.sml_direction * l.sml_cost_value) AS d_val
          FROM stock.stock_ledger l
          LEFT JOIN base b
                 ON b.svs_godown_id = l.sml_godown_id
                AND b.svs_item_id   = l.sml_item_id
                AND b.svs_lot_id    = l.sml_lot_id
                AND b.svs_bucket    = l.sml_bucket
         WHERE l.sml_company_id = p_company_id
           AND l.sml_branch_id  = p_branch_id
           AND l.sml_is_deleted = false
           AND l.sml_doc_date  <= p_as_on
           AND l.sml_doc_date   > COALESCE(b.svs_snap_date, DATE '0001-01-01')
           AND (p_item_id   IS NULL OR l.sml_item_id   = p_item_id)
           AND (p_godown_id IS NULL OR l.sml_godown_id = p_godown_id)
         GROUP BY 1, 2, 3, 4
    )
    SELECT COALESCE(b.svs_godown_id, d.sml_godown_id),
           COALESCE(b.svs_item_id,   d.sml_item_id),
           COALESCE(b.svs_lot_id,    d.sml_lot_id),
           COALESCE(b.svs_bucket,    d.sml_bucket),
           COALESCE(b.svs_qty, 0)           + COALESCE(d.d_qty, 0),
           COALESCE(b.svs_value_at_cost, 0) + COALESCE(d.d_val, 0)
      FROM base b
      FULL JOIN delta d
             ON d.sml_godown_id = b.svs_godown_id
            AND d.sml_item_id   = b.svs_item_id
            AND d.sml_lot_id    = b.svs_lot_id
            AND d.sml_bucket    = b.svs_bucket;
$$;

-- ───────────────────────────────────────────────────────────────────────────
--  17.10a  fn_sag_coverage — a ladder must cover every day, or it lies.
--
--  ex_sag_overlap stops two slabs claiming one day. Nothing stopped NO slab
--  claiming it, and that failure is silent in the worst way: fn_stock_ageing
--  LEFT JOINs the ladder, so an uncovered holding comes back with slab_no
--  NULL. The quantity is still there — the total still reconciles — but a
--  report that groups by slab and drops the blank shows an EMPTY ageing
--  report while the stock sits on the shelf.
--
--  The commonest way in is not a typo. It is a screen offering "customise the
--  ladder" and writing ONE row: that single insert switches the company off
--  the default ladder (fn_sag_effective is all-or-nothing) onto a one-rung
--  ladder covering almost nothing.
--
--  Contiguity is a property of the SET, so no CHECK can see it and no
--  EXCLUDE can express it. It needs a constraint trigger, and it is DEFERRED
--  so that a whole-ladder save may pass through invalid intermediate states
--  and be judged only at COMMIT.
--
--  The four rules, per ladder:
--      * starts at day 0            — stock is not born aged
--      * no gaps                    — each slab starts where the last ended + 1
--      * exactly one open-ended     — or stock older than the top rung vanishes
--      * the open-ended one is last — implied by the two rules above
--
--  An EMPTY ladder is legal: deleting every company row is how you revert to
--  the default one.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sag_coverage()
RETURNS trigger
LANGUAGE plpgsql
AS $$
DECLARE
    v_company uuid;
    v_n       integer;
    v_open    integer;
    v_bad     record;
    v_label   text;
BEGIN
    v_company := CASE WHEN TG_OP = 'DELETE' THEN OLD.sag_company_id
                                            ELSE NEW.sag_company_id END;
    v_label   := COALESCE(v_company::text, 'the default ladder');

    SELECT count(*), count(*) FILTER (WHERE sag_to_days IS NULL)
      INTO v_n, v_open
      FROM stock.stock_ageing_slab
     WHERE COALESCE(sag_company_id, '00000000-0000-0000-0000-000000000000'::uuid)
         = COALESCE(v_company,      '00000000-0000-0000-0000-000000000000'::uuid)
       AND sag_is_active  = true
       AND sag_is_deleted = false;

    -- No ladder at all is how a company reverts to the default one.
    IF v_n = 0 THEN
        RETURN NULL;
    END IF;

    IF v_open <> 1 THEN
        RAISE EXCEPTION
            'ageing ladder % must have exactly one open-ended slab (sag_to_days NULL), found %; stock older than the top rung would belong to no slab',
            v_label, v_open
            USING ERRCODE = 'check_violation';
    END IF;

    SELECT * INTO v_bad FROM (
        SELECT l.sag_slab_no, l.sag_label, l.sag_from_days,
               row_number() OVER (ORDER BY l.sag_from_days) AS rn,
               LAG(l.sag_to_days) OVER (ORDER BY l.sag_from_days) AS prev_to
          FROM stock.stock_ageing_slab l
         WHERE COALESCE(l.sag_company_id, '00000000-0000-0000-0000-000000000000'::uuid)
             = COALESCE(v_company,        '00000000-0000-0000-0000-000000000000'::uuid)
           AND l.sag_is_active  = true
           AND l.sag_is_deleted = false
    ) x
     WHERE (x.rn = 1 AND x.sag_from_days <> 0)
        OR (x.rn > 1 AND (x.prev_to IS NULL
                          OR x.sag_from_days <> x.prev_to + 1))
     ORDER BY x.rn
     LIMIT 1;

    IF FOUND THEN
        IF v_bad.rn = 1 THEN
            RAISE EXCEPTION
                'ageing ladder % must start at day 0; its first slab (%) starts at %',
                v_label, v_bad.sag_label, v_bad.sag_from_days
                USING ERRCODE = 'check_violation';
        ELSIF v_bad.prev_to IS NULL THEN
            RAISE EXCEPTION
                'ageing ladder %: the open-ended slab must be the last one, but slab % (%) starts after it',
                v_label, v_bad.sag_slab_no, v_bad.sag_label
                USING ERRCODE = 'check_violation';
        ELSE
            RAISE EXCEPTION
                'ageing ladder % has a gap: nothing covers days % to %, and stock that age would fall into no slab',
                v_label, v_bad.prev_to + 1, v_bad.sag_from_days - 1
                USING ERRCODE = 'check_violation';
        END IF;
    END IF;

    RETURN NULL;
END $$;

ALTER FUNCTION stock.fn_sag_coverage() OWNER to postgres;

-- DEFERRED, not merely DEFERRABLE: a whole-ladder save is invalid at almost
-- every step and only has to be right at COMMIT.
DROP TRIGGER IF EXISTS tr_sag_coverage ON stock.stock_ageing_slab;
CREATE CONSTRAINT TRIGGER tr_sag_coverage
    AFTER INSERT OR UPDATE OR DELETE ON stock.stock_ageing_slab
    DEFERRABLE INITIALLY DEFERRED
    FOR EACH ROW EXECUTE FUNCTION stock.fn_sag_coverage();


-- ───────────────────────────────────────────────────────────────────────────
--  17.10b  fn_sag_effective — WHICH ageing ladder a company uses.
--
--  sag_company_id is nullable and NULL means "the default ladder". Resolving
--  that is NOT the row-by-row fallback fn_stp_effective does, because a
--  consumer needs the whole ladder, not one row: if a company had five slabs
--  of its own and five default ones were also visible, every holding would
--  match TWO slabs and the ageing report would count all the stock twice.
--
--  So the fallback is all-or-nothing. A company that has defined any slab of
--  its own uses only its own; every other company uses the default ladder.
--  It lives in a function so that fn_stock_ageing, any report and the client
--  cannot each invent a different answer.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_sag_effective(p_company_id uuid)
RETURNS TABLE (
    slab_id    uuid,
    slab_no    integer,
    label      character varying(50),
    from_days  integer,
    to_days    integer,
    is_default boolean)
LANGUAGE sql
STABLE
AS $$
    SELECT s.sag_id, s.sag_slab_no, s.sag_label, s.sag_from_days, s.sag_to_days,
           (s.sag_company_id IS NULL)
      FROM stock.stock_ageing_slab s
     WHERE s.sag_is_active  = true
       AND s.sag_is_deleted = false
       AND (
            s.sag_company_id = p_company_id
         OR (s.sag_company_id IS NULL
             AND NOT EXISTS (SELECT 1
                               FROM stock.stock_ageing_slab o
                              WHERE o.sag_company_id = p_company_id
                                AND o.sag_is_active  = true
                                AND o.sag_is_deleted = false))
           )
     ORDER BY s.sag_slab_no;
$$;

ALTER FUNCTION stock.fn_sag_effective(uuid) OWNER to postgres;


-- ───────────────────────────────────────────────────────────────────────────
--  17.11  fn_stock_ageing — how old is what we are holding.
--
--  Buckets come from stock_ageing_slab, so a dairy's 0-3-7 and a jeweller's
--  years are the same query. The age itself is measured per the item's own
--  stp_ageing_basis:
--
--      INWARD_DATE   the lot's first entry into the CHAIN. A transfer between
--                    branches does not reset it, which is exactly the point.
--      LAST_IN_DATE  how long it has sat on THIS shelf.
--      MFG_DATE      the age of the goods themselves.
-- ───────────────────────────────────────────────────────────────────────────
CREATE OR REPLACE FUNCTION stock.fn_stock_ageing(
    p_company_id uuid,
    p_branch_id  uuid DEFAULT NULL,
    p_as_on      date DEFAULT CURRENT_DATE)
RETURNS TABLE (
    branch_id   uuid,
    godown_id   uuid,
    item_id     uuid,
    lot_id      uuid,
    batch_no    character varying(100),
    supplier_id uuid,
    expiry_date date,
    age_days    integer,
    slab_no     integer,
    slab_label  character varying(50),
    qty         numeric(18,6),
    value_at_cost numeric(18,2))
LANGUAGE sql
STABLE
AS $$
    WITH held AS (
        SELECT b.sbl_branch_id, b.sbl_godown_id, b.sbl_item_id, b.sbl_lot_id,
               b.sbl_batch_no, b.sbl_supplier_id, b.sbl_expiry_date,
               b.sbl_on_hand_qty, b.sbl_stock_value,
               l.slt_first_inward_date, l.slt_mfg_date,
               b.sbl_last_in_date,
               pol.ageing_basis
          FROM stock.stock_balance b
          JOIN stock.stock_lot l ON l.slt_id = b.sbl_lot_id
    CROSS JOIN LATERAL stock.fn_stp_effective(b.sbl_company_id, b.sbl_branch_id,
                                              b.sbl_item_id, p_as_on) pol
         WHERE b.sbl_company_id = p_company_id
           AND (p_branch_id IS NULL OR b.sbl_branch_id = p_branch_id)
           AND b.sbl_is_deleted = false
           AND b.sbl_on_hand_qty > 0
    ), aged AS (
        SELECT h.*,
               GREATEST(0, (p_as_on - CASE h.ageing_basis
                                          WHEN 'MFG_DATE'     THEN COALESCE(h.slt_mfg_date,
                                                                    h.slt_first_inward_date)
                                          WHEN 'LAST_IN_DATE' THEN COALESCE(h.sbl_last_in_date,
                                                                    h.slt_first_inward_date)
                                          ELSE h.slt_first_inward_date
                                      END))::integer AS days
          FROM held h
    )
    SELECT a.sbl_branch_id, a.sbl_godown_id, a.sbl_item_id, a.sbl_lot_id,
           a.sbl_batch_no, a.sbl_supplier_id, a.sbl_expiry_date,
           a.days, s.slab_no, s.label,
           a.sbl_on_hand_qty, a.sbl_stock_value
      FROM aged a
      -- fn_sag_effective, not the table: it returns ONE ladder, so this join
      -- still matches exactly one slab per holding.
      LEFT JOIN stock.fn_sag_effective(p_company_id) s
             ON a.days >= s.from_days
            AND a.days <= COALESCE(s.to_days, 2147483647);
$$;

ALTER FUNCTION stock.fn_stock_ageing(uuid, uuid, date) OWNER to postgres;

--  ── The problem this exists to solve ─────────────────────────────────────
--  Hamam 100g was received at MRP 40. A price revision arrives and the next
--  purchase is MRP 45. Both are on the shelf. They must sell at DIFFERENT
--  prices — the packet's own printed MRP governs — and the shop needs all
--  four of its price levels (Wholesale, Retail, Hotel, …) at each.
--
--  inventory.item_price_master cannot express that. It is unique on
--  (company, branch, item, unit) — there is no MRP in the key — so changing
--  a selling price there changes it for every unit of that item on hand,
--  including stock that is still labelled at the old MRP.
--
--  ── The legacy system already solved this, and this table copies it ──────
--  In 3.0, public.stocks carried sales_pricea/b/c on the RECEIPT ROW, and
--  "Change Selling Price - Bulk" repriced it with
--
--      UPDATE public.stocks SET sales_pricea = … , …
--       WHERE item_id = … AND unit_id = … AND max_price = …
--                                              ^^^^^^^^^^^^^ the MRP
--
--  That one predicate is the whole design: a rate change touches only the
--  bucket being edited, and stock at the other MRP is left completely alone
--  until it sells through. Nothing is revalued and nothing is re-batched.
--
--  Two faults of the legacy version are deliberately NOT copied:
--    * it carried only THREE levels on the stock row — sales_priced was
--      written to the master and silently never reached stock. All four are
--      here.
--    * a rate change to an MRP that had no stock rows matched nothing and
--      said nothing. fn_smp_effective makes the absence explicit instead.
--
--  ── Why this is keyed on the MRP and NOT on stock_lot ────────────────────
--  Two batches of the same soap at the same MRP sell for the same money. Its
--  batch number, expiry and supplier are all part of stock_lot's identity and
--  none of them changes the price. Keying the price on the lot would store
--  the same four numbers once per batch and let them drift apart, which is a
--  data-entry hazard rather than a feature.
--
--  So the grain is the PRICE-DEFINING part of the lot's identity, and there
--  are two such dimensions, not one:
--
--      smp_mrp          the printed MRP        (stp_track_mrp)
--      smp_sale_price   the selling price      (stp_track_sale_price)
--
--  Both are nullable and null-normalised into GENERATED companions, exactly as
--  stock_lot does it, so the unique index below cannot be fooled by NULLs and
--  the two tables agree by construction rather than by convention:
--
--      MRP shop            mrp set, sale_price NULL   — one bucket per MRP
--      selling-price shop  mrp NULL, sale_price set   — the skip_mrp case:
--                          garments and hardware, where nothing is printed
--      both tracked        one bucket per (mrp, sale_price) pair
--
--  Keying on MRP alone was the first draft and it was wrong: an item tracked
--  by BOTH gets two lots at one MRP with different selling prices, and a
--  single bucket cannot price them apart. ck_smp_identity requires at least
--  one dimension, because a bucket with neither is the headline price, and
--  that already has a home in item_price_master.
--
--  ── Which of the four levels is slt_sale_price? ──────────────────────────
--  The DEFAULT one — app setting sales.default_price_level. The lot carries a
--  single scalar because identity needs one number; the bucket carries all
--  four. The scalar should be sourced from the bucket's default level rather
--  than typed independently, or the two can disagree about the same holding.
--
--  ── This does not replace item_price_master ──────────────────────────────
--  ipm_ stays the headline price, the one an item is created with and the one
--  that applies when a holding has no bucket of its own. Same relationship
--  the legacy item_unit_rates had to stocks: master, plus a per-MRP override.
--  Nothing here ALTERs it — it is Prisma-owned and read only.
--
--  ── Effective dating: columns present, feature dormant ───────────────────
--  (2026-09-04) The legacy had none, and a scheduled price change is a real
--  want — so the COLUMNS and the machinery are in from day one, and the
--  FEATURE waits for a screen to use it:
--
--      smp_effective_from / _to    default 1900-01-01 / 9999-12-31, so every
--                                  row written today is simply always in
--                                  force — behaviour identical to no dating.
--      ex_smp_overlap              the EXCLUDE that replaced the old unique
--                                  index: same bucket key, plus "their date
--                                  ranges may not overlap". With the default
--                                  dates it degenerates to exactly the old
--                                  one-row-per-bucket rule.
--      fn_smp_effective(.., date)  resolves against a date, CURRENT_DATE by
--                                  default, so existing callers change
--                                  nothing. A bucket scheduled only for the
--                                  future correctly falls back to MASTER
--                                  until its day comes.
--
--  The far-past default start copies stock_track_policy's reasoning: a
--  CURRENT_DATE default would make a row priced today not apply to a bill
--  back-dated to yesterday. A row with no stated start has always been in
--  force.
--
--  NOTE for the save path: ON CONFLICT DO UPDATE cannot target an EXCLUDE
--  constraint. The bulk screen saves find-then-update (the fn_slt_resolve
--  shape), which it would want anyway to report Src = BUCKET/MASTER.
-- ═══════════════════════════════════════════════════════════════════════════

CREATE TABLE IF NOT EXISTS stock.stock_mrp_price
(
    smp_id                   uuid           NOT NULL DEFAULT uuidv7(),
    -- NULL = every company, exactly as stock_track_policy spells it. A
    -- company-specific row beats an every-company row.
    smp_company_id           uuid,
    -- NULL = every branch: ONE row prices the whole chain, and a branch that
    -- must differ writes its own row, which beats the chain row. This is how
    -- "same price everywhere" costs one row instead of one per branch, and
    -- how a NEW branch starts priced instead of blank. Prices remain a
    -- branch decision — the chain row is simply every branch's decision made
    -- once. Resolution: branch beats all-branch FIRST, then company beats
    -- every-company — see fn_smp_effective's ORDER BY.
    smp_branch_id            uuid,
    smp_tenant_id            uuid,

    smp_item_id              uuid           NOT NULL,
    -- An item_unit_conversion(iuc_id), never item_unit_master(unit_id) — the
    -- mistake the whole engine warns about. A 12-piece box and a piece are
    -- two rows here, as they are two rows in item_price_master.
    smp_uom_id               uuid           NOT NULL,

    -- ── The bucket: the price-defining half of the lot's identity ────────
    -- Nullable, because which of the two applies is the item's tracking
    -- policy's business, not this table's. At least one must be present —
    -- ck_smp_identity.
    smp_mrp                  numeric(18,6),
    smp_sale_price           numeric(18,6),

    -- The key the unique index is actually built on. Same sentinel and same
    -- reason as stock_lot's slt_key_mrp / slt_key_sp: a UNIQUE index treats
    -- every NULL as distinct, so indexing the raw columns would let a shop
    -- store the same bucket twice and price one holding two ways.
    smp_key_mrp   numeric(18,6) GENERATED ALWAYS AS (COALESCE(smp_mrp, -1)) STORED,
    smp_key_sp    numeric(18,6) GENERATED ALWAYS AS (COALESCE(smp_sale_price, -1)) STORED,

    -- ── The four levels ──────────────────────────────────────────────────
    -- Names come from fixed.price_levels (Wholesale / Retail / Hotel / …);
    -- the letters are positional, exactly as item_price_master has them, so
    -- the two tables are interchangeable to a caller.
    smp_price_a              numeric(18,6)  NOT NULL DEFAULT 0,
    smp_price_b              numeric(18,6)  NOT NULL DEFAULT 0,
    smp_price_c              numeric(18,6)  NOT NULL DEFAULT 0,
    smp_price_d              numeric(18,6)  NOT NULL DEFAULT 0,

    -- Stored, not derived. The tax rate lives on the item's tax master, which
    -- a generated column cannot reach, and a historic price must keep the
    -- without-tax figure it was quoted at even after the tax rate moves.
    smp_price_a_wot          numeric(18,6)  NOT NULL DEFAULT 0,
    smp_price_b_wot          numeric(18,6)  NOT NULL DEFAULT 0,
    smp_price_c_wot          numeric(18,6)  NOT NULL DEFAULT 0,
    smp_price_d_wot          numeric(18,6)  NOT NULL DEFAULT 0,

    -- What the operator typed, when they priced by markup rather than by
    -- rupees. Kept so the bulk screen can show the same number back.
    smp_markup_a_perc        numeric(9,3)   NOT NULL DEFAULT 0,
    smp_markup_b_perc        numeric(9,3)   NOT NULL DEFAULT 0,
    smp_markup_c_perc        numeric(9,3)   NOT NULL DEFAULT 0,
    smp_markup_d_perc        numeric(9,3)   NOT NULL DEFAULT 0,

    -- ── The floor, and the counter's room to move ────────────────────────
    -- min_price is a hard floor in the legacy screen, not advice: a price
    -- below it is refused outright. Kept with the bucket because the floor
    -- moves with the cost, and the cost moves with the MRP.
    smp_min_price            numeric(18,6)  NOT NULL DEFAULT 0,
    smp_disc_perc            numeric(9,3)   NOT NULL DEFAULT 0,
    smp_disc_qty             numeric(18,6)  NOT NULL DEFAULT 0,

    -- How the prices above were arrived at, so the screen can reproduce it.
    smp_profit_type          character varying(20) NOT NULL DEFAULT 'MANUAL',
    smp_round_off            numeric(10,4)  NOT NULL DEFAULT 0,

    -- The cost this bucket was priced AGAINST. Not the current cost — that is
    -- stock_item_cost's job and it moves on every receipt. This is the figure
    -- the margin on screen was calculated from, kept so a later reader can
    -- see why the price is what it is.
    smp_priced_on_cost       numeric(18,6)  NOT NULL DEFAULT 0,
    smp_priced_on_cost_wot   numeric(18,6)  NOT NULL DEFAULT 0,

    -- ── When this row is in force ────────────────────────────────────────
    -- Dormant until a scheduling screen exists: the defaults mean "always",
    -- which is exactly the pre-dating behaviour. See the header. The far
    -- past start is deliberate — a CURRENT_DATE default would not apply to
    -- a back-dated bill.
    smp_effective_from       date           NOT NULL DEFAULT DATE '1900-01-01',
    smp_effective_to         date           NOT NULL DEFAULT DATE '9999-12-31',

    smp_remarks              character varying(250),
    smp_is_active            boolean NOT NULL DEFAULT true,
    smp_is_deleted           boolean NOT NULL DEFAULT false,
    smp_sync_date            timestamp with time zone,
    smp_created_on           timestamp with time zone NOT NULL DEFAULT now(),
    smp_created_by           uuid,
    smp_modified_on          timestamp with time zone,
    smp_modified_by          uuid,

    CONSTRAINT pk_stock_mrp_price PRIMARY KEY (smp_id),

    -- One price set per bucket AT A TIME. Built over the GENERATED key
    -- companions (that is the whole point of them), plus the date range.
    -- With the default dates every range is [1900, 9999] and this is the
    -- plain one-row-per-bucket rule; the day a scheduled reprice is saved,
    -- it becomes "no two rows for one bucket may overlap in time" for free.
    -- Company and branch are COALESCEd because EXCLUDE never conflicts on
    -- NULL — without it two chain-wide rows for one bucket would both be
    -- accepted. A chain row and a branch row for the same bucket DO coexist,
    -- and must: that is the override. Same construction as ex_stp_overlap.
    -- DEFERRABLE so a split-and-reschedule (end the old row at 30 Sep,
    -- start the new at 1 Oct) can be saved as one transaction in any order.
    CONSTRAINT ex_smp_overlap EXCLUDE USING gist (
        (COALESCE(smp_company_id, '00000000-0000-0000-0000-000000000000'::uuid)) WITH =,
        (COALESCE(smp_branch_id,  '00000000-0000-0000-0000-000000000000'::uuid)) WITH =,
        smp_item_id    WITH =,
        smp_uom_id     WITH =,
        smp_key_mrp    WITH =,
        smp_key_sp     WITH =,
        daterange(smp_effective_from, smp_effective_to, '[]') WITH &&
    ) WHERE (smp_is_active = true AND smp_is_deleted = false)
      DEFERRABLE INITIALLY IMMEDIATE,

    CONSTRAINT fk_smp_company FOREIGN KEY (smp_company_id)
        REFERENCES public.companys (comp_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_smp_branch FOREIGN KEY (smp_branch_id)
        REFERENCES public.branch_master (br_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_smp_item FOREIGN KEY (smp_item_id)
        REFERENCES inventory.item_master (item_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,
    CONSTRAINT fk_smp_uom FOREIGN KEY (smp_uom_id)
        REFERENCES inventory.item_unit_conversion (iuc_id) MATCH SIMPLE
        ON UPDATE CASCADE ON DELETE RESTRICT,

    CONSTRAINT ck_smp_mrp CHECK (smp_mrp IS NULL OR smp_mrp > 0),
    CONSTRAINT ck_smp_sale_price CHECK (smp_sale_price IS NULL OR smp_sale_price > 0),
    -- A bucket with neither dimension is not a bucket.
    CONSTRAINT ck_smp_identity CHECK (
        smp_mrp IS NOT NULL OR smp_sale_price IS NOT NULL),
    CONSTRAINT ck_smp_prices_nonneg CHECK (
        smp_price_a >= 0 AND smp_price_b >= 0 AND smp_price_c >= 0 AND smp_price_d >= 0
        AND smp_price_a_wot >= 0 AND smp_price_b_wot >= 0
        AND smp_price_c_wot >= 0 AND smp_price_d_wot >= 0
        AND smp_min_price >= 0 AND smp_disc_perc >= 0 AND smp_disc_qty >= 0),
    -- The legacy screen blocks a price above the MRP outright (message 14),
    -- overridable only by a global "skip MRP" setting for shops that do not
    -- print one. Here it is a constraint, because a bill above the printed
    -- MRP is not a pricing decision, it is an offence.
    CONSTRAINT ck_smp_not_above_mrp CHECK (
        smp_mrp IS NULL
        OR (smp_price_a <= smp_mrp AND smp_price_b <= smp_mrp
            AND smp_price_c <= smp_mrp AND smp_price_d <= smp_mrp)),
    CONSTRAINT ck_smp_profit_type CHECK (
        smp_profit_type::text = ANY (ARRAY['MANUAL'::text, 'PERCENT'::text,
                                           'AMOUNT'::text])),
    CONSTRAINT ck_smp_dates CHECK (smp_effective_to >= smp_effective_from)
);

ALTER TABLE IF EXISTS stock.stock_mrp_price OWNER to postgres;

-- ux_smp_bucket is gone: one-row-per-bucket is now ex_smp_overlap's job (the
-- EXCLUDE in the table body), which enforces the same rule plus no-overlap
-- once effective dating is used. If upgrading a database that already has
-- the old index:  DROP INDEX IF EXISTS stock.ux_smp_bucket;

-- The billing lookup: given the lot the engine picked, what does it sell for.
-- The effective dates ride along so the date filter needs no heap visit.
CREATE INDEX IF NOT EXISTS ix_smp_lookup
    ON stock.stock_mrp_price USING btree
    (smp_company_id, smp_branch_id, smp_item_id, smp_key_mrp, smp_key_sp)
    INCLUDE (smp_price_a, smp_price_b, smp_price_c, smp_price_d, smp_min_price,
             smp_effective_from, smp_effective_to)
    WITH (fillfactor=90, deduplicate_items=True)
    WHERE smp_is_active = true AND smp_is_deleted = false;

-- The bulk rate screen, loading every bucket of one item.
CREATE INDEX IF NOT EXISTS ix_smp_item
    ON stock.stock_mrp_price USING btree
    (smp_company_id, smp_branch_id, smp_item_id, smp_uom_id, smp_key_mrp, smp_key_sp)
    WITH (fillfactor=90, deduplicate_items=True)
    WHERE smp_is_deleted = false;


-- ───────────────────────────────────────────────────────────────────────────
--  fn_smp_effective — the four prices that apply to one holding.
--
--  A bucket price beats the headline price, and a holding with no MRP has no
--  bucket, so it gets the headline. That is the entire rule, and it lives in
--  a function so the till, the bulk screen and every report cannot each
--  invent a different answer.
--
--  `source` is returned deliberately: a screen that cannot say whether it is
--  showing an MRP-specific price or the item's default will mislead the
--  person changing it. The legacy screen made the same distinction visible by
--  reloading its previous-value columns from the chosen bucket.
-- ───────────────────────────────────────────────────────────────────────────
-- The return type grew (bucket_id, bucket_scope) and OR REPLACE cannot
-- change a return type, so any older version is dropped first. Re-runnable.
DROP FUNCTION IF EXISTS stock.fn_smp_effective(uuid, uuid, uuid, uuid,
    numeric, numeric, date);

CREATE OR REPLACE FUNCTION stock.fn_smp_effective(
    p_company_id uuid,
    p_branch_id  uuid,
    p_item_id    uuid,
    p_uom_id     uuid,
    p_mrp        numeric DEFAULT NULL,
    p_sale_price numeric DEFAULT NULL,
    -- The bill's date, not necessarily today: a back-dated bill must read
    -- the price that was in force on ITS date. Defaulted, so every existing
    -- caller keeps working unchanged.
    p_on_date    date    DEFAULT CURRENT_DATE)
RETURNS TABLE (
    price_a      numeric(18,6),
    price_b      numeric(18,6),
    price_c      numeric(18,6),
    price_d      numeric(18,6),
    price_a_wot  numeric(18,6),
    price_b_wot  numeric(18,6),
    price_c_wot  numeric(18,6),
    price_d_wot  numeric(18,6),
    min_price    numeric(18,6),
    mrp          numeric(18,6),
    sale_price   numeric(18,6),
    source       character varying(10),
    -- Which ROW answered, for the screen that must edit it. A bulk screen
    -- showing a chain price as if it were the branch's own misleads whoever
    -- is changing it — the same reason `source` exists at all.
    bucket_id    uuid,                     -- smp_id, NULL when MASTER
    bucket_scope character varying(10))    -- BRANCH | CHAIN | NULL (MASTER)
LANGUAGE sql
STABLE
AS $$
    (SELECT s.smp_price_a, s.smp_price_b, s.smp_price_c, s.smp_price_d,
           s.smp_price_a_wot, s.smp_price_b_wot, s.smp_price_c_wot, s.smp_price_d_wot,
           s.smp_min_price, s.smp_mrp, s.smp_sale_price,
           'BUCKET'::character varying(10),
           s.smp_id,
           (CASE WHEN s.smp_branch_id IS NULL THEN 'CHAIN'
                 ELSE 'BRANCH' END)::character varying(10)
      FROM stock.stock_mrp_price s
     WHERE (s.smp_company_id = p_company_id OR s.smp_company_id IS NULL)
       AND (s.smp_branch_id  = p_branch_id  OR s.smp_branch_id  IS NULL)
       AND s.smp_item_id    = p_item_id
       AND s.smp_uom_id     = p_uom_id
       -- Matched on the companions, with the same sentinel the lot uses, so a
       -- holding tracked by only one dimension finds its bucket and a holding
       -- tracked by both finds only its own pair.
       AND s.smp_key_mrp    = COALESCE(p_mrp, -1)
       AND s.smp_key_sp     = COALESCE(p_sale_price, -1)
       AND p_on_date BETWEEN s.smp_effective_from AND s.smp_effective_to
       AND s.smp_is_active  = true
       AND s.smp_is_deleted = false
     -- Most specific bucket wins. BRANCH specificity is the PRIMARY sort —
     -- a branch's own price beats the chain price whatever their companies —
     -- and company specificity breaks the tie within a level. The same
     -- construction as fn_stp_effective's ORDER BY, for the same reason.
     ORDER BY (s.smp_branch_id IS NULL), (s.smp_company_id IS NULL)
     LIMIT 1)

    UNION ALL

    -- The headline price. Reached when the holding carries no MRP at all, or
    -- when this MRP has never been priced separately — at any scope.
    (SELECT m.ipm_sales_price_a, m.ipm_sales_price_b,
           m.ipm_sales_price_c, m.ipm_sales_price_d,
           m.ipm_price_a_wot, m.ipm_price_b_wot,
           m.ipm_price_c_wot, m.ipm_price_d_wot,
           m.ipm_min_price, NULLIF(m.ipm_max_price, 0), NULL::numeric(18,6),
           'MASTER'::character varying(10),
           NULL::uuid, NULL::character varying(10)
      FROM inventory.item_price_master m
     WHERE m.ipm_company_id = p_company_id
       AND m.ipm_branch_id  = p_branch_id
       AND m.ipm_item_id    = p_item_id
       AND m.ipm_uc_unit_id = p_uom_id
       AND m.ipm_is_deleted = false
       AND NOT EXISTS (
             SELECT 1
               FROM stock.stock_mrp_price s2
              WHERE (s2.smp_company_id = p_company_id OR s2.smp_company_id IS NULL)
                AND (s2.smp_branch_id  = p_branch_id  OR s2.smp_branch_id  IS NULL)
                AND s2.smp_item_id    = p_item_id
                AND s2.smp_uom_id     = p_uom_id
                AND s2.smp_key_mrp    = COALESCE(p_mrp, -1)
                AND s2.smp_key_sp     = COALESCE(p_sale_price, -1)
                -- Date-filtered like the first branch, so a bucket scheduled
                -- only for the future falls back to MASTER until its day.
                AND p_on_date BETWEEN s2.smp_effective_from AND s2.smp_effective_to
                AND s2.smp_is_active  = true
                AND s2.smp_is_deleted = false)
     LIMIT 1)
    LIMIT 1;
$$;

ALTER FUNCTION stock.fn_smp_effective(uuid, uuid, uuid, uuid, numeric, numeric, date)
    OWNER to postgres;

-- Each time the signature grows, the old overload must go: CREATE OR REPLACE
-- leaves it behind, and a shorter call would then be ambiguous between the
-- old function and the new one's defaults.
DROP FUNCTION IF EXISTS stock.fn_smp_effective(uuid, uuid, uuid, uuid, numeric);
DROP FUNCTION IF EXISTS stock.fn_smp_effective(uuid, uuid, uuid, uuid, numeric, numeric);

COMMENT ON TABLE stock.stock_mrp_price IS
    'Four selling price levels per MRP bucket — what stock labelled at one MRP sells for, independently of stock of the same item labelled at another. inventory.item_price_master has no MRP in its key, so without this a price revision silently reprices stock still on the shelf at the old printed MRP. Copies the mechanism the legacy 3.0 "Change Selling Price - Bulk" screen used (UPDATE stocks … AND max_price = …), and carries all four levels rather than the three that screen managed. Company and branch are NULLABLE: NULL branch = one row prices every branch (and a new branch starts priced), a branch''s own row beats it; NULL company likewise. fn_smp_effective resolves most-specific-first: branch beats chain, then company beats every-company.';
COMMENT ON COLUMN stock.stock_mrp_price.smp_branch_id IS
    'NULL = every branch: the chain price, one row. A branch that must differ writes its own row, which wins. The bulk screen must therefore say which row it is editing — the chain row or this branch''s override.';
COMMENT ON COLUMN stock.stock_mrp_price.smp_company_id IS
    'NULL = every company, as on stock_track_policy. A company-specific row beats an every-company row within the same branch level.';

COMMENT ON COLUMN stock.stock_mrp_price.smp_mrp IS
    'One half of the bucket key — the printed MRP, when stp_track_mrp is on. Nullable: a shop that prints no MRP (skip_mrp — garments, hardware) buckets by selling price instead. ck_smp_identity requires at least one of the two.';

    'The other half — the selling price, when stp_track_sale_price is on. It mirrors stock_lot.slt_sale_price, which is a single scalar because identity needs one number; this row carries all four levels for that identity, and the scalar should be the DEFAULT level (app setting sales.default_price_level) taken from here rather than typed independently.';
