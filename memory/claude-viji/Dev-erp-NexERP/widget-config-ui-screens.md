Built 2026-10-22 (user: "used to store widget info header-wise to hide widgets per client"; "don't follow 3.0 — it's one table, here we have section and fields"; "yes do it for item entry ui").

- **Storage (server, existing):** `fixed.form_section` (heading: section_menu_id, section_name, section_gui_name, visibility, platform) + `fixed.form_field` (field_name, gui name, secondary text, visibility). Routes `/widget-masters/config?menu_id&platform=Desktop` (read), `create`/`create-bulk`, `PATCH visibility`. Scope = menu + platform only (one setting per database — the user confirmed one client per server). 3.0's `menu_widgets` / `fmenuwidgets` one-table model is NOT followed.
- **Naming:** `field_name` = the DATA KEY (same as the Web rows / NexCrudForm), `section_name` = a stable key (primary_info…). Qt's WidgetSectionConfig.sectionGuiName carries section_name (loadWidgetConfig).
- **.ui markup (Designer dynamic properties, not styles):** `fieldKey` on the input (a tab PAGE = its tab), `sectionKey` on the heading widget (the tab widget for the tab row), `fieldRequired=true` = never hidden (a section holding one keeps its heading). Labels found by BUDDY (or buddy == the field's focusProxy).
- **Code:** NexDialog::applyFieldConfig default implementation (NexCrudForm still overrides); NexDialog::event(first Show) calls loadWidgetConfig only if ctx.menuId and the screen carries fieldKey/sectionKey (unmarked screens: no request). Hidden widgets get `configHidden=true`; screen code that shows/hides fields itself must respect it (ItemEntry::applyExpiryVisibility does).
- **Item card:** opened from Item Master list → ctx.menuId **29**. 46 fieldKeys (7 required: name, tax, HSN, group, brand, tracked-as, unit grid), 5 sections. Desktop rows registered 10-22 via create-bulk (section ids 80-84, all visible) — script scratchpad n138/widgets29.py (refuses if Desktop rows exist).

**2026-10-22 gaps fix (user screenshot: hidden Alias + SKU left empty rows):** after applyFieldConfig, `reflowGrid()` (nex_dialog.cpp) re-packs every QGridLayout holding a configHidden widget in READING order — units = label+buddy on the same row (moved together) / single widget / nested layout; start columns = the columns units started in (0,3 for label|field pairs; 0..5 for the checkbox grid); a spanning layout keeps its column on the next row; spacers stay. Hidden units are taken out (their QLayoutItem wrappers deleted, widgets stay hidden). Result: [Name|Regional][Tax|HSN][Barcode|Display Order]. `slots` is a Qt keyword — don't name a variable that.
