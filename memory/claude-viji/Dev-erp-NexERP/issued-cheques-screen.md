Menu 52 was CODED on 2026-09-26 and is uncommitted. It lives in `src/modules/accounts/cheques/`:
- `issued_cheque_entity.h` (the `IssuedCheque::Row` from grid 121 + `allowedActions`);
- `issued_cheques.{h,cpp,ui}` (the `.ui` was generated by a python script, the same style as 51);
- `issued_cheque_action_dialog.*` (one form for all five verbs);
- `cheque_book_dialog.*` (grid 120 + the /cheque-books/get|create|close form).

It is registered with `fm.reg<IssuedCheques>(52)`. The endpoints are the `ApiEndpoints::IssuedCheques` namespace (the `Key` uses BARE apdId / apdAccYear keys, unlike 51) and the `ApiEndpoints::ChequeBooks` namespace.

**The verb map:**
- HELD → Presented (F7) / Returned (F8) / Stop (F3) / Void / Replace;
- BOUNCED and CANCELLED → Replace;
- CLEARED and REPLACED → History only.

The client has no post/cancel/amend rights, so the buttons follow the cheque's state and the server's 403 speaks, as on 51.

**Other behaviour:**
- **The strip** has no summary route. It pages grid 121 on `istatus=HELD,BOUNCED` (100 a page) and splits the rows by its `state` column (OUTSTANDING / POST-DATED). The leaves come from grid 120 ACTIVE.
- **Enter** opens `paymentVoucherId` through `/vouchers/get` rules.inRegister → `VoucherRegisterEntry::openFor`.
- **After Replace** the screen lands on the NEW cheque.
- **Shared code changes:** `ChequeHistoryDialog` gained a (url, title, heading, emptyText) constructor, and `ChequeRowDelegate::setLabel()` was added for the P words.

**Tests:** `tests/issued/run.sh smoke` passes 14/0/1. `live` passed **25/0/0 on 2026-09-26** once VKPOS had menu 52. Each live run POSTS a ZT PmtV with 4 × 10.00 cheques on supplier SK (no TDS), plus the replacement PmtV, and uses 5 leaves. A supplier line must be bill-allocated (VCH_BILLWISE_SHORT otherwise).

**Two bugs the live run found (both fixed):**
1. **Grid cache.** The server's global HttpCacheInterceptor caches `/configured-grid-sql/run` by URL for 1 s (it reads @CacheTTL(1) as seconds). A reload right after a write returns the old rows. Menu 52 and ChequeBookDialog wait 1.1 s since the last load before the post-action reload. Menu 51 is still exposed. The ask is notes 55 #3.
2. **Book list hijack.** A list reload moved the current row and loaded a neighbouring book onto the form, so Close shut the wrong book. Fixed with m_listReloading, which re-selects the form's book after the reload.

**Asks for the server** are in notes 55, at the end: paymentVoucherAccYear, and a way to void a blank leaf.
