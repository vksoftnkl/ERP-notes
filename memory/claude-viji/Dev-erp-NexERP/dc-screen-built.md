**Contract dry run PASSED** (`tests/dc/dryrun.sh`, `#define private public`):
create → validate → reload → update (sdcId + sdiId carried) → delete, on
customer 019f659c… item 019f73fd… (A001). `tests/dc/snap.sh` renders
`snap_dc_{new,loaded}.png`.

**Three server facts found (asked as notes 43):**
1. `/delivery-challans/get` returns `store.plain(items)` — NO item / unit /
   godown NAMES (sale-orders/get has them). Client workaround:
   `fetchItemPrice(row, …, displayOnly=true)` then `fetchItemName()` via
   `/items/get?item_id=` when the price row is gone. One GET per line on load.
2. `sdc_counter_id` is NOT NULL, no default, no counter master; the DC spec's
   `headerRequired` demands it as a uuid; the bill never sends one (nullable).
   The client sends the DEVICE id. On an UNREGISTERED terminal the MAC-derived
   device id is not a v7 uuid → /create 400s — same class as txn_hold.
3. VKPOS has every posting right FALSE on menu 182 (`rights` all false);
   tester1 was granted post/cancel/amend/override on 182 (2026-09-22).
