**Superseded in part by the Qt 4ae6575 redesign (2026-10-23, [[erp-qt-4ae6575-port]]):** grid is now Uom · From · To · Mode ("% off"/"₹ off"/"Fixed price" = P/R/F) · Value, with a panel under it (`slab-panel.tsx`: Applies to / When) and a "Today:" line + preview read from `/stock/price-bulk`. The ui_table-20 column map, the Add Row button, `item-search-cell.tsx` and the barcode→unit pre-fill described below are GONE; three headings still come from the "ITEM QTY WISE PRICE" ui table by name. Deep link `?itemId=&itemName=` (`itemQtyPriceHref`). Still no `iqp_notes` on the server. Dev DB lacks the `ck_iqp_*` / `ex_iqp_no_overlap` constraints the Prisma comments describe.

Built "Item Qty Wise Price" as an Opening-Stock-style inline-editable spreadsheet grid (not a CrudMasterPage modal-per-row master), per explicit user choice between the two patterns.

- Backend already existed in full: `inventory.item_qty_price` table (`ItemQtyPrice` Prisma model) + `src/modules/Inventory/items-qty-price-master/*` (`POST /item-qty-prices/create` bulk array create/update, `GET /item-qty-prices/get` list/single, `DELETE /item-qty-prices/delete` soft delete/restore). `iqp_item_unit_id` stores an `iuc_id` (unit conversion row), not a raw unit id — same pattern as `ipm_uc_unit_id`, see [[erp-item-price-unit-id-is-iuc-id]]. Company/branch/party/price_level are optional and NOT server-forced (unlike `item_price_master`), so the v1 UI omits them entirely and sends null.
- Client: `store/api/itemQtyPriceApi.ts` (RTK Query) + `features/masters/inventory/item-qty-price/*` (page.tsx, types, utils, a bespoke `ItemSearchCell` combobox, scoped scss module) + route `app/master/item-qty-price-master/page.tsx` + nav entry under Inventory in `components/layout/constants.ts` (`DEFAULT_PRIMARY_MENU` and `ERP_MENU_OBJECT`).
- Did NOT add a `fixed.menu_master` DB row / `user_menus` grant for it. Confirmed via research: the page is always directly reachable by URL (no server/client route guard tied to menu_master), and the client nav only falls back to showing unfiltered `DEFAULT_PRIMARY_MENU` entries when `/menu-masters/usermenu` returns empty for the user — once a user has any real menu grants, un-seeded client-only entries silently vanish from the sidebar (though the page still works via direct URL/search). The prior day's "Freight Charges"/"Loading Charges" pages (commit 4c49c4d) set this precedent — client-only constants.ts entry, no server seed — so this feature matched it. If the user later wants it in the sidebar for restricted-permission users, a `fixed.menu_master` insert + `user_menus` grant is still needed.

Related: [[erp-item-entry-spec-port]] (Opening Stock's own grid, the pattern this was modeled after, at ~3500 lines with column-config admin, godown/batch/barcode — this new page deliberately does NOT replicate that machinery, just the core edit-rows-and-save-all UX).

**Config-driven columns (added same day):** the grid's dynamic columns (everything after the pinned #/Item) are driven by `fixed.ui_tables` id 20 ("Item Qty Wise Price web") via `GET /ui-table-masters/get?uiTableId=20` (NOT `uiTblClmTableId` — that param name, used by the actively-running `features/stocks/_shared/useColumnConfig.ts` hook, is rejected by the DTO with "property should not exist"; `useColumnConfig` for opening/physical stock may be silently no-op/broken, its try/catch swallows the 400 and falls back to defaults — didn't investigate further since out of scope). Correct query param is `uiTableId`, response is `{data:[{uiTblId, columns:[...]}]}`. Column resolution lives in `item-qty-price.columns.ts`: `resolveConfiguredColumns` normalizes `ui_tbl_clm_name` (strip non-alphanumeric, lowercase) and maps to an internal `DynamicColumnKey` via a hardcoded name→key table, sorted by `uiTblClmColumnPosition`, first-occurrence-wins dedup (so raw id-echo duplicate rows like `company_id` alongside a friendly `Company` row collapse onto one rendered column). Item/# stay hard-pinned first regardless of config (the config has no friendly "Item" label, only a raw `item_id` row near the end — user explicitly chose to keep Item pinned rather than follow that literally). "Notes" is configured but has no backing DB column on `item_qty_price` — deliberately unmapped/dropped, user chose not to fake a client-only field.

**Spec-alignment pass (2026-07-23, later same day):** ported the planning doc ("Item Qty-wise Rates — React Implementation Plan", a Qt6 `ItemQtyPriceEntry` port). The page went from "append rows for any item" to **single-item scope**: picking an item (barcode or search) loads its saved slabs via `GET /item-qty-prices/get?iqp_item_id&limit=100` into the grid for editing, switching items confirms-then-discards, and a successful save resets the whole screen (item picker included) instead of remapping saved rows back. Also added: uniqueness rule over (company, branch, customer, price level, unit, from qty, to qty) checked at save with the clashing row named; Mode change clears the two fields it locks; From Qty required; delete confirms for saved rows too ("cannot be undone"); Save · Clear · Close + explicit Add Row; Ctrl/Cmd+S.
Deliberate deviations from that doc, both forced by the live API: mode letters stay **P|R|F** (doc says the flat-Rs mode is `Q`; the server DTO's `Matches(/^[PRF]$/)` rejects it — only the label follows the doc), and `iqp_effective_from` stays **required** (doc calls it optional; the server DTO has it non-nullable `@IsDateString()`). `iqp_effective_to` is sent as `null` rather than omitted when blank — the server's update path uses `hasOwnProperty` to decide what to touch, so omitting the key would make clearing a To Date on a saved row silently keep the old value.

Also added: Company/Branch/Customer/Price-Level as real optional per-row fields (`iqp_company_id`/`iqp_branch_id`/`iqp_party_id`/`iqp_price_level`), each a `SearchableSelect` fed by `/master-lookups/name-id/all-masters?module=customers|priceLevels` (new lookups added to `lookupsApi.ts`) — filter out the lookup's own blank/"Select X" placeholder option from the list since the cell already supplies its own "None" placeholder via `SearchableSelect`'s `placeholder` prop; otherwise it shows twice with mismatched wording and picking the wrong one silently saves null.
