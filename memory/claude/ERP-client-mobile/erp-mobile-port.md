**Install-on-device procedure (release APK, no Expo Go — Expo Go failed: client 54.0.8 < project expo 54.0.35):**
The `expo` dep was never installed (node_modules was stale RN-CLI); also `react-native-screens@~4.16.1`
was a bad pin → fixed to `~4.16.0` (SDK 54 wants ~4.16.0). `npm install --legacy-peer-deps` then works.
The original `android/` was stale RN-CLI (had `apply from react-native-vector-icons/fonts.gradle` → vector-icons
was dropped for @expo/vector-icons; and community-CLI autolinking → "Could not find project.android.packageName").
Fix = `npx expo prebuild --clean --platform android` (regenerates with `autolinkLibrariesWithApp()` + @expo/cli
bundler). prebuild wipes manual android edits, so AFTER prebuild re-apply in `android/`:
(1) `gradle.properties`: `org.gradle.java.home=/opt/android-studio/jbr` (system JDK-21 are JREs, no javac),
heap `-Xmx4096m` (2GB OOMs: "Could not receive a message from the daemon" during gesture-handler Kotlin compile),
and `reactNativeArchitectures=arm64-v8a` (phone is arm64; 4-ABI build is 4× heavier);
(2) `AndroidManifest.xml` <application>: `android:usesCleartextTraffic="true"` (backend is http://, blocked in release by default).
Build: `cd android && ./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`.
Install over USB (simplest): phone Developer options → USB debugging → "Allow" popup → `adb install -r app-release.apk`.
Install over Wi-Fi: phone Developer options → Wireless debugging → pair-code popup → `adb pair <ip>:<pairport> <code>`
(phone then auto-connects via mDNS — the explicit `adb connect <ip>:<connectport>` may show "offline", ignore it)
→ `adb install -r app-release.apk`. Backend must bind `0.0.0.0:3011` + firewall allow 3011; phone same Wi-Fi.

**DOUBLE-NAT GOTCHA (hit 2026-07-29):** this site has two routers. The PC is on ethernet `enp42s0`
`192.168.0.106/24` (gw `192.168.0.1` = inner router); the Wi-Fi SSID **"Airtel_vk computers" hands out
`192.168.1.x`** (outer/ISP router). PC→phone ping works, **phone→PC fails** — the PC is behind the inner
router's NAT, so the app cannot reach `API_BASE`. Symptom: app installs + renders login fine, login request
just hangs. Fix = join the phone to the **inner** router's Wi-Fi (the one the PC's ethernet plugs into) so it
gets a `192.168.0.x` address. Always check `adb shell ip addr show wlan0` is same /24 as `hostname -I`
BEFORE debugging the app. Alternative (USB-only): rebuild with `API_BASE=http://127.0.0.1:3011` +
`adb reverse tcp:3011 tcp:3011` — release APKs bake in the JS bundle, so changing API_BASE needs a full rebuild.
`API_BASE` in [src/lib/config/env.ts](src/lib/config/env.ts): **reverted to `http://127.0.0.1:3011/api/v1` on 2026-07-29**
and the app is now run over USB with `adb reverse tcp:3011 tcp:3011` (works regardless of Wi-Fi/subnet —
see the double-NAT note below; the LAN-IP variant is only right when phone and PC share a /24).
Verify what a built APK actually points at:
`unzip -p app-release.apk assets/index.android.bundle > /tmp/b.hbc && grep -aoE "http://[0-9.]+:3011/api/v1" /tmp/b.hbc`
(Hermes bytecode keeps the string table in plaintext; note `strings` is NOT installed on this box, use `grep -a`).

**Backend (same as web):** PostgreSQL REST API, base `/api/v1`. Reference `.env` →
`http://127.0.0.1:3011/api/v1`; web default `https://<host>:3010/api/v1`. Mobile resolves host in
[src/lib/config/env.ts](src/lib/config/env.ts) (Android emulator → 10.0.2.2, iOS → 127.0.0.1,
physical device → set `LAN_HOST_OVERRIDE`). JWT bearer + refresh token.
Endpoints: `POST /auth/login` (usrLoginName/usrPassword/device_id), `POST /auth/refresh`,
list = `GET /configured-grid-sql/run?grid_id=N`, columns = `/configured-grid-sql/columns`,
CRUD = `POST /{entity}/get|create`, `DELETE /{entity}/delete`,
lookups = `GET /master-lookups/name-id/all-accounts-and-masters?module=...`, menu = `/menu-masters/get`.

**Engine = metadata-driven.** Web `CrudMasterPage` (4143 L) + `ERPDynamicModalForm` + `ReusableTable`
ported to [src/features/masters/shared/CrudMasterScreen.tsx](src/features/masters/shared/CrudMasterScreen.tsx)
+ [src/components/form/DynamicForm.tsx](src/components/form/DynamicForm.tsx) +
[src/components/data/DataList.tsx](src/components/data/DataList.tsx). Masters are declarative
`MasterModuleDefinition`s (field-name-agnostic via `lookupKeys` arrays + normalizers). Engine boundary
uses `MasterModuleDefinition<any,any,any>` to dodge generic contravariance on buildRequestPayload/mapFormValues.

**RN gotcha:** RN's `URL` polyfill is incomplete — never use `new URL().pathname`; parse paths by hand
(see getRequestPathname). Session uses in-memory cache + AsyncStorage (no sync sessionStorage); call
`hydrateSession()` at bootstrap (done in [src/store/provider.tsx](src/store/provider.tsx)).
